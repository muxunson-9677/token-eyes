# Token Eyes 0.54.25 桌面小组件与额度重置提醒调整文档

日期：2026-07-29  
基准版本：Token Eyes `0.54.25`  
状态：需求讨论已确认，待新对话使用目标模式执行

## 1. 文档用途

本文件是本轮桌面小组件、额度重置历史与提醒调整的唯一执行依据。

以下旧文件只保留讨论过程，不作为目标模式的实施依据：

- `docs/superpowers/specs/2026-07-29-desktop-widget-and-agent-status-design.md`
- `docs/superpowers/plans/2026-07-29-reliable-codex-reset-history-alerts.md`

执行时不得从旧文件恢复与本文冲突的设计，尤其不得恢复“小组件重置提醒约 6 秒后自动消失”的旧行为。

## 2. 总体目标

在现有 Token Eyes 数据与功能基础上，完成当前仍属于占位状态的桌面小组件，使用户无需打开 Token Eyes 主窗口，也能在桌面快速查看：

1. 多项目、多对话的 Agent 红黄绿状态。
2. Claude、Codex、Cursor 等服务的用量套餐。
3. 当前 Agent 的模型 Token 消耗与花销。
4. 新发生的额度重置提醒。

小组件必须复用 Token Eyes 已有数据，不得为小组件建立第二套统计、账号或 Agent 状态采集渠道。

## 3. 桌面小组件基础能力

### 3.1 独立桌面窗口

- 完成真正可用的 Windows/Tauri 桌面悬浮小组件。
- Token Eyes 主窗口关闭或最小化到托盘后，小组件仍可正常显示和刷新。
- 用户可以把小组件拖动到桌面任意位置。
- 支持置顶。
- 支持用户手动调整宽度和高度。
- 重启后恢复上次位置、尺寸、Agent、信息模式、透明度和材质。
- 多显示器、分辨率或 DPI 变化后，小组件必须回到可见屏幕范围。

### 3.2 默认胶囊形态

- 默认使用单张、小尺寸、圆角胶囊。
- 默认尺寸以已经确认的本地原型紧凑形态为准。
- 数据增加时不得自动拉高或拉宽小组件。
- 胶囊与展开详情是同一个窗口、同一张卡片。
- 不得为了展示不同尺寸或状态生成多张独立卡片。
- 不在产品界面中展示“默认状态”“用户拉高后”等方案说明。

### 3.3 展开与折叠

- 左侧 Agent 主图标负责展开或折叠详情。
- 展开后仍然保持单张卡片，不打开第二个详情窗口。
- 再次点击主图标恢复胶囊形态。
- 展开和折叠不得改变用户选择的 Agent 或当前信息模式。

## 4. 胶囊状态下的直接操作

用户不展开详情也必须能够完成以下操作：

- 打开 Agent 选择菜单。
- 在项目红绿灯、用量套餐、模型消耗三个模式之间切换。
- 展开或折叠详情。
- 查看并关闭额度重置提醒。

具体交互：

- Agent 主图标旁使用独立小箭头打开 Agent 菜单。
- 主图标点击区域与 Agent 菜单箭头点击区域不得重叠。
- 右侧使用一个紧凑的信息模式按钮。
- 信息模式按钮打开项目、用量、模型消耗三个选项。
- Agent 菜单和模式菜单在胶囊折叠状态下也必须完整可见。
- 菜单不得被卡片圆角、窗口边缘或 `overflow` 裁切。
- 切换 Agent 或信息模式只替换当前胶囊内容，不创建新卡片、不改变窗口尺寸。

## 5. Agent 选择

小组件支持 Token Eyes 当前已经纳入检测与展示的 Agent，包括但不限于：

- Token Eyes 汇总
- Claude
- Codex
- Cursor
- Hermes
- 产品当前已支持并具备用量数据的其他 Agent

要求：

- 全部使用项目内已经收录的官方品牌图标。
- Token Eyes 使用自身产品图标。
- 禁止使用临时手绘、近似重画、Emoji 或来源不明的替代图标。
- Token Eyes 选项汇总所有 Agent 的现有数据。
- 单个 Agent 只显示属于该 Agent 的数据。
- 某个 Agent 在当前模式没有数据时显示紧凑空状态，不得伪造数据。

## 6. 三个信息模式

同一张胶囊支持三个模式：

1. 项目红绿灯
2. 用量套餐
3. 模型与 Token 消耗

三个模式必须使用同一个小组件窗口、同一套 Agent 选择和同一套 Token Eyes 数据。

## 7. 项目红绿灯模式

### 7.1 项目与对话层级

- 支持多个项目。
- 每个项目支持多个对话。
- 第一层显示项目。
- 展开项目后显示该项目中的对话。
- 同时只展开一个项目，避免卡片过度拥挤。
- 已完成对话较多时可以汇总显示数量。
- 优先显示等待处理、异常和正在运行的对话。
- 项目之间允许使用轻量细分割线。

### 7.2 红黄绿状态

- 红灯：等待批准、异常、用户中断或非正常停止。
- 黄灯：正在运行。
- 绿灯：任务已完成。

### 7.3 胶囊交通灯

- 红、黄、绿三个灯始终同时存在，顺序固定。
- 每个灯旁显示对应状态的对话数量。
- 数量大于 `0` 时，灯显示对应颜色并轻量发光。
- 数量为 `0` 时，灯和数字显示为灰色。
- 不得因为某个状态为 `0` 就隐藏对应的灯。
- 胶囊中不堆放“等待批准”“运行中”“已完成”等长文字。
- 完整状态文字在展开详情中显示。

### 7.4 状态可靠性

- 复用 Token Eyes 当前已有的 Codex 多项目、多对话状态能力。
- 只根据可靠的本地事件判断运行、完成、中断、异常和等待批准。
- 不得因为长时间没有日志就直接判定为等待批准。
- 没有可靠状态证据的 Agent 显示未知或空状态，不进行猜测。
- 不读取或生成新的对话内容摘要。

## 8. 用量套餐模式

- 复用当前 Token 服务列表和官方用量限制数据。
- 不建立小组件专用的用量数据源。
- 胶囊默认显示当前 Agent 最重要的少量套餐窗口。
- 使用小型圆形进度、极细进度条或沙漏图标配合百分比。
- 不允许只堆放多个裸百分比。
- 图形只表达用量进度或距离重置的时间，不增加装饰性图表。
- 展开后显示更多套餐。
- 每行保持极简，只显示 Provider/套餐、重置倒计时、使用百分比和小型进度图形。
- 用量模式不使用内容分割线。

## 9. 模型与 Token 消耗模式

### 9.1 胶囊摘要

胶囊只显示：

- 当前 Agent 的 Token 总消耗。
- 当前 Agent 的总花销。

该模式是唯一允许在胶囊内使用纯数字双指标的模式。

### 9.2 展开详情

- 展示模型消耗明细。
- 复用 Token Eyes 现有模型 Token 统计。
- 按 Token 消耗占比排序。
- 每行显示模型名称、Token 数量、占比和极细进度条。
- 模型模式不使用内容分割线。
- 默认尺寸下可以安全截断过长模型名。
- 用户拉宽窗口后显示更多模型名称。

## 10. 数据较多时的处理

- 项目、对话、套餐或模型增加时，小组件不得自动改变尺寸。
- 默认始终保持紧凑胶囊或用户上次保存的尺寸。
- 展开后的内容区域支持鼠标滚轮、触控板和拖动滚动。
- 默认隐藏滚动条。
- 鼠标移入或正在滚动时显示轻量覆盖式滚动条。
- 整张卡片只允许一个纵向滚动区域。
- 项目内部不得再嵌套第二个滚动区域。
- 用户拉高后自动显示更多条目。
- 用户拉宽后优先显示更完整的名称。
- 滚动、窗口拖动和右下角缩放三个操作区域不得冲突。

## 11. 材质、颜色与透明度

- 使用 Apple/macOS 控制中心风格的半透明玻璃材质。
- 背景必须是真正可调的透明材质，不是固定深色纯色。
- 提供少量受控预设，例如冰霜、石墨、海蓝、暖沙。
- 透明度和材质颜色分别保存。
- 不提供任意取色器，避免出现不可读配色。
- 透明度较高或较低时都必须保证文字对比度。
- 红黄绿只用于任务状态。
- 系统蓝色只用于当前模式和可操作控件。

材质设置方式：

- 不创建独立的“材质卡片”或“透明度卡片”。
- 在同一张卡片内部提供小型外观按钮。
- 点击后在当前卡片内覆盖显示迷你设置面板。
- 关闭后不占用内容空间。

## 12. 多账号用量优化

- 不新增重复的“多账号总览”页面。
- 继续使用当前 Token 服务列表。
- 参考 Cockpit Tools 优化现有多账号检测和刷新体验。
- 支持更清晰的账号标签、刷新状态和失败提示。
- 可以优化批量刷新。
- 不增加账号切换功能。
- 不为小组件建立单独的账号体系。

## 13. 额度重置检测

需要识别并记录：

- 正常周期重置。
- 用户手动使用重置次数。
- Token Eyes 未运行期间发生、但能从 Codex 本地用量快照恢复的重置。

检测要求：

- 结合当前官方用量窗口、重置时间和使用百分比。
- 解析当前版本遗漏的重置额度计数。
- 读取 Codex 本地 `token_count.rate_limits` 用量快照。
- 只读取时间、窗口和用量元数据。
- 不读取 prompt、回复正文、工具参数或命令输出。
- 多个来源发现同一次重置时，只生成一条记录。
- 先成功写入历史记录，再触发任何提醒。

## 14. 最近 30 天重置历史

- 历史记录保留最近 30 天，不再限制为最近 3 条。
- 按日期分组并按发生时间倒序排列。
- 使用用户本地时区显示。

每条记录显示：

- Agent
- 账号
- 套餐窗口
- 重置发生时间
- 周期重置或手动重置
- 重置前后的用量，例如 `21% → 0%`

补录规则：

- 第一次升级后可以补录最近 30 天已有证据的旧重置。
- 补录的旧事件只进入历史记录。
- 不得因为历史补录连续触发旧提醒。

## 15. Windows 醒目提醒

新重置发生后同时提供：

- Windows 原生通知。
- 提示音。
- Token Eyes 主窗口顶部的绿色提醒横幅。
- 托盘未读标记。
- 桌面小组件持久提醒。

要求：

- 同一次重置在所有提醒渠道共用同一个事件。
- 重启、重复轮询和多个 Codex 对话不得造成重复通知。
- Windows 系统通知不可用或被用户关闭时，主界面、托盘和小组件提醒仍然生效。
- 本功能只提醒“额度已经重置”。
- 不增加“用量耗尽提醒”。

## 16. 小组件持久重置提醒

这是本轮最终确认行为，优先级高于旧文件中的自动消失设计。

### 16.1 出现方式

- 新重置发生后，当前胶囊立即切换为醒目的绿色重置提醒。
- 提醒仍然在原来的单张胶囊中显示。
- 不创建第二张提醒卡片。
- 不改变小组件尺寸。
- 显示实际发生重置的 Agent 官方图标。
- 显示“额度已重置”。
- 显示发生时间。
- 可以显示极简的用量变化，例如 `21% → 0%`。
- 刚出现时允许轻量脉冲两次，随后保持稳定高亮。

### 16.2 持续时间

- 不设置 6 秒或任何自动消失倒计时。
- 不论经过多久，提醒都必须一直显示。
- 只有用户亲自点击提醒后才消失。
- 小组件被隐藏时不得丢失未处理提醒。
- 下次显示小组件时仍然显示该提醒。

### 16.3 点击行为

用户点击持续显示的重置提醒后：

1. 只关闭当前提醒。
2. 清除该事件在小组件和托盘中的对应未读状态。
3. 恢复提醒出现前用户选择的 Agent。
4. 恢复提醒出现前的信息模式。
5. 恢复提醒出现前的展开或胶囊状态。
6. 不打开重置历史。
7. 不打开 Token Eyes 主窗口。
8. 不跳转到任何详情页。

重置记录仍然保留在最近 30 天历史中，用户可以之后从正常入口查看。

## 17. macOS 与 Windows 设置

- macOS 保留动画图标功能。
- macOS 保留额度重置撒花功能。
- Windows 不显示这两个仅适用于 macOS 原生菜单栏的开关。
- Windows 使用真正有效的系统通知、主窗口横幅、托盘未读和小组件提醒。

## 18. 数据与隐私

- 胶囊、展开详情、Token Eyes 主界面和重置历史复用同一份数据。
- 小组件不得建立独立统计渠道。
- 只读取 Token、费用、额度、Provider、模型、项目标识、会话标识、时间和状态事件。
- 不保存或上传 prompt。
- 不保存或上传回复正文。
- 不保存或上传工具参数和命令输出。
- 不在 API 或小组件中暴露认证 Token、原始账号 ID或完整本地路径。
- 项目、会话和账号继续使用隐私安全的规范化标识。

## 19. 明确不做

本轮调整不包含：

- 用量耗尽提醒。
- 自定义预算设置。
- 新增环境统计。
- 上下文压力展示。
- 新增 Agent 体验诊断。
- 账号切换。
- 模型切换。
- MCP 切换。
- Skill 切换。
- 实体硬件红绿灯。
- 小组件专用的独立数据采集渠道。
- 为不同模式生成多张独立卡片。
- 自动拉长或拉宽小组件。
