## 3. 数据流与信任边界

```text
Plan/Reset 受控生成任务 ----签名----> staging Worker 内部发布入口
                                      |
                                      v
                       SQLite Durable Object 对象存储
                                      |
                  同一 DO 一致性内存缓存 + 无认证 GET
                                      |
                        客户端验签并原子写入磁盘 LKG

排行榜登录页 --明确参赛意图--> InsForge Auth
本地聚合器 --全局参与者 5s 本地缓存 hash 检查；仅变化时 <=8 KiB 摘要--> InsForge participant state
                                     |
                         写入成功即标记固定 dirty key
                                     |
              Durable Object 60s 合并 alarm + 每日全量校准
                                     |
                     Top 50 JSON 签名并写同一 SQLite DO
                                     |
       未登录客户端 --无认证 GET--> CDN --验签--> 页面 Top 50
       已登录参与者 --JWT--> InsForge me endpoint --> 独立“我的名次”
```

禁止边界：

- 公共 feed 请求不得携带账户身份，也不得回源 InsForge。
- 静态对象生成器和 Worker 发布器是唯一持有发布 secret/feed 私钥的组件；客户端只包含公钥。
- 客户端上传仅允许版本化紧凑聚合数组、捕获时间、设备 ID 和摘要 hash。摘要 hash 不含捕获时间，因此没有数据变化时不会重复上传。
- InsForge anon key 不是 feed 签名，也不是 Worker 发布授权。
- 公开头像只允许当前 Worker origin 的 `/v1/avatars/{sha256}.webp` 内容寻址对象；InsForge 私有头像桶和认证资料头像不得直接出现在公共快照。
- 旧匿名 badge/embed/profile-like/avatar-public Edge 与公开 `/u/:userId` 路径已退役；`/u/:userId` 现在只允许已认证用户查看自己的资料，公共榜单不再产生匿名逐用户读取。

## 4. 参赛状态机

| 当前状态 | 事件 | 下一状态 | 副作用 |
|---|---|---|---|
| `guest` | 排行榜登录入口发起认证 | `consent_pending` | 本地写一次性排行榜登录意图；不上传 |
| `guest` | 非排行榜登录/会话恢复 | `signed_in_nonparticipant` | 只读远端参与状态；不得自动公开或上传 |
| `consent_pending` | 认证成功且登录意图未过期 | `participant` | 显式设置 `leaderboard_public=true`，上传紧凑摘要，标 dirty |
| `participant` | 会话恢复 | `participant` | 恢复现有资格；应用级同步器每 5 秒只检查带 queue 指纹/上海自然日缓存的本地紧凑摘要，摘要相同则不上传；离开排行榜页面后仍生效 |
| `participant` | 退出登录 | `guest_with_retained_participation` | 仅 `signOut`，不删除排行数据 |
| `participant` | 确认退出排行榜 | `deleted` | 删除/匿名化远端参与数据并标 dirty；保留本地统计 |
| `deleted` | 再次从排行榜登录并同意 | `participant` | 创建新的明确参赛同意并重新上传聚合摘要 |

排行榜登录意图必须同时满足：由排行榜按钮创建、绑定当前浏览器/桌面会话、短时有效、消费一次。OAuth 回跳或冷启动若没有该意图，不得创建参赛同意。

## 5. 固定快照键与读取合同

当前白名单是 5 个周期：`today/week/30d/month/total`；27 个 Agent 来源外加 `all`；指标是 `tokens/estimated_spend/actual_cost`。`actual_cost` 只允许 `source=all`。

因此对象总数固定为：`5 × (2 × 28 + 1) = 285`。对象路径：

```text
/v1/leaderboard/{period}/{metric}/{source}.json
```

每个对象：

- 固定最多 Top 50，不接受 `limit`、`offset`、用户 ID 或任意排序参数。
- 包含 `schema_version`、`snapshot_key`、`generated_at`、`entries`、公开聚合摘要和 Ed25519 签名 envelope。
- 客户端拒绝未知 schema、错 key、坏签名、未来时间、过旧回放、超过字节上限和超过 50 条记录。
- 排名超过 Top 50 的已登录参与者通过受认证 `me` endpoint 单独显示，不进入公共对象。
- 应用启动和其他页面导航不预取公共榜单；排行榜只在页面首次打开、白名单筛选变化或用户点击可见的“刷新”按钮时读取一个固定对象，页面没有后台 polling。
- 所有公开对象 GET/错误响应以及 OPTIONS 预检都允许匿名浏览器跨域读取（`Access-Control-Allow-Origin: *`），且不允许凭证；ETag 和 `X-Token-Eyes-Cache` 可被浏览器读取。Node 直连成功不能替代这项浏览器边界。

## 6. 增量刷新、每日校准与删除

- 聚合状态 upsert、公开资料变化、实际费用同意变化、参赛/退出参赛都写入 dirty 维度队列。
- dirty key 取固定 285 键的子集；写入成功后通过持密钥内部请求唤醒单个 SQLite Durable Object 协调器。协调器把同一窗口的重复通知合并成一个 alarm，并以 `lastSuccessfulRefreshAt + 60s` 为最早下一次刷新时间；没有 dirty 通知时不运行分钟空任务。
- 刷新任务重算受影响维度的完整排名，但只发布该维度 Top 50；若 Top 50 内容 hash 未变，不重写对象。
- 已参与用户的应用级同步器每 5 秒读取一次本地摘要；本地 API 用 queue `mtime/size` 与上海自然日作为缓存键，文件未变时不重新扫描队列。只有 hash 改变才上传并立即写 dirty；相同 device hash 和相同实际费用的 SQL upsert 不写行。`me` 读取写入后的聚合状态；公开快照由 alarm 领取全部最多 285 个已到期 dirty key。最终 staging 仍必须按 AC-05 实测“本地变化到 me/Top 50 均不超过 60 秒”，不能用 alarm 设计推断代替。
- 每日一次全量校准全部 285 个键，纠正漏标/价格表/日期边界漂移；校准不是页面 polling。
- 删除参与先在仍可读取该用户来源集合时标记全部可能受影响维度，再事务性删除 participant state、实际费用状态、排行资料及对应静态头像；`me` 立即返回未参与，静态 Top 50 在 60 秒内移除。

## 8. 免费额度、成本和降级门

2026-08-30 已核对的官方和账号边界：

- Workers Free 每天最多 100,000 个请求；超过后返回平台错误，而不是转为按量收费。每次请求 CPU 上限 10 ms。来源：<https://developers.cloudflare.com/workers/platform/pricing/>、<https://developers.cloudflare.com/workers/platform/limits/>。
- SQLite Durable Objects 可用于 Workers Free；每天含 100,000 个 DO 请求、5,000,000 行读、100,000 行写和总计 5 GB 存储。官方明确说明 Free 超出任一额度后该类操作失败，每日 00:00 UTC 重置。来源：<https://developers.cloudflare.com/durable-objects/platform/pricing/>。
- 账号探针把 staging Worker 的 CPU 限制请求设为 11 ms，Cloudflare API 以 `100328` 拒绝并明确返回 `Free plan`；该版本未上传/未部署。R2 列表 API 同时返回 `10042`（R2 未启用）。现有 staging 版本只绑定一个 SQLite-backed Durable Object。
- JSON 公开对象在同一全局 DO 中读取并使用 DO 实例内存缓存；响应为 `max-age=0, must-revalidate`，避免不同边缘 PoP 保存可变榜单陈旧副本。Cache API 只用于按 hash 内容寻址、不可变的公开头像。即使缓存失效，代码门也会在平台 100,000 请求/写入之前停止可选云读写。

不以预计流量证明零费用。本实现直接把请求和保守行写预算限制为 70,000 warning / 90,000 stop；任何部署变量只能调低。若其他账号级 Workers Free 流量先消耗配额，Cloudflare 会更早失败，也不会收费。

`$0` 硬门：

- 禁止 checkout、支付方式、R2、Workers Paid、自动升级和无上限计量。
- DO 的公开对象读取、发布、删除、dirty 和 alarm 共享同一 UTC 日账本；请求和保守行写达到 70,000 时返回 warning，下一操作将超过 90,000 时返回 429 并停止。计数账本自身写入也计入预算。
- 相同 content hash 不写；删除不存在对象不写；发布器/协调器缺失或预算账本不可用时 fail-closed。停止可选云功能不得影响本地统计、Usage、Cost、Realtime。
- staging 必须真实验证正常匿名读取、缓存 MISS/HIT、发布刷新、暂停/预算停止状态和客户端 LKG；测试 header 不能代替真实 URL 证据。
- 只能表述为“当前账号为 Workers Free，平台和代码均硬停，因此该实现不会产生账单”；不得承诺第三方服务永久免费，也不得把未来升级后的账户自动视为合格。

## 9. 缓存、签名与故障恢复

- Worker 对 JSON 使用同一 Durable Object 的实例内存缓存；对象发布按 content hash/ETag 幂等写入并立即使该缓存失效。响应使用 `max-age=0, must-revalidate`；客户端显示 payload 内 `generated_at`，不能把缓存 header 当生成时间。Cache API 仅用于内容寻址头像。
- 客户端磁盘 LKG 使用临时文件、fsync/close、原子 rename；只有完整下载、字节上限、schema、key、时间和签名全部通过才替换。
- 新快照回滚到更旧 `generated_at` 时拒绝覆盖；密钥轮换通过版本化 key id 和至少一个版本重叠完成。
- Worker/DO 故障或硬停：客户端读磁盘 LKG并显示陈旧状态；InsForge 故障：阻断新登录/上传/me，但不阻断已有缓存/LKG 和本地核心；生成任务故障：保留上一个对象，不发布半成品。
- Cloudflare Worker 的生产配置保持 `LEADERBOARD_PUBLISHING_PAUSED=true`；staging 只有在账号 Free 探针、密钥、对象存储和失败态测试通过后才临时解除。每日 70,000/90,000 阈值为代码上限。
