## 1. 验收结论

R1 的测试隔离目标通过：

- Node 测试的 HOME、临时目录、APPDATA、LOCALAPPDATA 和 XDG 目录均被重定向到仓库内 `.tmp/node-test-*`。
- 四个指定测试文件均在加载生产模块前加载统一 preload。
- 注入 HOME 时不再继承宿主路径、凭据和数据目录覆盖环境变量。
- 默认拒绝测试代码发起非 loopback `fetch`、`http` 和 `https` 请求；loopback 与测试注入的 fake fetch 仍可使用。
- Windows 生产入口仍允许默认盘符扫描；测试 preload 禁止真实默认盘符扫描；显式仓库内伪盘符仍可测试扫描逻辑。
- macOS 生产入口仍允许系统 Keychain；测试 preload 禁止真实 Keychain 探测，注入 runner 仍可测试该分支。
- 测试输出未命中真实用户目录、根级 `X:\AgentData`、Copilot OTEL 诱饵值或网络禁用失败。
- 测试临时目录在拥有者进程退出后清理，未发现 `.tmp/node-test-*` 残留。

`npm test` 当前仍以退出码 1 结束。这不是 R1 隔离失败：57 个失败与冻结的后续阶段问题一致，分别归入 R3、R4 和 R5；本报告不把它写成“全量通过”。

## 2. 根因

1. Windows 上 `os.homedir()` 与仅修改 `HOME` 的测试约定不一致，测试可能继续解析真实用户目录。
2. 多个库函数在收到显式 `home` 后仍默认继承 `process.env`，可被宿主的 AgentData、工具 HOME、凭据或遥测路径覆盖。
3. Node 测试没有统一的外部网络拒绝边界。
4. Windows Codex 多目录发现同时服务生产盘符扫描和测试注入；如果只按“是否传入 home”判断，会在生产与测试之间产生相反的回归。
5. Provider 错误对象可能把 Cookie、认证头、账号或队列上下文带入测试输出。
6. API billing、Cursor SQLite 和 Kiro CLI 的深层调用没有完整传递 `env`、`platform`、runner 与生产/测试探测决策。
