### 成本规则

1. `actual_cost_usd > 0` → 直接使用，分项写 `"0"`
2. `estimated_cost_usd > 0` → 直接使用，分项写 `"0"`
3. 均为 0 → `CostCalculator.calculate_for_app("hermes", ...)` + `find_model_pricing`
   - 先尝试 `{normalized_provider}/{model}`，再尝试 `{model}`

### Provider 归一化

- `anthropic/*` → `anthropic`
- `openai/*` → `openai`
- `google/*` / `gemini/*` / `vertex/*` → `google`
- 其它 → 转小写，`-` 替换为 `_`

### 过滤规则

- `model IS NULL OR TRIM(model) = ''` → SQL 层跳过
- `id` 为空 → 代码层跳过
- 所有 token 为 0 且成本 ≤ 0 → 跳过
- `should_skip_session_insert` 去重

## Review 修复记录

### P1: `started_at` 支持 SQLite REAL（小数秒）

- **问题**: `started_at` 以 `i64` 读取，REAL 值（如 `1750000000.25`）会导致 `query_sessions` 失败
- **修复**: `started_at` 改为 `f64` 存储，`query_sessions` 用 `row.get::<_, f64>(3).unwrap_or(0.0)` 解析，`created_at` 通过 `as i64` 截断为整数秒
- **回归测试**: `test_query_sessions_handles_real_started_at` — 验证 `1750000000.25` 正确解析且截断为 `1750000000`

### P2: 文件级同步水位有条件推进

- **问题**: 即使有会话插入失败，文件水位仍被推进，导致下次运行跳过失败记录
- **修复**: 引入 `has_sync_errors` 标志，仅在整轮无错时调用 `update_sync_state`，与 OpenCode 同步模式一致
