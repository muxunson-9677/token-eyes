## 7. 花销聚合计算表

**验证方式**: 代码审查 `cost_ledger.rs` 实现并与 `interfaces.md` 对比。

### 7.1 公式验证

| 公式 | 规范要求 | 实现 | 状态 |
|------|----------|------|------|
| 本周期花销 | `token_cost_usd + subscription_cost_usd` | `period_total_usd = token_cost_usd + subscription_cost_usd` | ✅ |
| 累计花销 | 历史同口径求和 | `cumulative_token(0, period_end) + cumulative_sub(0, period_end)` | ✅ |
| token 成本 | proxy_request_logs + usage_daily_rollups（去重） | `query_token_cost_sum` + `effective_usage_log_filter` + rollup 边界逻辑 | ✅ |
| 订阅费 | 按月计数，无按日摊销 | `for_each_month_in_range` 逐月计数，仅 USD | ✅ |

### 7.2 花销聚合数据流

```
前端 SpendOverviewChart
  → useCostLedgerSummary({ startDate, endDate, agentType })
  → Tauri invoke get_cost_ledger_summary
  → cost_ledger::get_cost_ledger_summary:
       token_cost = SUM(proxy_request_logs.total_cost_usd) [去重]
                  + SUM(usage_daily_rollups.total_cost_usd) [仅完整日]
       subscription_cost = 逐月统计 subscription_fees [仅 USD, 按月不按日]
       cumulative = 同公式, 范围 [0, period_end]
  → CostLedgerSummary → buildViewModel → Recharts 两根柱子
```

### 7.3 计算表模板

| 项目 | 值 | 说明 |
|------|-----|------|
| token 成本 (本周期) | 运行时由 `query_token_cost_sum` 计算 | proxy_request_logs + daily_rollups |
| 订阅费 (本周期) | 运行时由 `query_subscription_cost_sum` 计算 | 逐月统计 USD 订阅 |
| **期望本周期花销** | `token_cost + subscription_cost` | 规范公式 |
| **实际本周期花销** | `CostLedgerSummary.totalCostUsd` | 对应图表 period 柱子 |
| **实际累计花销** | `CostLedgerSummary.cumulativeTotalCostUsd` | 对应图表 cumulative 柱子 |

> 注：具体数值需运行 `pnpm tauri dev` 后在 Dashboard 查看。公式实现已通过 8 个 Rust 单元测试 + 1 个集成冒烟测试验证。

### 7.4 边界行为说明

`compute_rollup_date_bounds` 对 end_date 的 `hour == 23 && minute == 59` 检查仅匹配精确值。若查询范围结束于月初 00:00:00 UTC，该日的 rollup 数据会被排除（detail 行仍覆盖到该时刻）。此为保守设计，已由测试覆盖，非 bug。

**结论**: 公式实现与规范完全一致，图表组件正确映射 `totalCostUsd` → period 柱, `cumulativeTotalCostUsd` → cumulative 柱。

### 8.3 `pnpm tauri build`

**结果**: ❌ 失败

**失败原因 1 — 缺少 Tauri CLI 原生模块**:

```
Error: Cannot find module './cli.linux-x64-gnu.node'
Error: Cannot find module '@tauri-apps/cli-linux-x64-gnu'
```

`pnpm install --frozen-lockfile` 创建了 `@tauri-apps+cli-linux-x64-gnu@2.8.1` 目录但**内容为空**（无 `cli.linux-x64-gnu.node` 文件）。原项目中该文件存在（ELF 64-bit shared object）。

**失败原因 2 — vite 符号链接缺失**:

```
sh: 1: vite: not found
```

`node_modules/.bin/` 中缺少 `vite` 符号链接。手动创建后仍因 ESM 解析失败报错：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'vite' imported from vite.config.ts
```

### 8.4 复现步骤

```bash
mkdir -p /tmp/token-eyes-coldstart
cd /tmp/token-eyes-coldstart
git clone <repo> token-eyes
cd token-eyes
git checkout main
pnpm install --frozen-lockfile
pnpm tauri build
# → 失败：缺少 @tauri-apps/cli-linux-x64-gnu native binary 和 vite symlink
```

### 8.5 根因分析

| 问题 | 根因 | 影响 |
|------|------|------|
| `@tauri-apps/cli-linux-x64-gnu` 为空目录 | pnpm store 中未缓存该平台原生包，`--frozen-lockfile` 不会重新下载 | `pnpm tauri` 无法启动 |
| `vite` symlink 缺失 | pnpm 未为顶层 `vite` devDependency 创建 `.bin` 入口 | `vite build` 失败 |

这两个问题均与 pnpm store 缓存状态相关。原项目 `node_modules` 是在已有 store 缓存的环境下安装的，因此正常。全新环境（空 store）下 `--frozen-lockfile` 可能无法正确解析可选平台依赖。

**建议**: 在 CI 或全新环境中，`pnpm install` 后需验证 `node_modules/.pnpm/@tauri-apps+cli-linux-x64-gnu*/node_modules/@tauri-apps/cli-linux-x64-gnu/cli.linux-x64-gnu.node` 存在。如不存在，需执行 `pnpm install --force` 或手动 `pnpm add @tauri-apps/cli-linux-x64-gnu@<version>`。
