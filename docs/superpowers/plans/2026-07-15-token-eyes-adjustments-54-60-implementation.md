# Token Eyes 调整 54–60 实施计划

**实施状态：已完成。** 版本 `0.54.2`；NSIS 安装包已构建并完成版本、图标和哈希校验。

**目标：** 修复同供应商多账号串号，补齐备注、环比颜色和趋势布局，建立官方自动核价闭环，改进 Trae/CodeBuddy 精确数据源状态，并替换项目图标，最终生成可覆盖安装的 NSIS EXE。

**约束：** 仅修改 Token Eyes 项目内文件；外部应用和数据目录只读；不伪造第三方用量或价格。

## 任务 1：同供应商多账号隔离

- 在 `TokenPlanSection` 测试中复现两个 Codex 套餐错误复用同一会话。
- 删除按供应商回退首个会话的逻辑，新增套餐只能使用未被其他套餐绑定的会话。
- 保存前校验已连接套餐必须有明确绑定；额度同步只写回绑定该会话的套餐。
- 增加 Rust/前端测试，证明两个 `session_ref` 使用独立 `CODEX_HOME` 和独立额度。

## 任务 2：环比、趋势与备注

- 增加 UsageStatsPanel 测试，要求新增/减少均为绿色。
- 增加 UsageTrendChart 布局测试，要求图表和空状态填满卡片高度。
- 增加 Token 套餐设置列表和 Token 服务列表备注渲染测试。
- 用最小 CSS/DOM 改动实现。

## 任务 3：官方自动核价

- 扩展模型目录条目，保存供应商、官方来源、解析适配器和核验元数据。
- 新增后端官方核价服务：官方域名白名单、请求超时、内容上限、结构化解析和明确错误码。
- 新增 API/Tauri 调用与 AgentPricingSection 的“自动核价”按钮、状态、失败原因及人工回退。
- 测试成功、域名拒绝、模型不匹配、解析失败与人工规则覆盖。

## 任务 4：Trae/CodeBuddy 数据源

- 用 fixture 复现安装目录被当成数据目录，以及识别目录但误报未检测到。
- 扩展路径解析和状态契约：`connected_ready`、`connected_no_tokens`、`not_detected`。
- 复核现有本地解析器，只导入明确 Token 字段；接入已有官方授权用量时保持来源标记。
- 测试目录识别、精确 Token 导入和无 Token 不入账。

## 任务 5：项目图标

- 建立 `src-tauri/icons/token-eyes-orange/`，复制只读源图到项目内。
- 用 Tauri 图标生成器创建 PNG/ICO/ICNS，并更新 Tauri、NSIS、托盘和 favicon 引用。
- 验证配置引用文件全部存在。
