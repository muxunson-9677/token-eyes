## 实施步骤

### 任务一：先建立失败测试

- 为每日细目浮层增加点击、切换、关闭、Agent/模型分组和“不占布局空间”的失败测试。
- 为请求日志来源提示增加失败测试。
- 为悬浮小组件的统一 Agent 来源、已选项目匹配、5h/7d 独立窗口、重置时间、有效期和五种状态增加失败测试。
- 为实际现金支出、API 标价等价价值、回本倍数和未知/部分覆盖增加失败测试。

### 任务二：实现概览与请求日志调整

- 使用精确日期调用已有模型用量明细接口，并在每日表格内部渲染绝对定位浮层。
- 保留键盘操作、加载态、错误态、滚动和底部翻转逻辑。
- 通过 `copy.csv` 增加请求日志计价来源文案并同步生成文案资源。
- 接入从 DeepSeek 官方来源取得的品牌资源。

### 任务三：修复悬浮小组件

- 以“限制显示”偏好作为使用明细和悬浮小组件的唯一 Agent 显示来源。
- 用已选项目的稳定标识、标签和规范化路径与真实会话进行匹配，不把存在活动的数据错误显示为无活动。
- 每个套餐窗口独立呈现供应商、账户、窗口、进度、重置时间、有效期和错误信息。
- 按五张设计稿校准组件尺寸、间距、圆角、材质、图标、层级和菜单位置。
- 原生窗口在菜单和特效开关前后保持主体坐标不变，折叠态固定高度，不写回临时几何。

### 任务四：修正费用统计口径

- 增加 `API 标价等价价值`、`官方 API 实际支出` 与 `实际现金支出` 的显式字段。
- 实际现金支出 = 已记录订阅费用 + 官方 Billing/发票值 + 自定义花销；不加入订阅 Token 的等价价值。
- 回本倍数 = API 标价等价价值 ÷ 已记录订阅费用。
- 在摘要卡片和说明中明确“精确 / 估算 / 等价价值 / 未知”，对官方账单覆盖不足显示“部分”而不伪装精确。
- 排行榜等使用“实际成本”的入口改用实际现金支出口径，避免继续读取旧的估算合计。

### 任务五：两道独立交付闸门

1. **需求匹配核对：** 按上方五行验收矩阵逐条比对代码、文案、数据结构和交互；任何偏差先修复，再重新核对。
2. **真实呈现核对：** 在真实本地应用中逐状态操作，使用与设计稿相同的状态和视口比较；核对数据显示、浮层遮挡、Agent 切换、项目活动、套餐窗口、特效关闭和窗口位置。

完成两轮核对后再向用户报告结果；在用户明确要求前仍不提交、推送、合并或打包。
