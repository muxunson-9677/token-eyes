# Token Eyes V4 第 20260816 轮 UI 调整实施计划

> **给执行代理：** 必须逐任务执行并勾选步骤；实施时使用 `superpowers:executing-plans`。每项任务均以“失败测试 → 最小实现 → 通过测试 → 真实界面验收 → 独立提交”为顺序，未经用户另行授权不得推送、合并、发版或清理工作树。

**目标：** 在不削弱真实数据、既有功能和已验收交互的前提下，统一 Token Eyes 的卡片反馈、套餐信息层级、成本设置布局、响应式行为、深色模式与桌面启动体验。

**总体方案：** Dashboard 负责样式、信息层级、缓存呈现和交互；Tauri/官方会话适配层是套餐到期与重置事实的唯一来源；`tauri.conf.json` 负责初始窗口与打包图标。实施分为可独立验收的阶段，先建立基线，再依次完成卡片基础、套餐事实、页面布局和性能、响应式与拖拽、深色主题、原生壳层，最后做两轮独立验收。

**技术栈：** React 18、Vite、Vitest、`@dnd-kit`、Framer Motion、`dashboard/src/ui/foundation/apple-glass.css`、Tauri 2 / Rust、真实浏览器旅程检查、Node 测试运行器。

8. 截图 `2800 × 1696` 是启动尺寸和视觉密度的物理像素参考。Tauri 配置使用逻辑尺寸，实施时必须记录 Windows 缩放比例、`devicePixelRatio`、逻辑窗口边界和原生外框边界后再设定最终值；不能直接把 `2800 × 1696` 写入 `tauri.conf.json`。
