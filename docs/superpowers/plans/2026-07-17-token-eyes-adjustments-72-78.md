# Token Eyes 调整项 72–78（对抗性修复计划）

> 作用域：仅 `D:\04-AI-Project\010-Token eye\.worktrees\provider-api`。禁止修改项目外的软件、账号数据或文件。
>
> 完成原则：找到目录不等于检测到 Token；显示“已连接”不等于额度解析成功；每项必须由失败测试、实现和回归证据闭环。

## 调整项

### 72. 其他 AI 花销二级分组就地编辑

- 点击某个一级分组的“新增子分组”，表单只出现在该分组内部。
- 二级分组支持自定义名称、收藏/取消收藏、重命名和删除；一级与二级分组交互一致。
- 拖拽记录进入二级分组后，分组归属与排序均持久化。

### 73. Trae / CodeBuddy 出现在概览与使用统计

- 只有解析出真实 Token 记录时才纳入 Token 总量与模型/Provider 统计。
- 仅发现用户数据目录但日志无精确 Token 字段时，设置页明确显示“已发现数据目录，暂无可解析 Token”，不得伪造 0 消耗或“已检测用量”。
- 一旦本地同步产生 Trae / CodeBuddy 记录，概览卡片、Provider 统计、模型统计与每日细目必须同步出现。

### 74. Trae / CodeBuddy 安装目录与数据目录解析

- E 盘是程序安装目录；Electron/VS Code 系应用默认把可变用户数据写入 `%APPDATA%`，两者必须在 UI 中区分说明。
- 手动选择 E 盘安装目录后，程序自动定位对应用户数据目录并持久化最终可跟踪路径。
- 对真实可读 JSONL/SQLite Token 数据写解析回归测试；对加密或缺字段数据只报告证据，不宣称检测到 Token。

### 75. 供应商 API 配置文档

- 每条供应商配置新增“配置文档”按钮。
- 文档包含该供应商余额查询所需的 URL、鉴权方式、必填凭据、响应字段路径和可复制说明。
- 文档按供应商预设生成，不展示或复制用户密钥。

### 76. Cursor 真实配额同步

- 授权成功后解析 Cursor 官方用量响应，不再把登录成功误判为额度同步成功。
- Total Usage、Auto + Composer、API Usage 至少保存官方响应中可获得的分项；套餐卡使用 Total Usage 作为主进度。
- 响应缺字段时显示明确失败原因，禁止回落为 `已用 0 / 剩余 0`。

### 77. Codex 官网账号连接

- “连接/重试连接”点击必须调用原生会话创建并打开系统默认浏览器。
- 处理旧的 pending/session_ref 失效状态；重试时清理孤儿会话并重新授权。
- 授权回调成功后只更新当前套餐账号，失败/超时必须可见且可再次重试。

### 78. 成本累积紧凑与折叠

- 自定义花销分组改为紧凑行/小卡片，保留本月、本年、总累积信息。
- Token 套餐、供应商账户、API 计费均支持独立折叠/展开，标题保留数量与关键汇总。
- 默认状态减少纵向占用，但不删除刷新、配置或明细入口。

## 实施与验证顺序

1. 为 72–78 分别补充失败测试，记录当前失败原因。
2. 先修数据链路（73/74/76/77），再修 UI（72/75/78）。
3. 跑 Node、Dashboard、Rust 聚焦测试，再跑完整测试与类型检查。
4. 仅全部验证通过后构建新安装包；构建成功后删除旧安装包，仅保留最新 EXE。
