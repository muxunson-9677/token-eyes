# Token Eyes 排行榜与微信专属登录实施计划

日期：2026-07-13

对应事项：`docs/superpowers/specs/2026-07-13-token-eyes-fixes-1-6-design.md` 的事项 10。

## 假设与边界

- 所有代码、配置、测试、文档和构建产物只改动当前 Token Eyes 仓库；不读取或改动 CC Switch。
- 本地概览、使用统计、限制、成本和设置继续免登录；公开榜单可匿名浏览，只有“我的排名、上榜、排行榜云同步”要求登录。
- 排行榜登录入口只展示微信，不展示手机号、邮箱、密码或其他 OAuth。
- 时间统计按 Asia/Shanghai（UTC+8）自然日计算，避免“今日/昨日”因服务器 UTC 日期产生歧义。
- “含缓存”使用上报的总 Token；“不含缓存”定义为 `max(0, total - cache_read - cache_creation)`；“预估费用”继续使用项目现有模型价格规则。
- 只上传聚合 Token、Agent、模型、时间桶及计算费用所需数据；不上传提示词、回复、代码或日志正文。
- 微信开放平台真实扫码验收依赖已审核的网站应用 AppID、AppSecret 和回调域名。仓库内实现、自动化测试和部署说明完成后，真实扫码仍单独标为外部配置验收，不写入占位密钥。

## 技术决定

InsForge 自定义 OAuth 当前要求 Discovery 文档、授权端点、Token 端点和 UserInfo 端点；其回调会从 UserInfo 读取唯一 ID 和邮箱，再创建或复用标准 `auth.users` 会话。微信网站登录提供的是 OAuth2 `code/access_token/openid` 流程，不是可直接配置的 OIDC Provider。

因此在本项目 Edge Functions 中增加微信 OAuth 适配层：

1. 对 InsForge 暴露 Discovery、授权、Token、UserInfo 四个标准端点。
2. 授权端点校验 InsForge 的 client、redirect URI、state 和 PKCE 后，跳转微信二维码授权。
3. 微信回调服务端用 code 换取微信 access token 和用户资料，生成一次性短期授权码。
4. Token 端点校验 PKCE 并兑换项目短期 access token；UserInfo 返回稳定 `sub`、显示名、头像和项目内部不可投递邮箱。
5. InsForge 继续签发其标准会话，因此既有设备令牌、公开资料、云同步和行级权限无需另造第二套用户系统。

项目内部邮箱仅用于满足现有 InsForge UserInfo 契约，格式由微信稳定身份的不可逆摘要生成，不接收邮件、不展示给用户，也不提供邮箱登录。

## 批次 1：排行榜查询维度与前端交互

### 目标

补齐 Agent、周期和统计口径三类查询维度，并让缓存键、URL、Mock、API 和页面状态保持一致。

### 测试先行

- 为查询规范化写失败测试：
  - 周期支持 `today/yesterday/7d/30d/total`，旧 `week/month` 分别兼容到 `7d/30d`。
  - Agent 支持 `all` 和项目已知来源；非法值回退 `all`。
  - 口径支持 `with_cache/without_cache/estimated_cost`；非法值回退 `with_cache`。
- 为预加载缓存键写失败测试，证明 Agent 或口径变化不会复用错误快照。
- 为 API 参数写失败测试，证明 `period/agent/metric` 全部发送到榜单端点。
- 为页面写失败测试，覆盖三组切换、URL 状态、切换后回到第一页和公开未登录浏览。

### 实现

- 新增纯函数模块集中维护周期、Agent、口径和 URL 兼容映射。
- 扩展 `getLeaderboard`、预加载缓存键和 Mock 数据。
- 页面增加总榜/Agent 榜、五种周期和三种统计口径；首屏仍优先读取窗口级缓存。
- 显示参与人数、全员累计值和“我的排名”；未登录时仅“我的排名/参与排名”区域提示微信登录。

### 验证

- 相关 Vitest 全绿。
- 页面切换维度不会出现旧请求覆盖新请求。
- Dashboard 生产构建、copy 注册、变更文件 ESLint、`git diff --check` 通过。

## 批次 2：服务端聚合、稳定排名与分页

### 目标

让榜单按所选周期、Agent 和口径在服务端稳定排名，分页之间不重复、不漏项。

### 测试先行

- 为边界和排序纯函数写失败测试：
  - UTC+8 今日、昨日、7 日、30 日和总累计边界。
  - 含缓存、不含缓存、预估费用计算。
  - 同分按总 Token，再按 user ID 升序，结果确定。
- 为 Edge Function 合约写失败测试：非法维度 400、分页边界、参与人数、我的排名和匿名公开读取。
- 为 SQL 合约写失败测试：RPC 包含三维过滤、`row_number` 稳定排序和只返回聚合字段。

### 实现

- 扩展快照表，保存总计及逐 Agent 的含缓存、不含缓存和预估费用聚合。
- 刷新函数生成 `today/yesterday/7d/30d/total` 快照，并兼容旧周期读取。
- 新增数据库排名 RPC，动态选择分值、过滤零用量用户、先排名再分页，并在同一查询中返回参与人数和我的排名。
- 榜单 Edge Function 只调用排名 RPC，不把整榜拉到函数内排序。
- 沿用现有小时桶唯一键和 upsert 规则，明确多设备相同时间桶只保留/合并一次，避免重复上报累计。

### 验证

- SQL/Edge 合约测试和相关 Node/Vitest 全绿。
- 50+ 条同分夹具跨页无重复、无跳号。
- 不上传任何内容正文；响应不返回邮箱、微信 openid/unionid 或密钥。

## 批次 3：微信专属登录

### 目标

排行榜登录只出现微信按钮，完成安全的二维码授权、会话创建、取消、重放防护和退出。

### 测试先行

- Discovery：端点地址和支持的 PKCE 能力正确。
- Authorization：client、redirect URI、state、PKCE 缺失或非法时拒绝；合法请求跳转微信。
- Callback：state 签名/过期/篡改拒绝；微信取消可恢复；同一微信 code 不可重复兑换。
- Token：一次性授权码、过期码、错误 verifier、错误 client 全部拒绝；成功后授权码立即失效。
- UserInfo：只接受短期 bearer token，返回稳定 sub、显示名、头像和内部邮箱，不泄露微信 token。
- UI：排行榜没有邮箱/密码/手机号/其他 OAuth；只调用 `signInWithOAuth('wechat')`；本地路由不自动弹登录。

### 实现

- 新增微信适配 Edge Function 及所需 SQL 表，敏感状态只保存摘要，短期 code 单次消费。
- AppSecret 仅从服务端环境变量读取；日志对 code、token、openid/unionid 和 secret 脱敏。
- 增加 InsForge 自定义 Provider 配置说明，provider key 固定为 `wechat`。
- 新增排行榜专属微信登录组件，移除排行榜对通用 LoginModal 的依赖和自动弹窗。
- 保持 App 其他位置的现有认证组件不变，避免越界改造本地功能。

### 验证

- 单元/合约测试覆盖 state、PKCE、过期、重放、取消、绑定和退出。
- 生产构建不含 AppSecret；仓库敏感信息扫描通过。
- 无真实微信配置时显示明确“服务尚未配置”，不模拟登录成功。

## 批次 4：规则页、兼容性与最终验收

### 目标

把排行榜规则、隐私和费用口径对用户说清楚，并完成对抗性复查。

### 测试先行

- 路由测试覆盖排行榜规则页和返回榜单。
- 文案注册测试覆盖所有新增可见文本。
- 回归测试证明公开榜单、个人资料、设备令牌和云同步仍兼容。

### 实现

- 增加规则页：娱乐性质、数据来源、UTC+8 周期、缓存口径、预估费用、稳定同分规则、去重、多设备合并和隐私边界。
- 在榜单页提供“规则说明”入口，不复制生财有道私有实现或用户数据。
- 更新 12 条调整事项状态和进度记录，区分仓库完成与微信真实扫码人工验收。

### 最终验证

- 相关 Node、Vitest、TypeScript、Dashboard build、copy、guardrails、变更文件 ESLint 和 `git diff --check`。
- 运行独立代码审查；Important 以上问题清零后再标记仓库内完成。
- 明确保留项：真实微信开放平台扫码、已部署数据库迁移和生产域名回调验证，必须使用用户自己的合规配置人工验收。

## 完成定义

- 公开榜单匿名可浏览，本地功能不要求登录。
- 排行榜登录入口只有微信，且安全流程自动化测试通过。
- 五周期、总榜/Agent 榜、三口径、参与人数、我的排名、头像/名称/Agent/Token/费用和稳定分页全部可用。
- 服务端只处理聚合用量，重复上报与多设备合并规则可验证。
- 仓库内实现与文档完成；真实微信扫码未联调时明确标为外部配置验收，不冒充完成。
