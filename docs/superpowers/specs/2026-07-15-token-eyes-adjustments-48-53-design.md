## 48. 使用统计月度成本同比

根因方向：安装版截图来自 `UsageStatsPanel`，此前只给“本月总成本”计算比较，且比较被放在标题行；其他页面中的实现不能证明该页面正确。

设计：四张成本卡使用统一字段描述。API、订阅、总成本分别读取本月与上月 USD；累计总成本不显示月度比较。每张适用卡的第三行采用左右布局：左侧 CNY，右侧同比。上月为 0 时显示绝对新增金额，避免除零伪百分比。

## 49. Cursor 套餐检测登录

根因验证顺序：先验证嵌入 WebView 是否被 Cursor 的页面策略/登录跳转阻断，再检查 Cursor 桌面端本地认证状态是否能通过官方用量接口只读验证，最后才使用系统浏览器 OAuth/回调。独立 WebView Cookie 与用户日常浏览器 Cookie 隔离，不能把“打开同一网址”误当成复用登录。

设计：取消无反馈的永久空白登录窗。检测顺序为“已绑定账号会话 → 可验证的本地官方会话 → 系统浏览器授权回调”。只有官方支持的凭据/授权路径才能使用；不读取或复制浏览器 Cookie。授权成功后关闭临时窗口并刷新套餐，超时或页面被阻止时关闭窗口并显示原因。

## 50. 同一供应商多账号检测

设计：将“供应商单例会话”提升为本地账号记录集合。账号记录只保存脱敏标识、显示名、供应商、会话引用和最近用量快照；套餐保存 `account_id`。新增账号、重新授权、删除账号和刷新用量互不影响其他账号。明确不实现把账号注入 Cursor/Codex 启动环境。

## 51. 其他 AI 花销二级分组

设计：保留最多两级的现有后端约束，在每个一级组标题处增加“新增子分组”。二级组作为真实拖放容器，支持折叠；拖入后同时更新 `group_id` 与排序。二级组不得再创建第三级，避免无限树造成成本汇总和拖拽歧义。

## 52. Trae 与 CodeBuddy 数据检测

设计：数据目录检测区分三种状态：可识别且有 Token 日志、可识别但数据加密/无 Token 字段、路径无效。用户选择安装目录时，只读解析 Windows 安装位置对应的 Roaming/用户数据候选目录；同步器只统计明确的 Token 字段，绝不根据会话数估算 Token。

## 53. 模型定价目录与新模型标记

静态目录覆盖本轮截图中的 GPT、Claude、Gemini、GLM、DeepSeek、MiniMax、Kimi、MiMo、Grok 模型。价格来源优先官方定价；无法从官方确认的条目保留在目录中并标记“待核价”，不参与虚构成本。

运行时把实际使用模型与目录合并：目录外模型显示在定价表顶部或对应供应商分区，带“新模型”标记；若定价引擎已有可信价格则展示，否则显示“待核价”。该标记只基于模型 ID，不读取对话内容。

## 对抗性验收

1. 每项先有失败测试或可复现诊断，再修改实现。
2. 自动化测试之外，构建安装版并用安装版页面结构做静态/运行验证。
3. 不以“组件中已有代码”作为完成证据；必须核对实际调用组件、传入数据和最终 DOM。
4. 对第三方登录、加密数据库和未公开财务接口，不以模拟数据冒充成功。
5. 最终汇报逐项列出：完成、受官方能力限制、未完成；不能合并模糊表述。
