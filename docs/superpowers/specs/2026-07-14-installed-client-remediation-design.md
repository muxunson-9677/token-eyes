# Token Eyes 安装客户端五项复核修复设计

日期：2026-07-14  
状态：设计已获用户确认，进入实施

## 1. 范围与边界

本轮只修改 Token Eyes 仓库内的代码、测试、文档和构建产物，不修改、控制或重新配置仓库外的软件与文件。真实账号凭据只由用户在安装后的 Token Eyes 客户端内填写；开发和自动化测试使用不可用的占位凭据与固定响应，不读取、复制或写入真实密钥。

本轮以安装客户端实测为准，纠正旧进度文档中“源码存在即视为完成”的过早结论。

## 2. 五项问题与验收标准

### 2.1 Codex 账号检测失败

现状：官网账号检测强制创建隔离的 Codex app-server 登录会话。实测会话目录没有生成授权文件，而本机已有有效的 Codex 官方登录，因此重复授权既增加摩擦，也成为失败点。

设计：

1. 检测开始时先只读发现本机 Codex 官方登录目录，并使用已有令牌调用官方用量接口。
2. 本机没有可用登录、令牌过期且刷新失败时，才启动官方 app-server OAuth。
3. OAuth 保留浏览器自动回调，并提供手动粘贴完整回调地址的兜底入口。
4. 授权成功和额度同步是两个状态；额度暂时读取失败不能把已授权状态回滚为“连接失败”。
5. 错误必须区分：未发现登录、授权取消、回调未到达、令牌过期、网络失败、官方接口结构变化。

验收：已有 Codex 官方登录时无需再次登录即可完成检测；无登录时可通过 OAuth 或手动回调完成；失败不清除上次成功额度。

### 2.2 排行榜入口缺失

现状：`/leaderboard` 和规则页已存在，但侧边栏没有入口。

设计：在概览分组中增加“排行榜”顶级入口，沿用现有路由和登录边界。本地页面继续免登录，进入排行榜后才显示微信登录或开发者测试直登。

验收：安装客户端侧边栏可直接进入排行榜；规则页和返回路径可达；现有概览、支出和设置入口不受影响。

### 2.3 Token 服务列表错误隐藏已耗尽套餐

现状：列表同时过滤 `used < total` 和 `percentage < 100`，因此 100% 用完但尚未过期的套餐被隐藏。

设计：只按过期状态过滤套餐；保留有有效总额度的已耗尽套餐，继续按已用量降序和每页 5 条分页。已耗尽状态显示 100%，但不伪造剩余额度。

验收：100% 用完且未过期的套餐展示；过期套餐不展示；跨页序号连续。

### 2.4 按平台选择账号检测方式

不使用一套通用“URL + Key”冒充所有平台能力，也不复制 Cockpit Tools 的代码。参考其多入口、多适配器思路，但每个平台只调用官方接口：

| 平台 | 目标能力 | 凭据 | 实现 |
|---|---|---|---|
| Codex | 官方订阅窗口额度 | 本机官方登录；OAuth 兜底 | 官方 Codex/app-server 与 ChatGPT 用量接口 |
| Kimi | 开放平台现金、代金券和可用余额 | Kimi API Key | `GET /v1/users/me/balance` |
| 阿里云/千问 | 阿里云账户可用余额 | 专用只读 RAM AccessKey ID/Secret | BSS `QueryAccountBalance` |
| 火山引擎/豆包 | 火山引擎账户可用余额 | 专用只读 AK/SK | Billing `QueryBalanceAcct` |
| DeepSeek | 开放平台余额 | DeepSeek API Key | 官方余额接口 |
| MiniMax | Key/Token Plan 可用性 | MiniMax API Key/Token Plan Key | 只验证官方公开能力；没有公开现金余额接口时明确显示不支持 |
| 智谱 GLM | 套餐额度或 Key 可用性 | 官方 API Key/JWT 规则 | 使用内置端点和响应解析，不要求用户填写 JSON 路径 |

凭据界面只显示当前平台必填字段。长期凭据不得进入普通配置、前端回显或日志；沿用项目现有系统安全凭据引用。请求加入超时、单次并发合并和短时缓存，刷新不阻塞使用统计首屏。

验收：每个适配器覆盖成功响应、401/403、429、超时、HTML 登录页和响应结构变化；真实余额仍需用户在安装客户端内自行填写凭据比对。

## 3. OpenCode 检测目录与限制显示

现状：OpenCode 已出现在部分前端 provider 列表，但数据目录没有配置项，后端 token-only 汇总也没有返回 OpenCode。

设计：

1. 数据目录增加 OpenCode 配置项，支持 `OPENCODE_HOME`、`XDG_DATA_HOME/opencode` 和用户自定义覆盖。
2. 检测 `opencode.db`、数据库 WAL 或 `storage/message`，不把空目录误判为有效。
3. 同步代码统一使用解析后的 OpenCode 目录，不再绕过设置页自定义路径。
4. 限制显示把 OpenCode 作为 token-only provider，只显示真实导入 Token 消耗，不显示虚构额度或现金成本。

验收：自动路径、自定义路径、无效路径和 Windows/WSL 归一化均有测试；限制接口返回 OpenCode Token 消耗并在页面展示。

1. 先写失败测试，修复排行榜入口和 Token 服务过滤。
2. 先写目录与汇总失败测试，补齐 OpenCode。
3. 先写本机登录优先级和状态分离测试，修复 Codex。
4. 校核并补齐各供应商适配器、凭据表单与错误分类。
5. 跑全量验证，构建仓库内 Windows EXE，更新总进度文档。

## 5. 完成定义

只有代码行为、自动化测试、生产构建和仓库内可重复验证证据全部具备，才标记“仓库内完成”。需要用户真实密钥、微信开放平台或安装环境交互的部分单列为“待人工验收”，不得用 fixture 或模拟登录冒充完成。
