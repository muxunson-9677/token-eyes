# 价值对比与实时会话数据溯源设计

## 目标

把“价值对比”和“实时会话”从聚合数字页面改为可追溯的真实功能页面。每个用户可见结论都能展开查看安全的采集证据、数据状态和可跳转的依据；未知数据不得伪装成零值。

## 已确认的边界

- 仅使用真实本地采集、可解释计算和公开价格数据。
- 不保存或展示提示词、回复、代码、文件正文、工具结果、系统提示词、推理文本或密钥。
- 允许展示的会话证据仅限安全标识、时间、Agent、模型、Token、状态、成本、原生资源变化、归因状态和价格元数据。
- 无可靠证据的积分、Credits、速通次数和额度保留原始单位；不得固定换算为 Token。
- 未知、未授权、暂不支持、仅额度和待识别必须显示各自状态，只有采集到真实零值时才显示 `0`。

## 数据契约

在价值对比和实时会话接口中，所有聚合指标与明细行均使用安全证据对象：

```json
{
  "value": 1256,
  "unit": "tokens",
  "evidence_state": "exact",
  "evidence": {
    "source_kind": "local_usage_log",
    "record_count": 4,
    "observed_from": "2026-08-22T01:00:00.000Z",
    "observed_to": "2026-08-22T01:15:00.000Z",
    "safe_record_refs": ["session:ab12…"],
    "pricing": {
      "state": "estimated",
      "model": "gpt-5",
      "source_url": "https://..."
    }
  }
}
```

`safe_record_refs` 使用可读但不可还原会话正文的截断/散列标识。`source_url` 仅用于公开模型价格页或应用内“数据与诊断”定位，不指向用户私密文件或第三方账户账单。

## 价值对比页

1. 顶部三项保持“实际支出 → API 等价使用价值 → 价值倍数”，每项提供“查看依据”。
2. “本月构成”必须固定呈现订阅、官方 API、其他 AI、积分/速通/配额、待识别五类；无证据时显示状态，不补零。
3. 套餐价值对比只在真实 `plan_ref` 与 `account_ref` 同时存在时呈现套餐级结果；否则列为“待归因来源”，不能伪装为套餐。
4. 三级折叠区改为真实内容：订阅/API 明细、原生资源明细、模型价格与覆盖率、待识别与归因、数据状态。每一项显示记录数、采集时间、状态与可用依据链接。
5. 六个月趋势中，未覆盖月份使用“无数据”而非零柱；真实零值仍显示零柱。

## 实时会话页

1. 顶部摘要与焦点会话仍来自实时聚合，但可展开查看会话证据。
2. 会话构成中的每个 Token 组成和 API 等价值都绑定对应的安全来源、计数、时间范围、模型和价格状态。
3. “请求明细”改为真实的安全请求元数据列表，而非趋势点替代品。
4. 价格覆盖率列出已覆盖/未覆盖模型及公开价格来源；原生 Credits、积分、速通和额度以各自单位显示。
5. 没有新增使用事件时，数值保持不变；刷新动作显示最新采集时间与数据状态。

## 空态与诊断

空态必须说明属于以下哪一种：未检测到本地来源、已连接但无精确数据、需要授权、仅额度、价格缺失、数据过期或暂不支持。每种状态提供实际可执行的刷新或“数据与诊断”跳转，不显示假数据。

## 验收

| 验收项 | 必须可见的结果 | 证据层 |
| --- | --- | --- |
| 六个月历史边界 | 仅汇总最近六个月的账本记录；更早记录不进入卡片 | `agent-history-inventory` 单元测试与本地 API 契约测试 |
| 真实 Agent 名称 | 卡片使用注册表中的正式名称，不出现 `Agent 1/2` 等占位名 | API `agent_history` 与浏览器截图 |
| 已安装但无历史 | 只显示“已检测，无记录”与 `—`，不伪造 `0`、Token 或成本 | API 契约、卡片翻页交互与浏览器截图 |
| 实时与历史分离 | 焦点会话仅由所选实时范围决定；横向卡片仅由六个月历史/检测清单决定 | 后端视图模型测试与前端交互测试 |
| 隐私白名单 | `agent_history` 不含提示词、会话正文、代码、密钥或私密文件路径 | API 序列化断言 |

1. 每张页面都能从可见指标展开至安全证据，且公开价格链接/应用内诊断跳转可用。
2. 空值不显示为 `0`，真实零值才显示 `0`。
3. 价值构成包含积分/速通/配额和待识别状态。
4. 实时请求明细来自请求级安全元数据；会话树只使用明确的父子标识。
5. 在最终安装包中，以真实本机数据验证：首次加载、展开依据、跳转、手动刷新和重启后状态。
6. 两次独立核对：先在运行时逐项核对验收，后从最终安装包重新走真实用户路径。
