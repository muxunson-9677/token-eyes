# Token Eyes 桌面小组件与 Agent 状态设计

日期：2026-07-29
状态：胶囊交互方向已确认，等待其他需求讨论完成后统一实施

## 1. 目标

把现有 `/widgets` 中偏展示、偏占位的内容扩展为 Windows/Tauri 上可真实使用的桌面悬浮小组件。用户无需打开 Token Eyes 主窗口，即可快速查看：

1. 多项目、多对话的 Agent 运行状态。
2. Claude、Codex、Cursor 等服务的用量限制。
3. 当前主要模型的 Token 消耗与占比。

小组件只展示本地状态与用量元数据，不读取或展示 prompt、消息正文和会话内容。

## 2. 明确不做

- 不增加用量耗尽通知。
- 不增加预算设置。
- 不新增环境统计、上下文压力或 Agent 体验诊断。
- 不提供账号、模型、MCP 或 Skill 切换。
- 当前范围不包含实体硬件红绿灯；只在桌面小组件内实现状态灯。

## 3. 桌面窗口体验

### 3.1 默认状态

- 使用独立的 Tauri 桌面悬浮窗口，不依赖 Token Eyes 主窗口保持打开。
- 默认使用约 `322 × 72 px` 的迷你胶囊形态，以最终 Windows 缩放比例和可读性验证为准。
- 点击左侧主 Agent 图标后，在同一张卡片内展开详细内容；再次点击恢复胶囊形态。
- 胶囊形态和详情形态是同一个窗口、同一个组件，不展示成两张独立卡片。
- 无系统标题栏，小圆角、Apple/macOS 控制中心式半透明材质。
- 支持始终置顶。
- 用户可拖动到桌面任意位置。
- 顶部区域用于拖动窗口，内容区域用于滚动，右下角用于缩放，三种操作不得冲突。

### 3.2 数据较多时

- 项目、对话、套餐或模型增加时，小组件不得自动拉高或拉宽。
- 内容区域使用单一纵向滚动容器。
- 支持鼠标滚轮、触控板和拖动滚动。
- 滚动条默认隐藏；鼠标移入或滚动时显示轻量覆盖式滚动条。
- 不允许项目列表内部再嵌套第二个滚动区域。

### 3.3 用户缩放

- 默认胶囊保持紧凑尺寸；展开详情后，用户可以从右下角拖动调整宽度和高度。
- 设置最小尺寸，不能缩到内容不可操作。
- 拉高后自动显示更多条目；拉宽后优先显示更完整的项目、对话和模型名称。
- 保存窗口位置、宽度、高度、展开状态、当前 Agent 和最后使用的信息模式。
- 多显示器布局或缩放发生变化时，将窗口限制回可见屏幕范围。

## 4. 胶囊导航与 Agent 选择

小组件始终只有一张卡片，不增加独立的导航卡、设置卡或“默认/拉高后”方案控件。

- 左侧主图标显示当前 Agent。点击主图标只负责展开或折叠详情。
- 主图标旁附着一个独立小箭头，点击后打开 Agent 菜单。
- Agent 菜单在胶囊折叠状态和详情展开状态下都必须完整可见，不得被卡片的圆角裁切或 `overflow` 隐藏。
- Agent 菜单包含 Token Eyes 全部汇总，以及当前产品支持的 Claude、Codex、Cursor、Hermes 等 Agent。
- 所有 Agent 图标必须直接复用项目内已经收录的官方品牌资源；Token Eyes 使用自身产品图标。禁止使用临时手绘、近似重画或无来源的替代图标。
- 右侧只保留一个小型信息模式按钮。点击后打开项目、用量、Token 消耗三个选项，胶囊折叠时同样可以操作。
- 切换 Agent 或信息模式只替换当前胶囊内容，不创建新卡片、不改变窗口尺寸。
- 当前 Agent 在某个模式没有数据时，保留模式入口并显示明确空状态；Token Eyes 选项汇总全部 Agent 的现有数据。

信息模式按钮使用简洁线性图标，悬停显示名称。弹出菜单位于卡片裁切层之外，确保胶囊状态下可见；动画只使用短暂淡入和轻微位移。

## 5. 项目状态页

### 5.1 两级层级

- 第一层是项目。
- 第二层是项目内的多个 Codex 对话。
- 同时只展开一个项目；其他项目保持单行。
- 已完成对话默认汇总为“X 个已完成”，优先显示等待处理和正在运行的对话。

### 5.2 状态灯

状态定义：

- 黄色：正在运行。
- 绿色：任务完成。
- 红色：等待批准、异常、用户中断或非正常停止。

胶囊摘要：

- 红、黄、绿三个灯始终同时显示，顺序固定为红、黄、绿，形成明确的红绿灯语义。
- 每个灯旁显示对应状态的对话数量，不再使用两个占空间较大的纯数字指标区。
- 对应数量大于 `0` 时，灯显示状态色和轻量发光；数量为 `0` 时，灯和数字显示为灰色。
- 三个灯不得因为某一状态为 `0` 而消失，避免用户误以为该状态没有被监测。
- 胶囊只显示状态灯和数字；等待批准、运行中、已完成等完整文字保留在展开详情中，满足可访问性要求。

项目标题行：

- 左侧主灯表示项目内最紧急的对话状态，优先级为红色、黄色、绿色。
- 右侧显示该项目内所有对话状态灯的集合以及对话数量。
- 项目之间使用轻量细分割线。

对话标题不得读取或生成新的内容摘要，只能使用已有的安全会话标题或隐私安全的项目标识。

### 5.3 状态可靠性

Codex 本地事件可直接识别 `task_started`、`task_complete`、`turn_aborted` 和 `error`。等待批准状态仅在存在可靠事件或未完成交互证据时标记；证据不足时不得将长时间运行直接误判成等待批准。

实现前需要为状态推导建立独立测试夹具，覆盖：

- 正常开始与完成。
- 同一项目多个并发对话。
- 用户中断。
- 错误退出。
- 等待批准后继续。
- 日志停止更新但 Codex 进程仍存在。
- 应用或电脑异常退出后的过期状态恢复。

## 6. 用量页

- 复用当前 Token 服务列表和官方限制数据，不建立第二套数据源。
- 胶囊形态默认显示当前 Agent 最重要的两个套餐窗口。
- 胶囊摘要不能只堆放裸百分比，必须使用小型圆形进度、细进度条或沙漏图标与百分比组合；首选圆形进度加百分比。
- 图形只表达进度或重置时间，不增加装饰性图表。
- 展开详情后显示更多套餐窗口；数据更多时在内容区域滚动。
- 每行只显示 Provider/套餐、重置倒计时、使用百分比和极细进度条。
- 不使用内容分割线。
- 支持现有多账号数据结构；后续多账号检测与批量刷新优化单独讨论。

## 7. Token 消耗与模型详情

- 胶囊形态使用纯数据表达，只显示当前 Agent 的 Token 总量与花销，保持参考方案中的极简信息密度。
- Token 总量和花销是唯一允许在胶囊中使用纯数字双指标的模式。
- 展开详情后显示模型消耗明细。
- 复用现有模型 Token 统计。
- 按 Token 占比排序。
- 每行显示模型名、Token 数量、占比和极细进度条。
- 不使用内容分割线。
- 默认小尺寸下允许安全截断长模型名；拉宽后显示更多文本。

## 8. 材质与透明度

- 背景是可调透明材质，不是固定纯色。
- 提供少量受控预设：冰霜、石墨、海蓝、暖沙。
- 透明度与材质色分别保存。
- 默认透明度约 72%，最终范围暂定为 40%–96%。
- 不提供任意取色器，避免生成不可读的低对比度组合。
- 红黄绿只表达任务状态；系统蓝色只表示当前信息模式或可操作控件。

材质与透明度不使用独立设置卡片。展开详情后在右上角显示一个小型“外观”按钮，点击后在当前卡片内部覆盖显示迷你面板，关闭后不占用空间。

## 9. 交互与可访问性

- 点击左侧主 Agent 图标展开或折叠详情；小箭头只打开 Agent 菜单；右侧模式按钮只打开信息模式菜单，三种热区不得重叠。
- 打开 Token Eyes 对应完整页面使用详情中的明确入口，不能占用整个胶囊点击区域，以免与展开、Agent 和模式切换冲突。
- Agent 菜单、信息模式、项目展开、外观和缩放热区需要明确的鼠标命中范围。
- 透明度较低时仍必须保持最低文字对比度。
- 状态不能只依赖颜色；等待批准、运行中、已完成等文本仍需保留。
- 支持系统缩放和高 DPI。
- 小组件窗口获得键盘焦点时，Agent、信息模式、详情展开和项目展开功能均可通过键盘操作。

## 10. 数据与隐私

- 只读取 Token、费用、限额、Provider、模型、项目标识、会话标识、时间和状态事件。
- 胶囊、详情卡片和 Token Eyes 主界面复用同一份状态与用量数据；小组件不得建立独立统计渠道。
- 不保存或上传 prompt、回复正文、工具参数、命令输出或完整本地路径。
- 项目和会话标识继续使用现有隐私安全的规范化或哈希策略。

## 11. 额度重置检测、历史与提醒

### 11.1 多来源检测

额度重置不得继续只依赖现有的定时轮询。Token Eyes 使用同一套重置事件账本融合以下来源：

- 官方用量响应中的主窗口、次窗口、使用百分比和 `reset_at`。
- 官方响应中的重置额度计数；移除 0.54.25 对该字段的主动忽略。
- Codex 本地任务快照中的 `token_count.rate_limits`，仅读取用量、窗口和时间字段，不读取消息正文。
- Token Eyes 运行期间的增量轮询，用于及时提醒。

普通周期重置以计划的 `reset_at` 和重置后的窗口状态确认；手动使用重置额度以额度计数下降、使用百分比下降和新窗口建立共同确认。多个来源观察到同一次重置时必须合并为一条事件。

Token Eyes 启动或升级后扫描最近 30 天的本地用量快照，补录软件未运行期间发生的重置。首次补录的旧事件只进入历史记录，不触发当前提醒；只有新发生并首次确认的事件触发提醒。

### 11.2 最近 30 天历史

重置历史按发生时间倒序显示并按日期分组，不再限制为最近 3 条。每条事件至少保存和展示：

- Agent、账号标识和额度窗口。
- 重置发生时间与首次观察时间。
- 重置类型：周期重置或手动重置。
- 重置前后的使用百分比，例如 `21% → 0%`。
- 去重标识与数据来源；来源细节默认不占用主列表空间，仅用于诊断。

历史按发生时间滚动保留最近 30 天，超期记录自动清理。所有时间使用用户本地时区显示。

### 11.3 Windows 醒目提醒

每个新重置事件在持久化成功后触发一次统一提醒：

- Windows 原生通知，带提示音；点击后打开重置历史。
- Token Eyes 主窗口顶部显示醒目但不阻断操作的绿色横幅。
- 托盘图标显示未读标记，用户查看重置历史后清除。
- 如果系统通知权限不可用或被关闭，应用横幅、小组件提醒和托盘未读标记仍然生效。

同一事件在各提醒渠道共用同一个事件标识，重启、重复轮询和多个 Codex 对话不得造成重复提醒。本功能只提醒额度已经重置，不新增“用量耗尽提醒”。

Windows 的“动画图标”和“额度重置时撒花”属于 macOS 原生菜单栏能力，Windows 设置页不再显示；macOS 保留原有能力。

### 11.4 小组件提醒

小组件提醒必须融入现有单张胶囊，不创建第二张卡片，也不改变默认窗口尺寸：

- 新重置发生时，胶囊内容短暂切换为绿色确认状态，显示 Agent 图标、“额度已重置”和发生时间。
- 状态灯或确认图标进行两次轻量脉冲，总时长约 6 秒；不持续闪烁，不妨碍拖动窗口。
- 动画结束后恢复用户原来的 Agent 和信息模式，并在 Agent 图标或模式按钮旁保留绿色未读点。
- 点击确认状态或未读点，直接展开对应重置记录；查看后清除小组件和托盘的未读状态。
- 当前选择的 Agent 与发生重置的 Agent 不同时，确认状态必须明确显示实际 Agent，恢复后不得改变用户原来的选择。
- 小组件当时未显示时不丢失提醒；下次显示时保留未读点，但不重播完整动画。

### 11.5 可靠性边界

- 先写入事件账本，再发送任何提醒，避免提醒出现但历史记录为空。
- 系统时间调整、离线恢复、不同 Codex 对话写入的重复快照不得生成伪重置。
- 重置前后缺少连续快照时，可以使用计划重置时间或首次确认时间，但界面不得伪造高于数据来源的时间精度。
- 解析本地快照时只提取时间、用量和窗口元数据，禁止保存 prompt、回复正文、工具参数或命令输出。

## 12. 验收标准

1. Windows 桌面可打开独立悬浮小组件。
2. 默认尺寸小巧，数据增加不会自动改变窗口尺寸。
3. 胶囊折叠时可以直接切换 Agent 和项目、用量、Token 消耗三个模式，菜单不会被卡片裁切。
4. Claude、Codex、Cursor、Hermes 和 Token Eyes 使用项目内官方图标资源，不存在临时近似图标。
5. 项目胶囊始终显示红、黄、绿三个灯和对应数量；数量为零的状态显示灰灯。
6. 用量胶囊使用进度图形与百分比组合，Token 消耗胶囊只显示 Token 总量与花销。
7. 项目页支持多个项目和每个项目多个对话。
8. 状态灯与状态文本符合实际 Codex 生命周期。
9. 内容超出时只有一个纵向滚动区域。
10. 用户可以调整窗口大小，并在重启后恢复位置、尺寸、Agent 和信息模式。
11. 材质色和透明度在卡片内部设置，重启后保持。
12. 小组件可拖动、置顶，并在多显示器变化后保持可见。
13. 不读取或暴露会话正文。
14. 普通周期重置与手动使用重置额度都能写入同一份事件账本，重复来源不会生成重复事件。
15. 历史页显示最近 30 天的重置时间、类型、Agent、账号和重置前后用量。
16. Token Eyes 未运行期间发生、但存在 Codex 本地快照证据的重置能够在下次启动时补录。
17. 新重置触发 Windows 原生通知、主窗口横幅、托盘未读标记和小组件胶囊提醒；旧记录回补不触发提醒。
18. 小组件提醒不创建新卡片、不改变窗口尺寸，动画后恢复原 Agent 和信息模式，并保留可点击的未读点。
19. Windows 不再显示仅适用于 macOS 的“动画图标”和“额度重置时撒花”设置。

## 13. 尚待后续讨论

- 是否默认启用始终置顶，以及是否提供鼠标穿透快捷切换。
- 小组件是否随 Token Eyes 启动自动显示。
- 完成状态保留多长时间后从项目页隐藏。
- 第一版除 Codex 外是否同时支持 Claude Code 等 Agent 状态。
- Token 服务列表的多账号检测、账号标签和批量刷新细节。
