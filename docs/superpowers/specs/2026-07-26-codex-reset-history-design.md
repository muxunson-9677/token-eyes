# Codex 重置记录设计

## 目标

在 Token Eyes 桌面端新增独立的“重置记录”导航页，展示本机 Codex 套餐额度实际发生重置的时间。该功能继续使用现有本机额度检测，不增加 X 搜索、付费 API、云端任务或新的隐私数据上传。

排行榜的时间范围保持为“今日 / 本周 / 本月 / 总累计”，本次不增加自定义日期，也不改变排行榜统计口径。

## 用户界面

- 侧边栏新增一级入口“重置记录”，未读重置提醒的小圆点只显示在该入口。
- 页面顶部为“今日提醒”：
  - 当本机检测到今天发生过 Codex 重置时，醒目显示最近一次重置的准确日期和时间。
  - 今天没有重置时，该区域不显示占位提示或虚构记录。
- 页面下方为“历史记录”：
  - 仅显示实际发生的重置。
  - 不显示“今天 / 昨天 / 本周”等相对标签，只显示本机时区下的年月日和时分。
  - 最多保留最近 5 条真实重置记录。
  - 当今天存在重置时，今日记录只在顶部提醒显示，历史区域显示其余记录，避免重复。
- 第一版只显示 Codex，页面结构保留未来增加 Claude 的空间，但不预先实现 Claude 逻辑。

## 数据口径

只有以下两类本机事件属于“真实重置记录”：

1. `reset_completed`：按额度窗口跨过官方重置时间且用量下降确认；发生时间取原窗口的 `resetAt`。
2. `unexpected_quota_restore`：额度在正常重置时间前持续恢复并通过二次确认；发生时间取确认检测的 `createdAt`。

`reset_upcoming` 和 `official_reset_announcement` 继续用于现有提醒，但不进入重置历史。

状态压缩时仅保留最近 5 条真实重置事件，同时保留现有即将重置和公告提醒所需事件；本地接口单独返回经过清洗的 `history` 数组。前端根据本机日历日期区分今日提醒与历史记录。

## 隐私与成本

- 数据仅来自 Token Eyes 已有的本机 Codex 用量接口。
- 只保存事件类型、额度窗口和时间戳，不保存凭证、响应正文、代码或对话。
- 不启用 X 搜索，不调用付费模型，不增加云端部署与定时任务，因此该功能没有新增运行费用。

## 验收标准

- 导航可立即打开“重置记录”页。
- 今天有实际重置时顶部醒目显示；今天无重置时顶部内容为空。
- 历史只含真实重置、按时间倒序、总计不超过 5 条。
- 所有记录只显示准确日期时间，不显示相对日期标签。
- 现有全局重置提醒与确认已读行为仍可用。
- 排行榜仍只提供“今日 / 本周 / 本月 / 总累计”。
- Node、Dashboard、文案校验、类型检查和生产构建全部通过。
