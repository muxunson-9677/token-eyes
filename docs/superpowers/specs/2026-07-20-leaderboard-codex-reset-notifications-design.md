# Token Eyes 排行榜、登录参与与 Codex 重置通知设计

日期：2026-07-20

状态：待用户复核后进入实现计划

主线：Token Eyes Tauri + React + 本地 Node 运行时 + 现有 InsForge 后端
范围约束：所有代码与文件增删改查仅限本仓库 `D:\04-AI-Project\010-Token eye` 及其子路径。

## 背景

Token Eyes 是本地优先的 AI Token 用量与成本工具。用户不登录时也必须能够使用全部本地功能；云端只服务于公开排行榜和登录资料，不得成为本地仪表盘的运行前提。

仓库目前已经具备：

- InsForge 登录、设备令牌、用量上传和排行榜 Edge Functions。
- 云上传默认关闭；本地队列和仪表盘可离线工作。
- 周、月、总累计排行榜快照，以及 Token 总量、Agent 拆分和模型标价折算。
- 昵称、OAuth 头像、公开/匿名资料等基础能力。
- Codex 官方会话窗口和 `reset_at` 配额字段的本地读取能力。

当前主要缺口：

- 登录、参与排行、云同步、公开资料被拆成了多个用户概念，交互过重。
- 今日排行、预估费用排序仍是前端占位。
- 开启云同步会把本地仪表盘切换到云端账户口径，违背“本地仪表盘始终优先”。
- 客户端每次同步后直接触发一次排行榜刷新，用户规模增长时会放大 Edge Function 调用和数据库扫描。
- 实际总成本没有独立的公开同意与排行榜口径。
- 没有 Codex 定时重置、额度异常恢复、重置券/活动通知。

## 目标

1. 默认不登录；不登录可使用全部本地功能，并可查看公开排行榜。
2. 只保留一个小入口“登录 · 参与排行”；登录成功即参与排行，无额外参与开关。
3. 登录后的云上传是隐藏实现，不向用户暴露“云同步”概念，本地仪表盘始终读取本机数据。
4. 支持自定义昵称和头像。
5. 支持今日、本周、本月、总累计四个周期。
6. 支持 Token 总量、模型标价折算、实际总成本三种排行指标。
7. 实际总成本默认不公开，只有用户主动勾选后才上传汇总并参与该榜。
8. 不上传代码、对话、项目/仓库名、路径、Skill/MCP 名、按键、截图或文件内容。
9. 增加 Codex 定时重置、异常恢复、重置券/官方活动的醒目提醒。
10. 控制 Edge Function、数据库扫描和带宽消耗，不能按用户数放大排行榜重算。

## 非目标

- 不引入 Firebase，不新建 WPF 版排行榜。
- 不提供用户可见的“云同步”开关或云端账户仪表盘。
- 不上传或展示会话正文、消息内容、会话时长、消息数量、官方额度百分比、操作系统或用户时区。
- 不把排行榜宣传成 OpenAI/Anthropic 等供应商认证账单。
- 不承诺完全杜绝客户端伪造；本榜定位为客户端自报的娱乐性统计。
- 不为排行榜绑定现金奖励或高价值权益。
- 不抓取 Codex 页面 DOM，不读取或上传 Cookie、Access Token、Refresh Token。
- 不承诺第三方可以实时检测所有 Codex 重置券；官方没有公开稳定的重置券 webhook/API 时只做尽力而为检测。

## 方案选择

### 方案 A：复用现有上传管道并简化产品概念（采用）

- 复用 InsForge 登录、设备令牌、`tokentracker_hourly`、幂等 upsert、聚合 RPC 和排行榜快照。
- 登录后自动启用排行榜上传。
- 桌面仪表盘保持本地口径。
- 删除客户端同步后触发排行榜全量刷新的耦合，改为服务端统一调度。

优点：改动集中、最大程度复用现有代码、多设备聚合自然成立。

代价：需要清理现有账户云视图耦合，并收窄上传数据。

### 方案 B：新增独立的按日排行榜上传系统（不采用）

隐私和存储最小，但需要新建表、迁移、上传协议、聚合函数和测试，重复现有系统，开发量更大。

### 方案 C：迁移 Firebase（不采用）

会重复认证、存储、排行和安全体系；桌面客户端仍无法证明 Token 数真实，且不保证免费额度覆盖生产规模。

## 用户流程

### 1. 未登录

- 首页、成本、项目、设置、Token 检测、Codex 配额与通知全部本地可用。
- 排行榜页面公开可访问。
- 侧栏或右上角仅显示一个低干扰按钮：`登录 · 参与排行`。
- 不请求 InsForge 登录状态以外的排行写入能力，不创建匿名账号，不上传队列。

### 2. 登录弹窗

标题：`登录并参与 Token 排行`

必须在登录按钮上方显示简短告知：

1. 登录后自动参与排行并上传 Token 聚合统计。
2. 不上传代码、对话、项目名、Skill、MCP 或文件内容。
3. 数据属于客户端自报统计，可在账号菜单退出排行并删除。

提供“查看排行榜规则与数据字典”链接。点击 OAuth/邮箱登录即代表接受本次排行数据处理。

### 3. 登录成功

1. 将 `leaderboard_public` 设为 `true`。
2. 使用 OAuth 昵称和头像建立初始公开资料。
3. 签发或恢复设备令牌。
4. 执行一次历史队列补传。
5. 后续按事件驱动策略增量上报。
6. 侧栏按钮替换为头像和昵称；点击进入资料设置。

产品日常界面不提供匿名参榜或临时隐藏开关；不希望展示真实身份的用户可修改昵称和头像，以化名参与。

若登录成功但首次上传失败，登录本身仍成功，本地功能不受影响；头像菜单显示“排行数据等待同步”。

### 4. 登出与退出排行

- `退出登录`：停止后续上传，不立即删除历史排行数据，便于重新登录恢复。
- `退出排行榜并删除数据`：撤销设备令牌，删除云端用量、实际成本汇总、排行榜快照、资料和自定义头像。
- `删除账户`：在退出排行榜清理基础上删除认证账号。

“退出排行榜并删除数据”放在账号菜单的隐私区域，不占用主界面空间，但必须可发现并二次确认。

## 同步与成本控制

### 为什么不采用每客户端固定 10–15 分钟

InsForge 当前公开定价中，Free 包含每月 100,000 次 Edge Function 调用和 5 GB 带宽；Pro 为每月 25 美元，包含 100,000 次调用，超出后每 1,000 次 0.01 美元，并提供 250 GB 带宽：

- https://insforge.dev/pricing

以 3,000 DAU 估算：

- 每人每天 1 次上传：约 90,000 次/月，尚未计算设备令牌、资料和其他接口。
- 每人每 15 分钟持续上传：理论上 `3,000 × 96 × 30 = 8,640,000` 次/月。
- 若每次客户端上传还触发排行榜刷新，调用、数据库扫描和带宽会继续翻倍。

因此生产阶段不应假设永久免费。3,000 DAU 应至少按 InsForge Pro 的 25 美元/月基础成本预算，并设置用量告警。

### 客户端上传触发（采用）

不建立固定 10–15 分钟计时轮询。仅在本地队列有新数据时触发：

1. **首次登录**：立即补传历史聚合。
2. **打开排行榜**：如果有新数据且距上次成功上传超过 30 分钟，则上传。
3. **应用启动每日兜底**：如果有待上传数据且距上次成功上传超过 24 小时，则上传。
4. **正常退出 best-effort**：有新数据时尝试一次短超时上传；失败留在本地队列，下次继续。
5. **手动刷新排行榜**：只拉取服务器快照；满足第 2 条时可先触发一次增量上传，但不直接重算全榜。

上传必须先检查队列 offset/pending 状态；没有新数据时不得调用 ingest。

### 服务端榜单刷新（采用）

客户端上传完成后不再调用 `tokentracker-leaderboard-refresh`。

由服务端 Cron 全局执行：

| 快照 | 频率 |
|---|---:|
| 今日 | 每 15 分钟 |
| 本周 | 每 15 分钟 |
| 本月 | 每小时 |
| 总累计 | 每天一次 |

每 15 分钟刷新今日和本周的调用量只有每天 192 次，与登录用户数量无关。读取排行榜只读预计算快照，不在 GET 请求中临时聚合原始表。

若后续数据库扫描仍高，应把聚合尽量下推到 SQL/RPC，并按 `updated_at` 增量更新受影响用户，禁止把全量小时行拉到 Edge Function 内存后循环计算。

生成公开快照时必须先过滤 `leaderboard_public = true` 的参与者，再在这个公开集合内计算连续名次。未公开、已退出或已删除的用户不得写入或出现在公开快照，也不得通过名次跳号间接影响公开结果。公开读取接口还必须再次限定只返回公开快照行，不能依赖前端隐藏。

## 排行榜统计口径

### 统一时间边界

- 今日：UTC+8 当日 00:00 至当前快照时间。
- 本周：UTC+8 周一 00:00 至当前快照时间。
- 本月：UTC+8 每月 1 日 00:00 至当前快照时间。
- 总累计：用户首次有效上传至当前。

服务端存储仍使用 UTC 时间戳；周期边界统一转换，不接收客户端自报时区。

### Token 总量

默认口径包含：

```text
total_tokens =
  input_tokens
  + output_tokens
  + cached_input_tokens
  + cache_creation_input_tokens
  + reasoning_output_tokens
```

保持现有 Token 归一化约定。Agent 分榜按 `source` 聚合。

### 模型标价折算

```text
estimated_list_price =
  input_tokens × input_price
  + output_tokens × output_price
  + cached_input_tokens × cache_read_price
  + cache_creation_input_tokens × cache_write_price
  + reasoning_output_tokens × reasoning/output price rule
```

- 由服务端使用仓库内统一定价表计算，不直接信任客户端传入的金额。
- 快照保存 `pricing_version` 和 `generated_at`。
- UI 名称使用“预估费用”或“模型标价折算”，不得称为“实际成本”。
- 明示：包月、赠送额度、地区折扣和供应商优惠不逐项折算，仅供统一口径比较。

### 实际总成本

定义：

```text
实际总成本 =
  API 实付
  + Token 套餐/充值
  + AI 产品订阅
  + 用户主动录入的其他 AI 花销
```

- 默认 `share_actual_cost = false`。
- 未公开时云端值必须为 `null`，不能用 `0` 表示。
- 用户打开“公开实际总成本”时，只上传按日汇总后的 `actual_cost_usd`，不上传套餐名、备注、商户、支付方式或单笔明细。
- 本地复用 Token Eyes 现有的币种与汇率换算能力转换为 USD；本地聚合记录保留换算日期、汇率版本和 `aggregation_version`，云端只接收聚合后的 `actual_cost_usd`。榜单按 USD 排序，再按查看者币种换算显示。
- 关闭公开后立即删除云端实际成本日汇总，并在下一次快照中置为 `null`。
- “实际成本榜”只纳入主动公开且值有效的用户。

## 云端数据合同

### 排行榜上传允许字段

| 字段 | 说明 |
|---|---|
| `user_id` | 服务端从已验证身份派生，不接受客户端指定 |
| `device_id` | 服务器签发的匿名设备 ID |
| `hour_start` | UTC 小时/半小时桶 |
| `source` | Codex、Claude Code、Cursor 等受控枚举 |
| `model` | 受限模型标识，用于定价与分榜 |
| Token 分类字段 | 输入、输出、缓存读写、推理及总量 |
| `pricing_version` | 定价口径版本；金额仍由服务端重算 |

幂等键继续使用：

```text
(user_id, device_id, hour_start, source, model)
```

同一键的更新以最新累计值覆盖，不重复累加。

### 单独的实际成本汇总

建议表：`tokentracker_actual_cost_daily`

| 字段 | 说明 |
|---|---|
| `user_id` | 认证用户 |
| `day` | UTC+8 日期 |
| `actual_cost_usd` | 当日实际总成本汇总 |
| `aggregation_version` | 本地成本聚合版本 |
| `updated_at` | 更新时间 |

唯一键：`(user_id, day)`。

### 云端不接收/不持久化

- 代码、提示词、回复、对话正文、文件内容、按键、截图。
- 项目/仓库名、本地路径、文件名、工作区名称。
- 自定义 Skill、MCP、插件、命令名称。
- 会话时长、消息数量、`conversation_count`。
- Codex 官方额度百分比、重置时间、重置券数量。
- 操作系统、用户名、用户时区。
- 实际成本的计划名称、备注、商户、支付记录和单笔明细。

应增加上传 DTO 白名单测试：出现任何未允许字段都拒绝或剥离，禁止直接透传本地对象。

## 资料、昵称和头像

- 初始昵称：OAuth 公开名称；缺失时使用用户可修改的随机昵称，不公开邮箱。
- 自定义昵称：2–30 个可见字符，服务端裁剪、规范化并做基本敏感词/控制字符过滤。
- 初始头像：OAuth 头像。
- 自定义头像：客户端裁剪到 256×256，去除 EXIF/ICC 等元数据，转换为 WebP/JPEG，最大 128 KB。
- 头像对象使用不可猜测路径；仅公开最终头像 URL，不公开原文件名。
- 更换头像后删除旧对象；退出排行或删除账户时删除头像。

## 排行榜界面

### 导航

- 排行榜入口始终可见。
- 未登录时显示小按钮“登录 · 参与排行”。
- 已登录时显示头像、昵称和本人排名摘要。

### 过滤与列表

- 周期：今日 / 本周 / 本月 / 总累计。
- 指标：Token / 预估费用 / 实际成本。
- Agent 分榜：全部、Codex、Claude Code、Cursor 等已有 source。
- 默认每页 20 人，服务端分页；公开接口返回快照生成时间。
- 本人不在当前页时，额外返回本人行并高亮。
- 快照过期时显示“数据更新于 …”，保留旧榜，不显示空榜。

### 金额术语

- `预估费用`：按模型公开价目表折算，不代表实际付款。
- `实际成本`：用户自报的 API、套餐、订阅和其他 AI 花销总和。
- 未公开实际成本显示 `—` 或“未公开”，不能显示为 0。

## 公平、防作弊与申诉

排行榜明确标注：

> 数据来自客户端本地日志的聚合统计，属于用户自报数据，仅供交流与娱乐，不作为官方账单或严肃比较依据。

服务端最低限度校验：

- JWT、设备令牌、用户/设备绑定。
- Token 字段必须为有限非负整数，时间桶不得超出允许范围。
- 单次批量上限、请求体上限、用户/设备/IP 频率限制。
- 幂等 upsert 和历史重放保护。
- 异常增长、未来时间、频繁换设备进入 `reviewing`，不直接删除历史。
- 管理端可屏蔽用户并重建快照。

第一版不限制“最高三台设备”，因为不能真正阻止伪造且会误伤真实多设备用户。后续可基于实际滥用情况增加设备上限。

申诉第一版可使用 GitHub Issue/邮件等已有渠道，不为此新建即时聊天系统。

## Codex 重置通知

### 目标

在不上传 Codex 账户数据、不读取 DOM/凭据的前提下，尽快提醒：

1. 正常 5 小时/7 天额度窗口即将重置。
2. 正常窗口已重置、额度已经恢复。
3. 在原计划时间之前发生的额度异常恢复或官方直接重置。
4. 账户出现可使用的重置券/临时额外额度（仅在可可靠解析时）。
5. OpenAI 发布与 Codex 重置、赠送额度或相关活动有关的公开消息。

### 数据来源

#### 账户级本地检测

复用现有 `src-tauri/src/codex_session.rs`：

- 用户在官方 `chatgpt.com` 页面登录。
- WebView 在同源会话内调用官方使用量接口。
- 只把白名单后的配额窗口数字返回 Rust。
- 不读取 `document.cookie`、localStorage、sessionStorage 或页面 DOM。
- 不记录原始响应，不上传 Access Token、Cookie、配额、重置时间。

该接口并非面向第三方承诺的公共稳定 API；必须保留结构漂移、重新认证和功能降级处理。

#### 全局公告

维护一个可缓存、带签名的静态公告 JSON，由 Token Eyes 客户端直接读取：

```json
{
  "id": "codex-reset-promo-2026-07",
  "type": "codex_reset_or_credit",
  "title": "Codex 可能提供新的重置/额度活动",
  "summary": "请前往 Codex 使用页面确认你的账户是否符合条件。",
  "official_url": "https://help.openai.com/...",
  "published_at": "2026-07-20T00:00:00Z",
  "expires_at": "2026-08-20T00:00:00Z",
  "signature": "..."
}
```

- 每条必须附 OpenAI 官方页面。
- 公告只能写“可能适用，请确认”，不能据此宣称某个用户已获得。
- 静态资源优先放现有网站/CDN，不占用每用户 InsForge Edge Function 调用。
- 客户端按 30 分钟缓存，离线继续显示已验证且未过期公告。

OpenAI 当前公开说明中，部分推广可能提供 Codex rate-limit reset、临时额外用量或 credits，用户在 Codex 使用摘要中查看和使用：

- https://help.openai.com/en/articles/20001271
- https://help.openai.com/en/articles/11369540

公开资料未提供第三方稳定的重置券 webhook/API。因此第一版不得通过 DOM 文案抓取“1 reset available”。

### 本地检测状态机

本地只保存脱敏状态：

```json
{
  "lastCheckedAt": "2026-07-20T08:00:00Z",
  "windows": {
    "rolling_5_hour": {
      "usedPercent": 37,
      "resetAt": "2026-07-20T10:30:00Z"
    },
    "rolling_weekly": {
      "usedPercent": 64,
      "resetAt": "2026-07-24T00:00:00Z"
    }
  },
  "seenEventIds": []
}
```

事件规则：

1. `reset_upcoming`：距 `resetAt` 30 分钟以内，只提醒一次。
2. `reset_completed`：跨过 `resetAt` 后使用率下降或新窗口开始。
3. `unexpected_quota_restore`：未到旧 `resetAt`，使用率显著下降（初始阈值 20 个百分点）且新响应有效。
4. `banked_reset_available`：只有官方响应出现经过明确白名单解析的可用数量字段时产生；结构未知时不猜测。
5. `official_reset_announcement`：来自签名公告源。

异常恢复需连续两次检查确认，避免接口暂时返回 0 或结构错误造成误报。

### 检查频率

- 应用/托盘启动后延迟 30 秒检查一次。
- 运行期间每 10 分钟检查一次账户配额；失败采用 10 分钟、30 分钟、1 小时退避。
- 窗口重新聚焦或用户手动刷新时，如果距上次检查超过 5 分钟可再检查。
- 公告源最多每 30 分钟请求一次，尊重缓存头。

这些请求只发生在本机与 OpenAI 官方页面/静态公告源之间，不进入排行榜上传链路。

### 提醒表现

默认不申请新的系统通知权限：

- 应用内顶部醒目横幅。
- 侧栏/Token 套餐入口红点。
- 托盘菜单显示“Codex 额度已恢复”状态。
- 相同事件只提醒一次，用户可标记已读。

可选的 Windows 系统通知必须由用户主动开启；第一版不是交付阻塞项。

横幅操作：

- `查看额度`：打开本地 Codex 配额区。
- `前往 Codex`：打开官方 Codex 使用页面。
- `查看官方说明`：仅公告事件显示，打开 `official_url`。

### 失败与降级

- 未登录 Codex：显示“连接 Codex 后可检测重置”，不反复弹错。
- 401/403：标记需要重新登录。
- 404/结构漂移：显示“暂时无法读取额度”，不产生恢复提醒。
- 网络错误：保留最后成功状态和时间，不把旧数据误判为新重置。
- 公告签名失败、过期或无官方 URL：拒绝显示。

## 本地优先与离线行为

- 未登录、认证过期、云端故障时，本地解析、成本、项目和 Codex 本地状态继续工作。
- 排行上传失败写回本地 pending 状态，按现有退避机制重试。
- 公开排行榜离线时显示最近缓存及更新时间。
- 云端数据不得覆盖本地明细或成为本地成本计算的唯一来源。

## 安全要求

- 所有排行写接口必须服务端验证身份；客户端不得指定 `user_id`。
- 设备令牌只存哈希，支持撤销和轮换。
- 公开排行榜只读取服务端生成的快照；快照生成与读取接口都必须限定 `leaderboard_public = true`。
- 昵称、头像、GitHub 链接等用户内容输出前转义并限制协议/域名。
- 实际成本明细永不上传；只允许数值汇总。
- Codex 会话模块维持现有官方域名白名单，不向远程页面暴露 Tauri IPC。
- 日志不得打印 Token、Cookie、JWT、原始 Codex 响应、成本备注或本地路径。

## 错误处理

| 场景 | 行为 |
|---|---|
| 登录成功、首次上传失败 | 保持登录和本地功能；显示等待同步 |
| 设备 ID 不可用 | 不生成浏览器临时设备；稍后重试 |
| 上传部分失败 | 保持 offset，幂等重试未完成部分 |
| 榜单 Cron 失败 | 保留上一快照，显示生成时间与“更新延迟” |
| 实际成本公开写入失败 | 开关回滚为关闭，云端不得出现半公开状态 |
| 关闭实际成本公开 | 先完成云端删除，再在 UI 确认关闭 |
| 退出排行清理失败 | 保持“删除中/重试”状态，不假装已删除 |
| Codex 结构漂移 | 停止通知并显示不可读取，不猜测 |

## 验证计划

### 登录与本地优先

1. 未登录、断网启动：全部本地页面可用，排行榜入口可见。
2. 未登录查看排行榜：无需 JWT，能读取公开快照。
3. 点击“登录 · 参与排行”：必须看到三条告知；成功后自动创建资料并首次上传。
4. 登录后断网：本地仪表盘仍展示本机数据，不出现云端加载门。
5. 登出：停止上传；重新登录可恢复。
6. 退出排行并删除：云端用量、快照、头像、成本汇总和设备令牌全部清理。

### 同步与调用量

1. 无 pending 数据时，打开/切换页面不得调用 ingest。
2. 打开排行榜距上次成功上传不足 30 分钟时不得重复上传。
3. 超过 30 分钟且有新数据时只上传增量。
4. 客户端上传后不得调用 leaderboard-refresh。
5. Cron 按今日/周 15 分钟、月 1 小时、总计 1 天运行。
6. 容量测试记录 Edge Function 调用、DB 扫描行、带宽和快照耗时。

### 隐私合同

1. 上传 DTO 快照测试只包含允许字段。
2. 注入 project name、path、skill、MCP、conversation_count、quota percent 等字段时必须被拒绝或剥离。
3. 项目队列永不进入云上传。
4. 实际成本明细/备注不进入网络请求。
5. Codex 配额、resetAt、重置券数量不进入 InsForge。

### 排行榜

1. UTC+8 跨日、跨周、跨月边界测试。
2. 同一设备同一桶重复上传覆盖而非累加。
3. 多设备同账号正确累加。
4. Token 总量符合现有归一化不变量。
5. 预估费用由服务端定价表计算，客户端伪造金额无效。
6. 实际成本未公开为 `null` 且不进入该榜；公开后按周期汇总。
7. 快照失败时保留旧榜并展示更新时间。
8. 未公开、已退出或已删除用户不进入公开快照；过滤后公开名次从 1 开始连续排列。

### Codex 重置通知

1. 距重置 30 分钟只提示一次。
2. 正常跨过 resetAt 后正确提示恢复。
3. 提前下降一次不提示，连续两次确认后提示异常恢复。
4. 401/403 提示重新登录；404/结构漂移不误报。
5. 不读取 DOM、Cookie、localStorage；测试继续验证初始化脚本禁用这些访问。
6. 公告签名错误、过期、缺少官方 URL 时拒绝显示。
7. 相同公告/重置事件重启应用后不重复提示。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 登录即参与被误解 | 登录按钮和弹窗明确写“参与排行”及上传范围 |
| Edge 调用增长 | 事件驱动上传；无 pending 不调用；榜单重算全局调度 |
| 全量聚合耗时/带宽 | SQL/RPC 内聚合、预计算快照、月/总降低频率 |
| 客户端伪造 | 自报定位、服务端校验、异常复核，不绑定高价值奖励 |
| 实际成本隐私 | 默认关闭，只上传日汇总，关闭即删 |
| OAuth 头像泄露真实身份 | 允许立即修改昵称/头像；登录弹窗说明公开资料 |
| Codex 私有接口变化 | 白名单解析、结构漂移降级、不得 DOM 抓取 |
| 重置券无法可靠检测 | 区分账户检测与全局公告，只对明确字段作肯定提醒 |
| 云故障影响主功能 | 本地仪表盘和本地数据始终独立可用 |

## 成功标准

1. 新用户无需登录即可完整使用 Token Eyes。
2. 排行榜无需登录即可查看，登录后无需第二次开关即可参与。
3. 用户界面不再出现“云同步”概念，本地仪表盘不因登录改变口径。
4. 3,000 DAU 下不产生按 15 分钟 × 用户数放大的排行榜刷新请求。
5. 公开榜具备今日/周/月/总及 Token/预估费用/实际成本口径。
6. 实际成本只有主动勾选后才公开，关闭后云端汇总被删除。
7. 网络上传严格遵守数据字典，不包含用户禁止上传的内容。
8. Codex 正常重置和异常恢复能在本机醒目提醒；重置券检测不作超出官方能力的承诺。
