# 价值对比 / 实时会话性能、数据与状态修正设计

## 目标

在不改动已验收整体视觉方向的前提下，消除两个分析页反复挂载时的阻断式重载，补回已经存在但未进入价值模型的套餐成本与仅支出来源，并把 Agent 徽标恢复为真实运行状态。

## 方案

### 页面切换

在 dashboard API 层增加按 `range + month` 区分的内存安全聚合缓存。页面挂载时先同步读取缓存作为初值，同时后台请求最新数据；请求期间保留旧数据。手动刷新绕过缓存。缓存只保存服务端已经脱敏的聚合响应，不持久化到磁盘，也不保存正文或凭据。

选择新的范围或月份时，同样采用已有数据持续显示、后台替换的方式，避免整页闪回加载态。失败时保留上一次成功结果并显示非阻断错误。

### 真实成本与月份回退

价值模型继续使用真实支出记录；同时把 Token Plan 中用户明确配置的订阅金额作为套餐成本证据。若同一来源已有支出记录，配置金额不再叠加，避免重复计费。配置中的确切零值保持零值。

来源列表由“有用量的来源”扩展为“有用量或有真实支出的来源”。每个来源独立寻找所选月及更早月份的最近真实记录，保留来源月份标记；不使用公开套餐价格，不跨来源复制数据，不把未知改成零。

仍然缺少现金账单时不伪造金额，而是提供直接进入订阅账单录入页的按钮；缺少定价时进入成本设置页。顶部状态减少重复死文案，保留一次证据边界说明。

### Agent 运行状态

生命周期读取结果 `running` 显示“运行中”；其他已检测来源统一显示“空闲”。“近期有历史”仍可作为详情证据，但不再占用运行状态徽标。活跃 Agent 数只统计 `running` 的唯一来源。

## 失败处理与隐私

WorkBuddy 或其他 provider 读取失败只影响该来源，缓存的聚合页面保持可用；API 继续返回 200。任何缓存、测试和截图不得包含会话正文、路径、账号标识、Cookie、Token、密钥或提示词。

## 验证

先用失败测试锁定缓存、状态、套餐成本去重、仅支出来源和设置路由；实现后跑聚焦测试、类型检查、dashboard 构建、全仓测试与本地 CI。最终从新 EXE 做两次独立安装验收，并把每轮当前页面与参考图合成同屏对照。
