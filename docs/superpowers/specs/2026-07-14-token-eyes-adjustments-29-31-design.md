## 3. 根因与设计决策

### 3.1 中文单位裁切根因

概览使用 `Counter` 把显示字符串逐字符拆分。数字字符可使用约 `0.88ch` 的窄宽度，但中文“万/亿”是全角字符；当前调用把数字宽度覆盖到所有静态字符，且滚动容器带 `overflow: hidden`，最终把末尾中文单位裁掉。修复应区分数字与静态字符宽度，并给整个计数器提供可收缩但不裁字的布局边界。

### 3.2 模型圆环图

使用已有 `modelBreakdown` 数据，不重复请求接口。纯函数按规范化模型名跨供应商聚合 Token，排序后保留前 5 个，其余合并为“其他”。组件使用 SVG 圆环和同卡片图例：圆环负责比例感知，图例负责精确值，中心显示当前范围模型总消耗。

### 3.3 视觉论点

- 视觉论点：冷白雾面工作台，内容浮层轻微抬升，绿色只用于选中、成功和关键操作。
- 内容计划：侧栏导航 → 主工作面板 → 关键数据卡 → 趋势/分布 → 明细。
- 交互论点：选中项用浅色底、内描边和短阴影；可交互卡片悬停上移 1px；数据图进入时使用 180–240ms 的克制绘制动画。

不采用整页渐变、厚重玻璃拟态或把每个文本块都做成卡片。Cockpit 的价值是层级与操作密度，不是照搬颜色和组件数量。

## 4. 对抗性验收

- `9999`、`1万`、`33.76亿`、负值和无数据不会被裁切。
- 模型同名但来源不同会合并；超过 5 个模型产生“其他”；总占比与总 Token 保持一致。
- 圆环图在 0 条、1 条、6 条以上模型时均可读，图例不会把左栏撑破。
- 明暗主题下卡片边界都可辨识；去掉阴影后仍能依靠背景层级和间距理解结构。
- 所有新增文案进入 copy registry，不在 JSX 中硬编码。

## 5. 汇报规则

每完成一个可独立验证的事项，更新本文状态并汇报完成项、验证结果、未完成项和下一步。最终生成新的仓库内 NSIS 安装包，由用户覆盖安装验证。
