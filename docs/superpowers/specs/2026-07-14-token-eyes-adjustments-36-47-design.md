## 3. 数据与交互约束

### 3.1 花销分组

- `otherAiSpendGroups` 增加可空 `parent_id`；父组自身不能再有父组，确保最大深度为两级。
- 删除父组时，其子组与记录安全移动到“未分组”，不级联删除花销。
- 拖拽使用明确的组和记录目标标识；投放到组标题表示移动到该组末尾，投放到记录表示插入指定位置。
- 编辑器只在被点击记录下方渲染，不使用全局顶部编辑器。

### 3.2 供应商 API

- 保留测试连接、刷新、编辑、删除四项操作，不因紧凑布局删除已有功能。
- 阿里云继续使用已经成功的 RAM 财务权限和余额读取。只修复成功结果之后又执行通用字段路径解析所产生的多余错误。
- 成功余额与错误状态互斥；不能同时显示“已连接”和“响应格式错误”。

### 3.3 数据目录和统计

- 安装目录只能作为发现入口，必须进一步解析到实际日志或数据库目录。
- 未发现可读 Token 数据时显示精确状态，不把“已安装”冒充“可统计”。
- 数据目录排序只属于展示偏好，不改变扫描优先级或解析结果。

### 3.4 UI 原则

视觉主张：冷静、紧凑、可信的运营台账；用网格、留白和状态对齐建立层级，不继续堆叠同权重卡片。

内容结构：一级区块负责分类和总览，二级列表负责快速扫描，编辑与错误仅在对应条目附近出现。

交互主张：折叠状态稳定、拖拽目标明确、原位编辑不打断滚动位置；所有动画只用于说明展开、投放和状态变化。
