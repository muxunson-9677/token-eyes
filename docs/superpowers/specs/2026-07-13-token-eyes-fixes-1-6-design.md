## 4. 子项目 A：桌面窗口可靠性与可见品牌

### 目标

Token Eyes 始终保持单实例；用户再次点击 Token Eyes 快捷方式时，已有主窗口必须从隐藏或最小化状态恢复、前置并获得焦点；所有 Token Eyes 用户可见表面统一显示 `Token Eyes`。

### 设计

- 单实例插件在应用初始化最早阶段注册。
- 第二实例只向第一实例发送唤醒请求，随后退出，不创建第二个主窗口。
- 唤醒操作按固定顺序执行：取消最小化、显示窗口、设置标题、请求焦点。
- 原生端维护唯一显示名常量 `Token Eyes`，用于主窗口标题、托盘提示和运行时纠偏。
- 前端入口同步设置 `document.title = "Token Eyes"`，避免页面标题覆盖原生标题。
- Tauri 产品名、窗口标题、安装器元数据和本项目生成的快捷方式名称保持一致。
- 只统一 Token Eyes 的用户可见表面，不重命名无用户影响的历史内部标识，不触碰 CC Switch。

### 验收标准

- 自动化测试证明重复启动请求只调用一次主窗口恢复流程。
- 主窗口处于正常、最小化、隐藏三种状态时，重复启动都恢复同一个窗口。
- 连续触发 20 次启动请求后仍只有一个 Token Eyes 主窗口实例。
- 主窗口标题、任务栏标题、托盘提示和安装器产品名均为 `Token Eyes`。
- Dashboard、Rust 单元测试和仓库内 Windows 构建通过。

## 5. 子项目 B：Codex 官方账号授权状态机

### 目标

不再依赖独立内嵌 WebView 登录态冒充系统浏览器登录；改用 OpenAI 官方 Codex app-server 在系统默认浏览器授权。Token Eyes 不再创建或遗留自有登录窗口，额度同步失败不得阻止账号授权完成。

### 方案比较

1. **推荐：官方系统浏览器授权交接。** 调用官方支持的浏览器登录流程，通过回调结果确认授权；安全边界清楚，可复用浏览器已有登录状态。
2. 保留独立 WebView。实现成本较低，但浏览器 Cookie 天然不共享，不能满足原始诉求。
3. 读取或复制浏览器 Cookie。安全风险高、兼容性差，不采用。

### 设计

- 将状态拆成 `authorization` 和 `quota_sync` 两条独立状态链。
- 授权链只负责：启动授权、等待官方通知、验证账号、记录非敏感会话引用、完成 Token Eyes 内连接状态。
- 额度链在授权完成后后台运行；成功更新套餐，失败在主界面显示可重试错误。
- 授权成功后立即返回 `authorized`，不等待额度接口；额度使用独立原生命令同步。
- 系统浏览器标签页不是 Token Eyes 创建的 WebView，Token Eyes 无权强制关闭；是否自动关闭由浏览器和 OpenAI 官方成功页决定，不影响 Token Eyes 完成连接。
- 不在前端、日志或本地普通配置中保存 Cookie、Bearer Token 或账号密码。
- 如果 OpenAI 未向第三方应用提供适用的授权交接能力，界面必须明确说明能力限制，不能退回到复制 Cookie。

### 验收标准

- 已登录浏览器场景不会要求用户在 Token Eyes 独立 WebView 再登录一次。
- 授权成功、额度接口成功：Token Eyes 完成连接并更新套餐。
- 授权成功、额度接口失败：Token Eyes 仍保存授权，主界面显示同步失败并允许原生手动重试。
- 用户取消授权：待授权绑定可安全清理，原套餐数据不被覆盖。
- 超时、错误和重复回调均有自动测试，且不泄露凭据。

## 6. 子项目 C：其他 AI 花销进入真实成本统计

### 目标

用户可以记录账号被封、历史充值或其他无法自动采集的 AI 花销，并让这些记录真实进入成本统计。

### 设计

- 继续复用 `spendRecords` 持久化，来源固定为 `other_ai`，周期为一次性花销。
- 支持名称、发生日期、金额、币种和备注的新增、编辑、删除。
- `other_ai` 进入所选月份总成本、累计成本、财务汇总和按来源后端结果。
- 它不产生 Token，不进入 Token 趋势图或 Token 排行。
- 使用统计总览默认计入 `other_ai`；筛选到单个服务或 Agent 时只显示该服务成本；即使没有启用 Token 服务，仍可查询 `other_ai` 成本。
- 汇率转换继续使用项目统一汇率设置，不增加第二套换算逻辑。
- “较上月新增/减少”属于原始事项 9，不在本次 1–6 修复阶段冒充完成。

### 验收标准

- 新增一笔 CNY 或 USD 花销后，本月和累计成本按统一汇率更新。
- 编辑日期或金额后，原月份与新月份统计正确回算。
- 删除记录后所有成本汇总同步减少。
- Token 总量不受影响。
- CRUD、汇率、月份边界、一次性花销日期桶、UTC+8 跨日和失败反馈均有自动测试。

## 7. 子项目 D：供应商 API 简化配置与真实财务能力

### 目标

用户只填写供应商、API 端点和 API Key；认证方式、查询接口、字段解析等复杂配置由 Token Eyes 的供应商适配器承担。

### 方案比较

1. **推荐：供应商专属财务适配器。** 每个适配器声明它真实支持的余额、套餐额度、月花销和累计充值能力，用户界面保持简单。
2. 通用 URL 加字段路径。扩展性强，但把供应商差异转嫁给用户，已经被实际使用证明不可接受。
3. 假设所有供应商都有统一财务接口。与现实不符，不采用。

### 设计

- 基础表单只保留：名称/供应商、API 模式、API 端点、API Key、启用状态。
- 已知供应商由适配器补齐请求方法、认证方案、财务端点和解析器；高级字段默认折叠，仅供未收录的自定义财务接口使用。
- 只有精确的官方供应商 ID/别名使用内置适配器；任何非空未知 ID 保持自定义，防止名称或域名误识别代理服务。
- DeepSeek 使用公开余额接口，仅展示接口真实提供的余额；月花销和累计花销标记为“不支持自动查询”。
- 智谱普通模型 API 没有可验证的公开现金余额、月花销或累计充值接口；Coding Plan `/quota/limit` 属于 Token 套餐额度，不得映射成现金余额，并在读取密钥和发起请求前停止。
- 明确区分四类数据：模型 API 可调用、现金余额、套餐 Token 额度、月度/累计花销。
- 每个供应商在界面展示能力矩阵；没有公开财务接口的数据标记为“不支持自动查询”，不显示伪造的零值。
- API Key 继续只保存在系统凭据存储引用中，接口和日志不得回显明文。

### 验收标准

- 智谱模型 API 和旧 Coding Plan quota 配置都不会冒充现金余额；旧配置不读取密钥、不发起财务请求，并引导至 Token 套餐设置。
- DeepSeek 只填基础字段即可规范化到公开余额接口，并正确解析响应中的余额和币种。
- 缺失的月花销或累计充值显示“不支持”，不显示 `0` 或误用 Token 额度。
- 401、403、429、超时、HTML 登录页和响应结构变化均返回可理解错误。
- 明确选择自定义或使用未知自定义 ID 时，不会被名称中的 DeepSeek/智谱字样误套官方适配器；官方智谱 quota URL 仍按套餐端点拦截。
- 每个已知适配器有响应 fixture 测试；真实账号验证作为人工验收项，不把 fixture 通过等同于真实连接成功。
