# 排行榜页 UI 对齐与交互规格

## 目标

在 Token Eyes 0.54.38 当前实现基础上，按用户提供的参考图优化排行榜页。交付以真实数据预览中的实际体验为准，不以自动化测试通过作为完成标准。

## 固定范围

### 允许修改

1. 全局应用外壳中导航区与内容区的边线、圆角和对齐基准。
2. 全局侧边导航的图标与标签颜色；现有选中、按下、展开和跳转行为保持不变。
3. 排行榜页右上“账户、退出登录、规则说明”的视觉按钮形态。
4. 排行榜页标题、三张统计卡、同步提示、筛选器、榜单表格和分页的视觉结构与间距。

### 必须保留

- Token Eyes 原有 Logo、文字内容、榜单数据、筛选逻辑、分页逻辑和榜单条目交互。
- 已有导航点击、按下、展开、焦点和键盘可用性。
- 非排行榜页面各自的内容布局；全局变化只限于共享导航/内容外壳规范。

## 视觉方案

### 视觉主张

这是一个平静而可扫描的数据工作区：卡片边线建立秩序，导航颜色只用于定位功能，榜单表格是视觉重心。

### 全局外壳

- 左侧导航与右侧主内容以同一顶部、底部和边线基准构成一组并列区域。
- 两个区域使用一致的小圆角、细描边和低层级阴影；不能出现一侧直角、另一侧圆角。
- 共享外壳规则应在所有 AppLayout 页面生效，但不得改变页面内部内容排序。
- 窄窗口下边线与圆角仍完整，不能裁切导航文字、按钮或焦点环。

### 全局导航颜色

- 每个一级功能使用稳定的识别色（概览蓝、排行榜绿、重置记录橙、组件紫、使用与成本琥珀、设置灰蓝）。
- 图标和功能名称使用同一识别色；子页面继承所属一级模块的颜色。
- 当前选中项仍沿用已有背景、按压和动效；颜色规则不能覆盖 `aria-current` 的按下效果。
- 悬停仅增强可读性，不增加新的跳动或装饰性动效。

### 排行榜内容

1. 顶部一行：左侧“排行榜”和更新时间，右侧三个等高操作按钮。
2. 统计区：三张等高卡片、统一小圆角和内边距；人数、Token、花销依次使用蓝、紫、橙图标和辅助增量颜色。
3. 同步提示：独立的低对比提示条，完整位于内容区域内。
4. 筛选区：时间、指标和来源筛选保持现有功能，所有控件有明确可点击边界。
5. 榜单区：表头、当前用户行、模型占比色条、数值列和分页处于同一外层表面内；数值列右对齐，长名称不挤压百分比或操作入口。

### 顶部操作按钮

- 账户、退出登录、规则说明为紧凑按钮，不是裸文字链接。
- 三者等高，具有边框、小圆角、水平内边距、悬停和键盘焦点反馈。
- 保持各自原有点击行为；在窄宽度下允许换行，不允许文字跑出内容区。

## 交互原则

- 现有切换筛选、分页、打开账户、退出登录、打开规则和查看榜单资料的行为不改。
- 导航按下状态保留；新增颜色仅帮助扫描和定位。
- 新按钮和现有筛选均保留可见焦点，支持键盘操作。

## 实施顺序

1. 为共享导航项补充稳定的功能标识，并用全局样式应用颜色，不改事件和状态逻辑。
2. 统一 AppLayout 导航区与内容区的外框几何关系。
3. 将排行榜顶部操作项改为真正的按钮，并为页面内容建立参考图对应的纵向节奏。
4. 用真实数据预览逐项检查，修复布局问题后再交付链接。

## 真实体验验收

1. 打开 `http://localhost:5173/leaderboard?native_preview=1`，确认页面是最新资源且能访问。
2. 从顶部滚动到底部，检查导航和内容的边线是否对齐，所有卡片圆角是否一致。
3. 逐项查看导航颜色、选中按下效果、子页面颜色继承和键盘焦点。
4. 检查三枚顶部操作按钮均有明确按钮形态，文字不溢出。
5. 检查统计卡、同步提示、筛选器、榜单表格和分页均在自身容器内；无空洞、重叠、直角或横向裁切。
6. 使用真实榜单数据检查长名称、模型标签、色条、数值列和滚动/分页。

## 不纳入本次范围

- 不更换 Logo。
- 不重做榜单数据结构、接口、登录流程或规则页内容。
- 不引入仅为装饰而存在的新动效。
