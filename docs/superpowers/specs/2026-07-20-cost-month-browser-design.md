# 成本月度查看功能设计

## 目标

在“当前成本累积”区域增加独立月份选择能力。用户可以查看任意历史自然月的成本，并保持当前月、历史月、环比、其他 AI 自定义花销和累计金额使用一致且可复核的原始账目口径。

本功能只影响成本累积区域，不改变使用趋势、Token 服务列表或页面全局日期筛选。

## 界面与交互

- 在成本累积标题区域增加“上一月 / 月份 / 下一月”控制器。
- 默认选择用户本地时区的当前月份。
- 当前月份禁用“下一月”，不允许选择未来月份。
- 点击月份可以直接选择年份和月份，以便跳转较早历史。
- 顶部卡片显示明确月份，例如“2025 年 6 月 API 成本”“2025 年 6 月套餐成本”“2025 年 6 月总成本”。
- “总累计”始终表示全部历史，不随月份切换。
- 其他 AI 花销分组卡片显示：
  - 所选月份；
  - 所选年份 1 月 1 日至所选月份结束的累计；
  - 全部历史总累计。
- 当前月份的年度累计截至今天；历史月份的年度累计截至所选月份最后一天。
- 月份切换期间显示加载状态，不能把旧月份金额暂时冒充为新月份数据。

## 数据来源与计算

所有金额由后端基于原始账目计算，前端只传递月份范围并展示结果。

所选月总成本恒等于：

`API / Token 实际消耗成本 + Token 套餐/订阅成本 + 其他 AI 自定义花销`

### API / Token 实际消耗

读取所选日期范围内的真实使用记录，并按现有模型定价规则核算。Provider API 余额、剩余额度和 Token 套餐额度属于账户状态，不作为成本重复相加。

### Token 套餐/订阅

- 月付记录在每个有效自然月计入月费。
- 年付记录按 `年费 ÷ 12` 分摊到每个有效自然月。
- 一次性记录只计入开始日期所在月份。

### 其他 AI 自定义花销

使用与套餐/订阅相同的月付、年付和一次性归属规则，并按用户创建的分组分别汇总。其他 AI 金额只计入一次：既进入其他 AI 分组，又作为总成本的一个组成项，但不得再次混入套餐成本。

### 日期范围

- 当前月本期：本月 1 日至今天。
- 当前月上期：上月 1 日至上月同日；该日期不存在时取上月最后一天。
- 历史月本期：所选月份完整自然月。
- 历史月上期：前一个完整自然月。
- 年度累计：所选年份 1 月 1 日至本期结束日期。
- 总累计：全部历史原始账目。
- 所有日期边界使用用户本地时区。

### 环比

API、套餐和总成本分别用各自原始账目计算，公式固定为：

`(本期 - 上期) ÷ 上期 × 100%`

必须分别处理增加、减少、持平和上期为零无基数。当前月使用“本月至今 vs 上月同期”；历史月使用“完整所选月 vs 完整前一个月”。

## 数据流与边界

- `SpendCostPage` 持有所选月份 `YYYY-MM`，默认本地当前月。
- 独立日期辅助函数根据所选月份、用户时区和当前日期生成本期、上期和年度范围。
- `useCostAccumulation` 接收这些范围，并分别请求本期、上期、年度分组和累计数据。
- 现有 spend timeseries 继续作为 API、套餐、其他 AI 和总成本的统一核算入口。
- 其他 AI 分组汇总改为尊重传入的所选月份和年度截止日期，不再硬编码为系统当前月。
- 页面全局来源可见性规则保持不变；月份控制器不修改全局筛选状态。
- 快速连续切换时，旧请求结果不得覆盖最新月份。

## 异常与空数据

- 所选月份确实没有账目时显示真实 `USD 0.00 / CNY 0.00`。
- 请求失败或字段缺失时显示“—”和错误提示，不能伪装成零成本。
- 任一组成成本不可用时，不用其他来源金额冒充，总成本也标记为不可用。
- 加载失败时保留用户选择的月份并明确显示失败状态。
- 总累计的读取和展示不因月份切换而改变。

## 测试与验收

先记录失败基线，再编写失败测试，最后实施最小修复。自动化覆盖：

- 当前月“本月至今 vs 上月同期”；
- 历史月“完整月份 vs 前一个完整月份”；
- 1 月跨年到上一年 12 月；
- 月末、二月和闰年边界；
- 月付、年付分摊和一次性花销归属；
- USD/CNY 换算；
- 其他 AI 分组的所选月、所选年截至月末和总累计；
- 总成本严格等于 API/Token、套餐和其他 AI 三项之和；
- 其他 AI 不漏算且不重复计算；
- 环比增加、减少、持平和上期无基数；
- 月份标题、上一月/下一月、直接选择月份和未来月份禁用；
- 快速切换时旧响应不能覆盖新月份；
- 切换月份后总累计不变；
- 无账目显示真实零，接口失败显示不可用。

本轮只运行 Node API 测试、React 组件/Hook 测试和开发调用窗口验证。不构建或安装新的安装版；所有需求完成后再统一执行正式安装版验收。
