## 54. 同一供应商多账号独立检测

继续使用 OpenAI 官方 `codex app-server`，但每个 Token 套餐只允许绑定一个明确的 `account_binding_id`。每个绑定对应项目应用数据中的独立 `CODEX_HOME`，不得按供应商寻找或继承其他套餐的会话。新增账号从空白绑定开始，授权完成后才允许保存为已连接套餐。账号记录保存脱敏显示信息、备注、会话引用与额度快照，不提供切号启动功能。

## 55. 月度环比颜色统一

环比上升与下降均使用产品统一绿色，避免把“成本新增”误表达为系统错误。无上月数据或持平时使用中性灰色。

## 56. 使用趋势填满卡片

图表区域采用可用高度驱动，不通过增加装饰或空模块填补。折线绘图区、坐标轴和空数据状态共同扩展，Token 服务列表高度变化时布局仍保持对齐。

## 57. 套餐备注跨页面展示

备注是同供应商多账号的主要人工识别信息。设置列表在套餐名下显示备注；使用统计的 Token 服务卡片在供应商/套餐标题下显示备注。备注不参与排序和账号绑定。

## 58. 官方自动核价为主、人工核价为辅

模型定价表为待核价和运行中新发现的模型提供“自动核价”按钮。自动核价流程：

1. 根据模型 ID 和供应商选择官方定价适配器。
2. 只请求白名单中的官方 HTTPS 域名；不把用户凭证发送到定价页面。
3. 解析官方可机器识别的定价数据，并要求模型 ID、输入/输出价格和计价单位一致。
4. 保存价格、官方来源 URL、核验时间和核验状态，再让成本计算使用该规则。
5. 官方页面不可达、页面结构变化、模型未列出或官方没有公开定价时，显示具体失败原因，不用第三方价格冒充官方价格。
6. 自动核价失败后允许打开原位人工表单，人工填写价格与来源；人工规则明确标记为“人工核价”，以后仍可再次执行官方核价覆盖。

内置目录中的官方已核验快照可用于离线展示，但用户点击“自动核价”时必须重新访问官方来源进行校验，不能只把静态内置值改成“已核价”。

## 59. Trae/CodeBuddy Token 数据与连接状态

数据源按可信度合并：本地会话日志中的精确 Token 字段优先；官方账号授权接口返回的精确用量其次。安装目录只用于定位真实 Roaming/用户数据目录。目录可识别但数据库加密或没有 Token 字段时显示绿色“已连接”，并附“暂无可统计 Token 字段”，不再笼统显示未检测到，也不按字符数或会话数估算 Token。

## 60. Token Eyes 橙黄色项目图标

在 `src-tauri/icons/token-eyes-orange/` 保存项目内源图副本和生成图标。Tauri 窗口、EXE、NSIS 安装/卸载、托盘及前端 favicon 使用同一套生成资产。外部源图保持只读。

## 对抗性验收

1. 每项先建立失败测试或可复现诊断，再改生产实现。
2. 多账号测试必须真实覆盖两个独立绑定 ID、两个独立额度和不同备注，不能只验证新增按钮。
3. 自动核价测试覆盖官方成功、模型不匹配、域名拒绝、页面结构变化和人工回退。
4. Trae/CodeBuddy 只用明确 Token 字段；无字段时验证不会产生虚假用量。
5. 图标构建后检查 EXE/NSIS 资源路径和生成文件，不修改外部源图。
6. 最终执行聚焦测试、Dashboard 全量测试、Node 测试、Rust 测试、生产构建和 Tauri NSIS 构建；逐项汇报完成、官方能力限制和未完成内容。
