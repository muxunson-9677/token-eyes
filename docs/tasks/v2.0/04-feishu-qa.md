# 04 - 飞书同步与总验收

## 中文简述

本工单负责把 2.0 长任务同步到飞书进度表，并在所有工单完成后做最终对抗性验收。它必须最后串行执行。

## 第一性原理执行规则

- 飞书进度表的作用是让用户知道任务在哪、谁负责、是否完成。
- 不把未完成任务标记为完成。
- 不只信 subagent 汇报，必须读取文件、运行验证、检查结果。
- 发现问题必须回到对应工单修复。
- 所有审查记录必须可追踪。

## 新增任务要求

- 飞书进度表新增 `2.0` 批次。
- 新增 4 个长任务行：`01 产品与前端改造`、`02 数据与环境检测`、`03 成本累积与计费`、`04 飞书同步与总验收`。
- 每行包含：版本、编号、模块、任务名称、状态、负责人、依赖、验收标准、审查记录、备注。
- 初始状态为 `待派单`。
- subagent 开始后更新为 `执行中`。
- 工单通过对抗性审查后更新为 `待用户验收` 或 `已完成`。
- 最终验收必须覆盖 CC Switch UI 对齐、请求日志分页、真实项目路径、Agent 环境检测、API 计费、订阅记录命名。

## 飞书字段建议

```text
版本：2.0
编号：01 / 02 / 03 / 04
模块：产品前端 / 数据环境 / 成本计费 / 飞书验收
任务名称：
状态：待派单 / 执行中 / 待用户验收 / 已完成 / 阻塞
负责人：
依赖：
验收标准：
审查记录：
备注：
```

## 总验收清单

- 概览页热力图已移除。
- 项目用量能展示真实项目路径、Token、成本。
- 使用统计 UI 对齐 CC Switch。
- 成本卡片尺寸已缩小。
- 使用趋势图右侧完整展开。
- 请求日志每页 10 条，并支持页码跳转。
- 设置页 Agent 数据目录卡片有环境检测按钮。
- 环境检测能区分 Win / WSL Ubuntu / 未检测到。
- 成本累积包含 Token 套餐、API 计费、订阅记录。
- `新增订阅记录` 已全部改名为 `订阅记录`。
- 飞书已有 2.0 批次和 4 个长任务行。

## 对抗性审查记录

执行者完成后必须填写：

```text
审查轮次：
发现问题：
对应工单：
修复动作：
复查结果：
最终结论：
```

如果 `发现问题` 不为空，必须回到对应工单修复，再重新执行总验收。只有最终结论为“无遗留问题”时才能结束。

## 完成情况汇报

完成后回复：

- 飞书新增了哪些 2.0 行。
- 每个长任务当前状态。
- 最终验收跑了哪些检查。
- 对抗性审查做了几轮。
- 是否还有阻塞项。
