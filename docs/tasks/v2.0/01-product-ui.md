# 01 - 产品与前端改造

## 中文简述

本工单负责把 2.0 的页面目录和前端展示结构定下来，并把使用统计 UI 向 CC Switch 对齐。它是后续所有 2.0 工单的前置串行任务。

## 第一性原理执行规则

- 先确认用户要看的是“真实消耗、项目消耗、成本变化”，不是装饰性图表。
- 每个模块必须回答：展示什么、用户为什么需要、点击后发生什么。
- 不保留没有明确决策价值的模块。
- 不改和本工单无关的后端同步逻辑。
- 所有页面命名和位置以后续正式产品为准，不为虚拟数据临时命名。

## 新增任务要求

- 移除概览页热力图。
- 保留并强化概览页 `项目用量`。
- 支出页拆成两个二级功能：`使用统计`、`成本累积`。
- `使用统计` 中的 `真实消耗 Tokens`、`新增输入`、`Output`、`创建`、`命中`、`总请求数`、`总成本`、`缓存命中率` UI 对齐 CC Switch。
- `本月 API 成本`、`本月订阅成本`、`本月总成本`、`累计总成本` 卡片缩小，不要占据过大空间。
- `使用趋势` 图表右侧必须完整拓展，参考 CC Switch 的宽图、双轴、tooltip、图例布局。
- `请求日志` 默认每页展示 10 条。
- `请求日志` 使用页码跳转形式，不使用简单“展开全部”。
- `新增订阅记录` 改名为 `订阅记录`。
- `订阅记录` 入口放在 `支出 > 成本累积`。

## 页面目录

```text
概览
- 核心指标
- 使用趋势
- Agent 分布
- 项目用量
- 每日明细

支出
- 使用统计
  - 真实消耗 Tokens
  - 成本卡片
  - 使用趋势
  - Provider 统计
  - 模型统计
  - 请求日志分页
- 成本累积
  - Token 套餐
  - API 计费
  - 订阅记录

设置
- 数据目录
- Agent 环境检测入口
- 同步状态
- 展示开关
- 数据接入说明
```

## 验收标准

- 概览页不再出现热力图。
- 支出页出现 `使用统计` / `成本累积` 二级切换。
- 使用统计顶部信息和 CC Switch 截图的层级、密度、布局方向一致。
- 成本卡片尺寸明显小于当前大卡片。
- 使用趋势图右侧不留空、不截断、不挤压。
- 请求日志每页 10 条，并出现页码跳转。
- 页面上不再出现 `新增订阅记录`，统一显示为 `订阅记录`。

## 对抗性审查记录

执行者完成后必须填写：

```text
审查轮次：
发现问题：
修复动作：
复查结果：
最终结论：
```

如果 `发现问题` 不为空，必须先修复，再新增一轮审查记录。只有最终结论为“无遗留问题”时才能结束。

- 对抗性审查做了几轮，最后结论是什么。
