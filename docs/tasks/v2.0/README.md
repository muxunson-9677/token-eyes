# Token Eyes 2.0 长任务总入口

## 文档目录

- `README.md`：总入口，说明文档清单、工单顺序、串并行关系。
- `01-product-ui.md`：产品与前端改造，梳理页面目录、CC Switch UI 对齐、请求日志分页。
- `02-data-env.md`：数据与环境检测，梳理真实项目路径、请求日志分页接口、Agent Win/WSL Ubuntu 检测。
- `03-cost-billing.md`：成本累积与计费，梳理 Token 套餐、API 计费、订阅记录。
- `04-feishu-qa.md`：飞书同步与总验收，梳理 2.0 进度表新增、对抗性审查、最终验收。

## 工单执行顺序

先执行：

- `01-product-ui.md`：串行。先固定产品目录、页面结构和前端视觉基准，后续工单不得绕开这里定义的结构。

再执行：

- `02-data-env.md`：并行。负责真实项目路径、请求日志分页接口、Agent 环境检测。
- `03-cost-billing.md`：并行。负责成本累积、API 计费、Token 套餐、订阅记录。

最后执行：

- `04-feishu-qa.md`：串行。必须等 `01`、`02`、`03` 全部完成并通过各自对抗性审查后再执行。

## 统一执行规则

每个工单执行前必须先按第一性原理确认：

- 用户真正要解决的问题是什么。
- 数据从哪里来，最终展示给谁看。
- 用户点击后发生什么。
- 哪些内容属于本工单，哪些不属于本工单。
- 有没有更小、更直接的实现路径。

每个工单完成后必须做对抗性审查：

- 站在反对者角度找遗漏、错位、假接入、视觉偏差、验收缺口。
- 发现问题必须先修复。
- 修复后重新做对抗性审查。
- 审查无问题后，才能汇报工单完成情况。
