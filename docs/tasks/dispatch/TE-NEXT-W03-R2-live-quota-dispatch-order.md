# TE-NEXT-W03-R2：小米 MiMo 实时额度同步调度顺序

## 2026-06-25 更新说明

本文件中的“控制台授权会话”方向只保留为底层能力参考，不再代表最终 UI 结构。

用户已确认新的产品结构：

- 不要在 Token 套餐主界面单独放“小米 MiMo 控制台连接”卡片。
- 小米 MiMo 应作为 `新增套餐` 表单中的 `服务商` 选项。
- 用户选择服务商和套餐后，在同一条套餐记录内选择检测方式。
- 检测方式必须支持“官网账号登录检测”和“自定义 API 检测”两个并存方案。

后续执行以 `docs/tasks/dispatch/TE-NEXT-W03-R3-token-plan-auth-methods-dispatch.md` 为准。

## 用户需求基线

本轮工单必须以用户原始需求为准：

- 用户不是要手动记录额度。
- 用户要在 Token Eyes 内实时看到小米 MiMo Token Plan 的已用额度、剩余额度、到期时间和同步状态。
- 用户授权方式可以是登录官网账号，也可以是用户显式授权后的会话读取。
- 手动字段只能作为同步失败时的兜底，不允许作为主路径或验收替代。

如果执行过程中发现没有公开官方 API，不允许把需求降级为“手动维护”。正确动作是继续走“用户授权登录控制台后，从控制台真实数据源同步”的路径；只有控制台数据源也无法稳定读取时，才能把工单标记为阻塞，并写清楚阻塞证据。

## 官方依据

- 小米 MiMo 功能更新说明 Token Plan 支持“用量查询”，并说明控制台可实时查看、导出 Token 消耗和调用次数：https://mimo.mi.com/docs/zh-CN/updates/feature
- 小米 MiMo 文档入口和控制台入口：https://mimo.mi.com/docs/zh-CN/quick-start/first-api-call
- Token Plan 购买与管理入口：https://platform.xiaomimimo.com/token-plan

这些依据证明“控制台存在用户可见状态”，但没有证明存在公开额度查询 API。因此本轮目标不是等待公开 API，而是通过用户授权后的官方控制台会话读取真实状态。

## 执行顺序

推荐顺序：

1. 先执行 `W03C-R2`：建立桌面端小米控制台登录会话、授权状态和安全边界。
2. 再执行 `W03D-R2`：在用户授权的控制台会话内发现额度数据来源，形成可复现的接口或页面数据契约。
3. 最后执行 `W03E-R2`：接入实时同步适配器、自动刷新、UI 展示和端到端验收。

## 是否可以并行

可以有限并行：

- `W03C-R2` 和 `W03D-R2` 可以并行启动，但 `W03D-R2` 若没有 `W03C-R2` 的应用内会话能力，只能做“人工控制台 DevTools / HAR 探测”，不能写最终适配器。
- `W03E-R2` 不可并行，必须等待 `W03C-R2` 和 `W03D-R2` 都通过。
- 如果只有一个执行代理，按 `W03C-R2 -> W03D-R2 -> W03E-R2` 顺序执行。
- 如果有两个执行代理，代理 A 执行 `W03C-R2`，代理 B 执行 `W03D-R2` 的人工探测部分；两者完成后再派一个代理执行 `W03E-R2`。

## 阻塞定义

以下情况才允许标记阻塞：

- 用户无法在官方控制台看到已用额度、剩余额度或到期时间。
- 控制台有可见数据，但网络请求和页面状态均无法稳定读取，且复现步骤已经写入报告。
- 控制台需要额外验证或风控，无法在用户授权条件下完成读取。
- 读取路径涉及绕过登录、破解风控、窃取浏览器 Cookie、读取用户外部浏览器数据库或保存账号密码。

以下情况不允许标记完成：

- 只实现套餐目录和总额度。
- 只实现手动录入已用额度、剩余额度、到期时间。
- 只显示“去官网查看”的链接。
- 只保存 Cookie 文本但不自动同步状态。
- 同步失败时没有可读失败原因。

## 最终验收口径

用户在 Token Eyes 桌面端完成小米 MiMo 控制台授权后，应能看到：

- 当前套餐名称。
- 总额度，来自已核验目录或控制台返回。
- 已用额度，来自控制台实时状态。
- 剩余额度，来自控制台实时状态或由总额度减已用额度计算并标明计算方式。
- 到期时间，来自控制台实时状态。
- 最后同步时间。
- 同步失败原因。
- 重新授权入口。

只有这些全部可用，`W03-R2` 才算满足用户需求。
