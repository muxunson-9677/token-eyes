# 01 - 密钥安全修复

## 中文简述

本工单修复两个已实测 P0：API Key 出现在安全存储子进程参数中，以及自定义鉴权 Header 在跨域重定向后继续携带密钥。同时补齐供应商 API endpoint 的错误脱敏和模型调用边界。

## 第一性原理执行规则

- 密钥只应在最短必要路径中存在；任何“加密后落盘”都不能抵消传输过程中暴露在 argv/env 的问题。
- 跨域重定向默认不可信，必须按实际配置的敏感 Header 精确删除，不能靠名称猜测。
- 安全测试必须先复现泄漏，再证明修复后原测试失败路径被关闭。
- 不能以“本机应用”为理由降低密钥保护标准。
- 安全存储不可用时明确失败，不得退回明文配置或内存假持久化。

## 必修问题

### 1. Windows 密钥不得进入 PowerShell 参数

当前 `provider-api-secrets.js` 把密钥插入 `powershell.exe -Command <script>`。必须改为：

- 子进程 argv 不包含密钥。
- 子进程环境变量不包含密钥。
- 密钥通过受控 stdin、原生 Tauri command 或等价安全 IPC 传递。
- 不在 PowerShell 历史、错误、调试日志或进程列表中出现。
- DPAPI 加密结果仍绑定当前 Windows 用户并可跨应用重启读取。
- 临时缓冲区和临时文件不得保留明文；若使用临时文件方案则工单直接判失败。

### 2. macOS Keychain 参数泄漏

当前 `security add-generic-password -w <secret>` 把密钥放入 argv。必须改为不经 argv/env 的原生 Keychain/Tauri 安全调用；如果当前架构无法安全实现，macOS 明确返回 `credential_store_unavailable`，不能保留不安全实现。

### 3. 精确剥离重定向鉴权 Header

- `executeFinancialRequest` 必须把实际 `authHeaderName` 作为敏感 Header 集合传入每一跳。
- origin 发生任一变化（协议、主机或端口）时删除：Authorization、Cookie、实际自定义鉴权 Header及其他明确敏感 Header。
- 删除规则大小写不敏感。
- 第一跳跨域后即使后续跳回原域，也不能恢复密钥。
- 每个重定向目标重新执行 HTTPS、云元数据、财务 endpoint 和模型 endpoint 校验。
- HTTP 降级重定向必须拒绝。

### 4. 错误脱敏

- `local-api.js` 中供应商 test/refresh/config/secret endpoint 的 catch 不得直接返回未经处理的 `e.message`。
- 统一使用供应商 executor 的安全错误映射或独立脱敏函数。
- 密钥位于 URL、Bearer、自定义 Header、PowerShell 错误、Keychain 错误时都必须被清除。

### 5. 严格保持“只查财务”

- 泛化配置不允许携带请求正文或提示词。
- generic POST 必须通过财务路径/适配器允许规则；无法证明为财务查询时返回 `unsupported_endpoint`。
- 至少拒绝 completions、chat、responses、messages、generate、generateContent、predict、invoke、infer、embeddings、images、audio 等模型调用路径。
- 不新增模型、聊天、提示词、代理或 API 调试入口。

### F1 原始失败证据

**反例 F1-a：Windows PowerShell argv 泄漏**

修复前 `provider-api-secrets.js` 的 `encryptSecret` 将密钥插值到 `-Command` 脚本参数中：

```javascript
// 修复前（已删除）
const psScript = `... $plain = "${secret}" ...`;
runner("powershell.exe", ["-NoProfile", "-NonInteractive", "-Command", psScript]);
```

密钥出现在 `powershell.exe` 的 argv 中，可通过进程列表、PowerShell 历史、错误输出泄漏。

复现测试 `F1-REPRO Windows DPAPI saveSecret: secret MUST NOT appear in runner argv`：使用 `makeCapturingRunner` 捕获 `args` 数组，断言 `REPAIR_UNIQUE_SECRET` 不出现在任何 arg 中。修复前 FAIL（secret 在 `-Command` 参数中），修复后 PASS（secret 只通过 `opts.input` 传递到 stdin）。

**反例 F1-b：macOS Keychain argv 泄漏**

修复前 `provider-api-secrets.js` 的 `createMacOSKeychainStore` 使用 `security add-generic-password -w <secret>`，密钥进入 `security` CLI 的 argv。

复现测试 `F1-REPRO macOS Keychain: store MUST be unavailable`：断言 `createDefaultCredentialStore({platform:"darwin"}).isAvailable()` 返回 `false`。修复前 FAIL（store 可用但通过 argv 传递密钥），修复后 PASS（macOS 返回 `credential_store_unavailable`，不保留不安全实现）。

**反例 F1-c：错误消息泄漏密钥**

修复前 `local-api.js` 的 secrets POST endpoint catch 块直接返回 `e?.message`，当 `saveSecret` 抛出含密钥原文的错误时密钥泄漏到 API 响应。

复现测试 `F1-REPRO error response MUST sanitize unique test secret`：使用 `throwingStore`（saveSecret 抛出 `failed to persist ${secret}`），断言响应体不含 `REPAIR_UNIQUE_SECRET`。修复前 FAIL（响应包含密钥原文），修复后 PASS（`sanitizeErrorMessage(e.message, [secret])` verbatim 脱敏）。

### F2 原始失败证据

**反例 F2-a：自定义鉴权 Header 跨域重定向未剥离**

修复前 `provider-api-executor.js` 的 `executeWithRedirects` 跨域剥离逻辑只删除 `Authorization` 和匹配 `SECRET_QUERY_PARAMS` 的 header，未删除实际配置的 `authHeaderName`（如 `X-Custom-Auth`）。

复现测试 `F2-REPRO custom X-Custom-Auth header stripped on cross-port redirect`：配置 `authType:"header"`, `authHeaderName:"X-Custom-Auth"`，首跳到不同端口，断言目标服务收到的请求不含 `X-Custom-Auth`。修复前 FAIL（自定义 header 被转发到跨域目标），修复后 PASS（`sensitiveHeaderNames` 集合包含 `configuredAuthHeaderName`，跨域时精确剥离）。

**反例 F2-b：HTTP 降级重定向未拒绝**

修复前重定向逻辑未校验目标协议，生产模式下 HTTP 降级重定向可被跟随。

复现测试 `F2-REPRO HTTP downgrade redirect MUST be rejected (production mode)` + `F2-UNIT validateRedirectTarget rejects HTTP downgrade in production mode`：断言 `validateRedirectTarget("http://evil.example.com/balance", {testMode:false})` 返回 `{ok:false}`。修复前 FAIL（无校验），修复后 PASS。

### 安全存储最终架构

| 平台 | 存储方式 | 密钥传输通道 | argv 泄漏 | env 泄漏 | vault 明文 |
|------|---------|-------------|----------|---------|-----------|
| Windows | DPAPI via PowerShell | stdin（`opts.input` → `[Console]::In.ReadToEnd()`） | 否 | 否 | 否（DPAPI 密文） |
| macOS | `credential_store_unavailable` | N/A | N/A | N/A | N/A |
| Linux | `credential_store_unavailable` | N/A | N/A | N/A | N/A |

关键设计：
- `defaultRunner` 使用 `stdio: ["pipe","pipe","pipe"]`，`opts.input` 写入子进程 stdin 后关闭
- PowerShell `-Command` 脚本为常量文本，不含密钥插值
- vault 文件 (`provider-api-vault.enc`) 存储 DPAPI 密文 blob，mode 0600
- macOS 不保留不安全的 `security -w <secret>` 实现，明确返回 `credential_store_unavailable`
