# 03 - 发布配置与可复现收口

## 中文简述

本工单由完成 01 的安全/发布主线 subagent 继续执行。它修复安装包版本、macOS runner、Homebrew 派发参数和工作流测试盲区，并把本轮相关代码整理成可从 Git 提交重现的状态。

## 前置条件

- 01 已完成并通过对抗性审查。
- 02 已完成或至少已提供最终提交，准备合入。
- 不得在脏工作区中盲目 `git add -A`。

## 第一性原理执行规则

- 发布产物的版本、平台、来源和校验必须一致，不能只看 workflow 绿色。
- 自动测试必须能够针对错误配置失败，不能只检查模糊字符串存在。
- 可复现意味着从提交重新 checkout 后能得到同样代码和构建结果。
- 只提交本轮相关文件，不打包旧日志、截图、临时脚本和用户其他修改。
- 无法运行真实 GitHub Actions 时明确记录缺证，不宣称发布通过。

## 必修问题

### 1. 版本统一

- `package.json`、`src-tauri/tauri.conf.json`、macOS `MARKETING_VERSION` 和需要版本的其他正式清单统一为当前发布版本 `0.54.0`。
- Windows workflow 同时校验 `package.json` 与 `tauri.conf.json`。
- 生成的 MSI/NSIS 文件名和安装包元数据不得再显示 `0.1.0`。
- 增加测试，任一版本不一致时失败。

### 2. macOS runner

- `.github/workflows/release-dmg.yml` 使用项目要求的 `macos-26`。
- 保持 Icon Composer/Xcode 26 所需能力。
- 测试必须精确解析 `runs-on`，不能只检查 workflow 文件存在。

### 3. Homebrew 派发

- `gh workflow run` 的 repo 修正为 `mm7894215/homebrew-tokentracker`。
- 不允许尾随 `/dispatches`。
- 增加精确参数测试，旧错误值必须触发失败。

### 4. 工作流测试盲区

- 更新 release workflow 测试，覆盖：显示名、runner、版本校验、Tauri build、artifact 路径、Homebrew repo。
- 对错误 fixture 做负向验证，证明测试会失败。
- 不用 `includes("homebrew-tokentracker")` 这类会让错误 repo 通过的宽松断言。

### 5. 合入与提交可复现性

- 合入 01、02 的最终提交，解决冲突后重新执行全量门禁。
- 盘点当前任务相关的 tracked/untracked 文件。
- 只提交本轮生产代码、测试、copy、workflow 和工单回写。
- 不提交 `_review_*`、`_acceptance_*`、日志、截图、临时 server PID、mock 输出和无关历史文档。
- 最终记录 base SHA、合入 SHA、最终 HEAD 和相关提交列表。
- `git diff --check` 必须通过；任务相关文件不得继续处于未提交状态。
