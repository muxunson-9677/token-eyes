# 02 - 前端交互与订阅契约修复

## 中文简述

本工单修复命令面板崩溃、成本设置页不实时显示账户财务数据，以及订阅记录周期和币种被后端静默改写的问题。它可与 01 并行，但不得降低 01 的安全约束。

## 第一性原理执行规则

- 测试必须复现用户真实操作，不能只测试数据数组或组件名称存在。
- 设置页承诺展示余额和花销，就必须加载真实财务结果、显示币种与更新时间，而不是只显示“已配置”。
- 前后端枚举必须只有一套事实来源，非法输入要明确拒绝，不能静默改成另一种含义。
- 未知、失败、未连接显示 `—` 或明确状态，不能显示 0。
- 只修复必要交互和契约，不重做页面视觉。

## 必修问题

### 1. 命令面板真实渲染

- `CommandPalette` 展平二级导航时，子项图标使用 `item.icon || group.icon` 或安全的统一 fallback。
- 渲染前确保 `Icon` 是有效组件；无图标时不得渲染 undefined component。
- 命令面板列出概览、使用统计、成本累积、基础设置、成本设置。
- 点击结果进入正确 URL。
- 单元测试必须真实渲染 `CommandPalette`，发送 `Ctrl+K`，断言 dialog 打开并点击子项；不能继续只复制 flatMap 代码进行自测。

### 2. 成本设置实时财务展示

- `ProviderApiConfigSection` 加载配置时同时读取 cached balances。
- 对启用且有密钥引用的配置，页面进入后立即刷新一次。
- 按配置间隔轮询，最短 60 秒，组件卸载后停止。
- 卡片必须展示余额、当月花销、累计花销、币种、状态、最后同步时间。
- 手动测试/刷新后立即更新卡片金额，不只更新“连接成功”。
- 网络失败保留上次成功金额并标记过期；首次失败显示 `—`。
- 可复用 `useProviderApiBalances`，不得新建不同字段的平行数据流。
- API Key 不进入余额 hook、金额卡片、DOM 属性或错误信息。

### 3. 一次性订阅周期契约

- API 持久化值统一为 `monthly | yearly | one_time`。
- UI 可显示“一次性”，但提交必须发送 `one_time`。
- 编辑已有 `one_time` 记录时选择框正确回显“一次性”。
- 后端遇到未知周期返回 400 `invalid_billing_cycle`，不得静默回退 monthly。

### 4. 订阅币种契约

- 本轮最小实现只支持现有后端真实支持的 USD/CNY。
- 从 UI 删除 EUR/GBP 选项。
- 后端遇到其他币种返回 400 `invalid_currency`，不得静默改为 USD。
- 不在本轮新增汇率体系或伪造 EUR/GBP 换算。

### 5. 表单基本校验

- 名称、供应商、正金额、币种、周期、开始日期为必填。
- 前端禁用无效保存并显示明确原因。
- 后端再次校验，不能只信前端。
- 金额为 0、负数、NaN 时返回 400，不能落成 0 元记录。
- 保存失败保留表单内容，不能显示成功。

### 6. 未知成本不得显示 0

- `use-cost-accumulation` 在关键 totals 缺失时返回 unavailable 状态或 null。
- 成本卡片显示 `—`/未取得数据，不得用 `?? 0` 掩盖缺失字段。
- 合法真实 0 仍显示 0，必须区分“真实零值”和“字段缺失”。

### F3-F6 原始失败证据

#### F3 — 命令面板 Ctrl+K 崩溃（React issue 130）

- 根因：`CommandPalette.jsx` 展平二级导航时，spend/settings 子项没有自己的 `icon` 字段；组件直接以 `item.Icon`（undefined）作为 React 元素类型挂载，触发 "Element type is invalid: expected a string ... but got: undefined"。
- 复现：旧测试只复制 `flatMap` 代码并断言 label 字符串，从未真实渲染 `CommandPalette`、从未发送 `Ctrl+K`、从未渲染 `item.Icon`。新增 `CommandPalette.nav.test.jsx` 真实渲染组件、发送 `Ctrl+K`、点击无图标的二级子项，修复前抛出 React issue 130。

#### F4 — 成本设置页不显示财务数据

- 根因：`ProviderApiConfigSection` 维护自己的局部 state，仅在手动"测试"按钮点击时读取一次 transient `lastBalance`；卡片从未渲染余额/月花销/累计花销，只显示"已配置"。
- 复现：新增 `ProviderApiConfigSection.test.jsx` 断言进入页面后卡片应立即出现金额、币种、最后同步时间；修复前断言失败（卡片无金额文本）。

#### F5 — `one_time` 被静默改写为 monthly

- 根因：前端表单 `value='one-time'`（连字符），后端 `VALID_BILLING_CYCLES=['monthly','yearly','one_time']`（下划线）；前端值不匹配后端枚举，落库时被默认回退为 monthly。
- 复现：`spend-records-api.test.js` 新增 8 个 F5/F6 契约测试，断言 `POST` 接受 `one_time` 原样存储、`PUT` 同样接受；修复前 `one-time` 提交后被存为 monthly。

#### F6 — EUR/GBP 被静默改写为 USD

- 根因：前端提供 EUR/GBP 选项，后端 `currency==='CNY'?'CNY':'USD'` 把 EUR/GBP 一律归一化为 USD。
- 复现：后端契约测试断言 `POST` 对 EUR/GBP 返回 400 `invalid_currency`；修复前端只提供 USD/CNY。

#### Task-10 — 未知金额被伪装为 0

- 根因：`use-cost-accumulation.js` 用 `?? 0` 把 null totals 掩盖成 0；`SpendPage.jsx` `formatAmount` 用 `Number(value || 0)` 同样把缺失字段显示为 `0.00`。
- 复现：`CostAccumulation.contract.test.jsx`（8 个契约测试）与 `SpendPage.test.jsx` 断言 null/undefined/NaN 显示 `—`、真实 0 显示 `0.00`；修复前缺失字段显示为 `0.00`（假 0）。

### 最终订阅契约

- `billing_cycle`：`monthly | yearly | one_time`（前端提交值与后端持久化值完全一致，下划线）。
  - 后端 `validateSpendRecordContract` 对未知值返回 HTTP 400 + `{ error_code: "invalid_billing_cycle" }`，不静默回退。
  - 前端表单 `<option value="one_time">` 显示文案"一次性"，提交值 `one_time`。
- `currency`：`USD | CNY`（仅本轮后端真实支持的两种）。
  - 后端对其他币种返回 HTTP 400 + `{ error_code: "invalid_currency" }`，不静默改写。
  - 前端表单只提供 USD/CNY 两个 `<option>`，EUR/GBP 已删除。
- `amount`：必须为正有限数；0、负数、NaN 返回 400，不落成 0 元记录。
- 必填：`name`、`provider`、`amount`、`currency`、`billing_cycle`、`start_date`；前后端双重校验。
- 缺失成本字段：totals 为 null/undefined/NaN → UI 显示 `—`；真实 0 → `0.00`。
