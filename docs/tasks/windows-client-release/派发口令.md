# Windows 客户端外发验收派发口令

## 推荐上下文矩阵

| Subagent | 执行方式 | 工单 | 上下文规则 |
|---|---|---|---|
| A 主线调度 | 第一阶段执行 01；第三阶段继续执行 04 | README + 01 + 04 | 01 与 04 共用一个上下文合适，便于维护文件归属和合流证据 |
| B 运行时封装 | 第二阶段与 C 并行 | README + 02 | 单独上下文/独立 worktree，只负责 Tauri EmbeddedServer 和启动恢复 |
| C 安全发布 | 第二阶段与 B 并行 | README + 03 | 单独上下文/独立 worktree，只负责依赖、签名和 workflow |
| D 最终终审 | A 完成 04 后执行 05 | README + 05 + 01-04 完成回写 | 必须全新上下文，不能继承 A/B/C 的通过结论 |

## 执行顺序

```text
第一阶段串行：
A: 01

第二阶段并行（不同 worktree）：
B: 02
C: 03

第三阶段串行：
A: 合流 B/C -> 04

第四阶段全新独立上下文：
D: 05
```

如果 05 发现问题：退回对应 A/B/C 修复，A 重新执行受影响的 04 路径，然后必须新开 D2 重新执行 05；不得复用已经参与问题定位的 D。
