# 05 - 独立贝叶斯终审

## 目标

由未参与 01-04 的全新上下文，主动推翻“已经可以外发”的假设，独立复验发布 HEAD、安装包内容、真实签名、依赖安全、干净 Windows 安装和数据闭环，重新计算 B1-B7 后验，只在全部硬门禁通过时签发“可外部安装验证”。

本工单不自动授予正式生产上线结论。

## 独立性硬门禁

- 审查者不得是执行过 01、02、03、04 或参与其修复决策的上下文。
- 审查者不能只读完成报告；必须亲自读取代码、运行命令和检查产物。
- 若审查者发现问题并亲自参与修复，该上下文立即失去最终签发资格。
- 问题必须退回对应执行上下文修复；04 重新合流验收后，再创建另一个全新 05 审查上下文。
- 不得让同一 05 上下文“发现问题 -> 修复 -> 自己宣布最终通过”。

## 第一性原理执行规则

1. 默认假设安装包不可用，直到独立证据逐项否定所有已知反例。
2. 优先攻击能够让测试全绿但用户失败的边界：缺资源、系统 Node、旧端口、错误签名、旧安装包和脏 HEAD。
3. 数值后验不能覆盖硬失败；任一 P0/P1、缺证或输出冲突都直接不通过。
4. 相同证据只计算一次；执行者测试与审查者复跑可作为两个证据组，但复制其日志不算独立复跑。
5. 无真实签名证书、无真正干净 Windows、无最终安装包时只能 `BLOCKED`。
6. 不读取或保存用户提示词、消息正文、API Key、Cookie、令牌和 `.env` 值。
7. 最终结论必须区分“可外部安装验证”和“可正式上线”。

## 必须重新攻击的反例

### R1：HEAD 与构建输入不可复现

- 从最终 HEAD 创建新的干净检出。
- 验证所有任务生产代码、测试、runtime manifest 生成脚本和工单已跟踪。
- 不允许复制原工作区的 `dist`、`target`、EmbeddedServer 或未跟踪源码。
- 在干净检出重新安装依赖并构建。

失败条件：任一必要文件为 `??`、干净检出构建失败、构建依赖原工作区缓存。

### R2：安装包仍依赖开发机

- 解包最终 MSI/NSIS，独立检查 Node、CLI、Dashboard、生产依赖、manifest 和许可证。
- 在 PATH 无 Node、cwd 不在 repo、无旧本地服务的环境启动。
- 通过进程路径证明使用安装目录内 bundled `node.exe`。

失败条件：调用系统 Node、寻找祖先 `bin/tracker.js`、手工补文件后才可运行。

### R3：窗口能开但本地 API/同步不可用

- 独立验证 `/api/local-auth` 协议/capabilities 和三个核心端点。
- 使用固定 fixture 连续同步两次，验证第二次不重复计数。
- 验证至少一个真实 Agent 本地日志计数，不读取消息正文。
- 杀掉后端、占用端口并重试，验证可见错误和恢复。

### R4：安全扫描被忽略或误判

- 独立运行 npm production audit 和 cargo audit。
- 重建 `ws`、`quick-xml` 反向依赖链。
- 扫描源码、dashboard dist、安装包解包目录和日志中的密钥模式、`.env` 和完整用户路径。

失败条件：任一未批准 high/critical、RustSec vulnerability、真实密钥或敏感数据进入产物/日志。

### R5：签名或发布资产不可信

- 独立验证主 EXE、MSI、NSIS 签名状态、发布者、时间戳和哈希。
- 篡改一份副本，证明签名校验会失败。
- 检查 workflow 上传 glob、README 下载名、版本和 SHA256SUMS 一致。

失败条件：自签名、NotSigned、UnknownError、证书主体不符、旧版本被上传或链接 404 风险未关闭。

### R6：干净安装生命周期缺证

- 使用不同于 04 正常路径的全新快照或第二台干净环境抽查安装。
- 验证首次启动、重启、重复启动、断网、本地历史数据、重装和卸载。
- 检查卸载后进程/安装目录，检查默认用户数据保留契约。

失败条件：只复用 04 截图、没有环境基线、没有真实安装、卸载残留进程或丢失用户数据。

### R7：CI 只是“看起来有门禁”

- 静态检查 workflow 后运行对应测试。
- 在受控副本/测试中分别制造 audit 失败、runtime 缺文件、版本不一致、签名无效，确认上传不会执行。
- 检查 release draft 不会在 Windows/macOS 任一失败时提前公开。

## 贝叶斯复算表

审查者必须填写实际数值和赔率推导：

| 编号 | 先验 | 独立证据组 | LR | 后验赔率 | 后验 | 门槛 | 结果 |
|---|---:|---|---:|---:|---:|---:|---|
| B1 可复现发布基线 | 0.20 |  |  |  |  | 0.99 |  |
| B2 自包含运行时 | 0.01 |  |  |  |  | 0.99 |  |
| B3 本地 API/同步/恢复 | 0.55 |  |  |  |  | 0.99 |  |
| B4 依赖与敏感信息安全 | 0.25 |  |  |  |  | 0.99 |  |
| B5 签名与发布身份 | 0.05 |  |  |  |  | 0.99 |  |
| B6 干净安装生命周期 | 0.05 |  |  |  |  | 0.99 |  |
| B7 可见故障与全量回归 | 0.40 |  |  |  |  | 0.95 |  |

必须计算：

```text
每项先验赔率 = 先验 / (1 - 先验)
每项后验赔率 = 先验赔率 × 相对独立 LR
每项后验 = 后验赔率 / (1 + 后验赔率)
加权总后验 = Σ(后验 × 权重)
```

同一测试的开发者运行和审查者重复运行最多分别算一个证据组；同一安装包的 MSI 解包和文件列表描述只算一个证据组。任何直接反例使用 LR=0.05，并触发硬门禁失败。

## 结论规则

- 任一 P0/P1 未关闭：`不可外发`。
- 任一 B1-B6 < 0.99 或 B7 < 0.95：`不可外发`。
- 加权总后验 < 0.97：`不可外发`。
- 证书、干净机器、最终产物或新鲜命令任一缺证：`BLOCKED`。
- 全部通过：`可外部安装验证`，但不是自动“可正式上线”。
- 正式上线仍需用户批准 release、外部测试反馈和项目正式发布流程，本工单不得越权执行 push/release。

## 问题闭环规则

发现问题时：

1. 立即在 `review-records.md` 追加失败记录、复现命令和归属工单。
2. 结论写 `RETURNED`，退回 01/02/03/04 对应执行上下文修复。
3. 修复者重新执行其对抗性审查；04 对合流产物重新构建、签名和干净安装。
4. 当前 05 上下文不得最终签发。
5. 新建另一个全新 05 审查上下文，从 R1-R7 重新开始，直到一轮完整通过。
