# 工单 08: 用量列表展示对接

## 任务编号与分支名

- 编号: `08`
- 分支: `feature/08-usage-list-panel`

## 背景说明

Day1 已完成 Hermes 用量解析、路径配置和后端写入链路。Token Eyes MVP 的用量列表不需要新设计，本任务只把现有用量列表模式整理成可复用展示区，并确保 Hermes 记录能按现有筛选方式正常显示。

## 允许改动的目标文件清单

- `src/components/usage/UsageListPanel.tsx`
- `src/components/usage/UsageDashboard.tsx`
- `src/components/usage/RequestLogTable.tsx`
- `tests/components/UsageListPanel.test.tsx`
- `docs/test-reports/08.md`

## 已确定的输入规范

接口定义以 `docs/dev-notes/interfaces.md` 的 `Day 2 前端组件数据接口` / `用量列表展示字段` 为准。

本任务复用现有链路:

- `RequestLog`
- `PaginatedLogs`
- `useRequestLogs`
- `RequestLogTable`

展示字段以现有 `RequestLogTable` 为准，并至少覆盖:

- `providerName`
- `appType`
- `model`
- `inputTokens`
- `outputTokens`
- `cacheReadTokens`
- `cacheCreationTokens`
- `totalCostUsd`
- `statusCode`
- `createdAt`
- `dataSource`

Hermes 约定:

- Hermes 行使用 `appType: "hermes"`。
- `appType === "all"` 调用查询前归一化为 `undefined`。

## 具体步骤

1. 新增 `src/components/usage/UsageListPanel.tsx`，作为 `RequestLogTable` 的薄封装，props 与当前 Dashboard 传入列表所需参数保持一致。
2. 在 `UsageListPanel` 中继续调用现有 `RequestLogTable`，不要复制表格实现。
3. 在 `src/components/usage/UsageDashboard.tsx` 中用 `UsageListPanel` 替换当前直接使用 `RequestLogTable` 的位置。
4. 如 `RequestLogTable` 已缺少 `appType` 或 `dataSource` 的可见展示，允许在 `RequestLogTable.tsx` 做最小字段展示补齐；否则不要改表格内部。
5. 增加 `tests/components/UsageListPanel.test.tsx`，mock `RequestLogTable` 或 query，验证 Hermes filter props 能传入列表组件。
6. 自测并把结果写入 `docs/test-reports/08.md`。

## 验收标准

- `pnpm typecheck` 通过。
- `pnpm test:unit -- UsageListPanel` 通过，或在报告中说明本仓库 test runner 对单测筛选的实际命令。
- Dashboard 用量列表仍保留原有分页、筛选和详情入口。
- 选择 Hermes 筛选时，请求参数能传递 `appType: "hermes"`。
- PR 改动只涉及允许文件。

## 禁止事项

- 不新增后端接口。
- 不修改用量 schema。
- 不新增依赖。
- 不改 locale JSON；需要文本时使用现有 key 或 `t(..., { defaultValue })`。
- 不复制一份新的完整表格实现。
- 不实现花销图表或订阅费表单。
- 不实现套餐摊销、预测、燃烧速率或自动识别。

## 子智能体纪律

- 只在 `feature/08-usage-list-panel` 分支工作，不能直接动 `main`。
- 完成后必须自测: 编译通过 + 功能验证。
- 自测结果写入 `docs/test-reports/08.md`。
- 提交 PR，但不能自行合并。
- 发现工单要求和代码现状冲突，不要自己改设计；在 PR 描述里写 `设计冲突,请确认` 并停下。
