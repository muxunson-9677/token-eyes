# 工单 05: cost_ledger 聚合查询

## 任务编号与分支名

- 编号: `05`
- 分支: `feature/05-cost-ledger`

## 背景说明

Token Eyes MVP 需要一个最简花销聚合服务，把 token 消耗成本和手动订阅费合并成统一查询结果。Day1 已确定公式和接口，本任务只实现后端聚合查询。

## 允许改动的目标文件清单

- `src-tauri/src/services/cost_ledger.rs`
- `src-tauri/src/services/mod.rs`
- `src-tauri/src/commands/usage.rs`
- `src-tauri/src/lib.rs`
- `docs/test-reports/05.md`

## 已确定的输入规范

接口定义和公式以 `docs/dev-notes/interfaces.md` 的 `cost_ledger 最简公式` 为准。

命令名:

- `get_cost_ledger_summary`

核心公式:

```text
period_total_usd = token_cost_usd + subscription_cost_usd
cumulative_total_usd = cumulative_token_cost_usd + cumulative_subscription_cost_usd
```

## 具体步骤

1. 新增 `src-tauri/src/services/cost_ledger.rs`。
2. 实现 `CostLedgerQuery`、`CostLedgerByAgent`、`CostLedgerSummary`，字段使用 camelCase 序列化。
3. 实现 `get_cost_ledger_summary(db, query)`。
4. token 成本沿用现有用量统计去重口径，避免重复计数。
5. subscription 成本只纳入 `currency = 'USD'` 的记录。
6. 对每个与查询周期相交的自然月，活跃订阅费计入一次。
7. `by_agent` 按 agent/app 维度汇总 token 成本、订阅费和合计。
8. 在 `services/mod.rs` 导出模块。
9. 在 `commands/usage.rs` 暴露 Tauri 命令。
10. 在 `lib.rs` 注册命令。
11. 添加单元测试:
    - 只有 token 成本。
    - 只有订阅费。
    - token 成本 + 订阅费。
    - 跨月订阅费计数。
    - `end_date < start_date` 返回错误。
12. 自测并把结果写入 `docs/test-reports/05.md`。

## 验收标准

- `cargo test --manifest-path src-tauri/Cargo.toml cost_ledger` 通过。
- `cargo check --manifest-path src-tauri/Cargo.toml` 通过。

- 四类金额字段均以 6 位小数字符串返回。
