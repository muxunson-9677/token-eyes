# 工单 01: Hermes 本地数据解析适配器

## 任务编号与分支名

- 编号: `01`
- 分支: `feature/01-hermes-usage-source`

## 背景说明

Token Eyes 需要把 Hermes 本地用量导入现有标准用量明细表。ccusage 的 Hermes 适配器读取 Hermes 本地 `state.db` 的 `sessions` 表，并从会话行提取 token、成本、模型与会话信息。本任务只实现本地数据解析与同步，不改动前端展示。

参考资料:

- `https://ccusage.com/guide/hermes/`
- ccusage 源码参考: `rust/crates/ccusage/src/adapter/hermes/loader.rs`
- ccusage 源码参考: `rust/crates/ccusage/src/adapter/hermes/parser.rs`

## 已确定的输入规范

Hermes 数据源路径:

- 使用 `crate::hermes_config::get_hermes_dir().join("state.db")`。
- 如果文件不存在，返回空同步结果，不报错。

读取 SQL:

```sql
SELECT
  id,
  model,
  billing_provider,
  started_at,
  message_count,
  input_tokens,
  output_tokens,
  cache_read_tokens,
  cache_write_tokens,
  reasoning_tokens,
  estimated_cost_usd,
  actual_cost_usd
FROM sessions
WHERE model IS NOT NULL
  AND TRIM(model) != ''
```

映射到 `proxy_request_logs`:

- `request_id = "hermes_session:{session_id}"`
- `provider_id = "_hermes_session"`
- `app_type = "hermes"`
- `model = model`
- `request_model = model`
- `session_id = Some(session_id)`
- `provider_type = Some("hermes_session")`
- `data_source = "hermes_session"`
- `input_tokens = input_tokens`
- `output_tokens = output_tokens + reasoning_tokens`
- `cache_read_tokens = cache_read_tokens`
- `cache_creation_tokens = cache_write_tokens`
- `status_code = 200`
- `latency_ms = 0`
- `first_token_ms = NULL`
- `is_streaming = 1`
- `cost_multiplier = "1.0"`
- `created_at` 来自 `started_at`，支持秒或毫秒数值。

成本规则:

- `actual_cost_usd > 0` 时优先使用。
- 否则使用 `estimated_cost_usd > 0`。
- 否则使用现有 `CostCalculator` 和 `model_pricing` 计算。
- 计算时先尝试 `{normalized_billing_provider}/{model}`，再尝试 `{model}`。
- 如果使用 Hermes 已记录的聚合成本，允许只写 `total_cost_usd`，各分项成本写 `"0"`。

过滤规则:

- `id` 或 `model` 为空的行跳过。
- input/output/cache/reasoning token 全为 0 且成本也为 0 的行跳过。
- 使用现有 `should_skip_session_insert` 去重。

## 具体步骤

1. 从 `session_usage_opencode.rs` 复制同步模式，但新文件名必须是 `usage_source_hermes.rs`。
2. 只读打开 Hermes `state.db`；同时检查 `state.db-wal` 修改时间，避免漏掉新写入数据。
3. 查询 `sessions` 表并解析字段，所有负数 token 按 0 处理。
4. 实现 provider 归一化: `anthropic/claude -> anthropic`、`openai/openai_codex -> openai`、`google/gemini/vertex -> google`，其它值转小写并把 `-` 替换为 `_`。
5. 插入 `proxy_request_logs`，不要显式写入 Day1 已定 schema 之外的字段。
6. 在 `sync_session_usage` 中合并 Hermes 同步结果。
7. 在应用启动初始同步和周期同步中加入 Hermes 同步。
8. 添加单元测试: 构造临时 `state.db` 和 `sessions` 表，验证至少一条记录可导入且 token、成本、`data_source` 正确。
9. 自测并把结果写入 `docs/test-reports/01.md`。
