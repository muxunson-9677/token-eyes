# Token Eyes 2.0 当前修复派发说明

## 中文简述

本目录是当前最新一轮中文工单，用于修复“界面局部可用，但还不能上线验收”的阻塞问题。工单不绑定任何具体代理或模型，统一使用“执行代理”和“审查代理”。

## 推荐派发矩阵

| 代理 | 执行方式 | 发哪些文件 | 说明 |
|---|---|---|---|
| 执行代理-主线修复 | 串行 | `README.md` + `01-上线阻塞修复.md` | 负责真实路径、请求分页、成本口径、飞书 2.0 记录和相关测试修复 |
| 审查代理-独立验收 | 等 01 完成后执行 | `README.md` + `02-独立验收审查.md` + 01 完成报告 | 必须使用独立上下文，不能直接采信主线修复结论 |

## 执行顺序

```text
执行代理-主线修复：
01-上线阻塞修复

然后再开独立审查代理：
02-独立验收审查
```

## 派发口令

### 01 派发口令

```text
请先阅读 docs/tasks/v2.0-release-repair/current/README.md，然后执行 docs/tasks/v2.0-release-repair/current/01-上线阻塞修复.md。必须按工单列出的缺漏证据逐项修复，每项修复都要写回证据、命令、结果和剩余风险。不要执行 02，02 会交给独立审查代理。
```

### 02 派发口令

```text
请先阅读 docs/tasks/v2.0-release-repair/current/README.md 和 docs/tasks/v2.0-release-repair/current/02-独立验收审查.md，并读取 01 的完成报告。你的职责是独立验收，不是继续相信 01 的自评。必须重新运行命令、检查 API、检查浏览器页面、核对飞书读回，并给出是否可上线体验的结论。
```

## 共用规则

- 不得把执行代理写死为任何具体模型或工具。
- 不得只根据上一轮代理汇报判断通过，必须使用当前工作区的真实命令和文件状态。
- 不得用仓库 URL 冒充本地真实项目路径。
- 不得把未定价成本显示成真实 0 成本。
- 不得把旧 W03E-R3 飞书记录当成本轮 2.0 工单读回证据。

工单执行完成的最后增加一个审查环节，以对抗性审查的方式回写审查记录，如果出现问题就修复，修复执行完的环节依旧是对抗性审查，直到都完成了才能结束，并汇报给我工单的完成情况
