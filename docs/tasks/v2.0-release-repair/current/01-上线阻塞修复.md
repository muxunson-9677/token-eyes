# 01-上线阻塞修复

## 中文简述

当前产品可以打开页面，也有部分专项测试通过，但还不能作为真实数据体验版上线。本工单负责修复上线前的硬阻塞：真实项目路径、请求日志完整分页、成本口径、API 计费语义、飞书 2.0 记录和本轮相关测试。

## 第一性原理执行规则

- 用户要解决的是“真实数据可理解、可追溯、可验收”，不是只让页面看起来有数据。
- 所有数字必须能追溯到真实 API、真实队列或明确的估算规则。
- 没有真实路径就显示“未检测到真实路径”，不能用 GitHub/Gitee URL 冒充本地路径。
- 未定价成本不能显示为真实 0 成本，必须明确“未定价”或“需配置价格”。
- 每项修复都要先写失败证据，再写修复动作，最后写复查结果。

## 缺漏证据

| 编号 | 缺漏 | 当前证据 |

| E1 | 项目用量没有真实本地路径 | `/functions/tokentracker-project-usage-summary?limit=10` 返回 5 个项目，但 `project_path` 全为空 |
| E2 | 请求日志 UI 只暴露 100 条上限 | 后端 `limit=5000` 可返回 5000 条、500 页，但 UI 显示 100 条、10 页 |
| E3 | 成本显示误导 | `gpt-5.4` 等记录 `cost_usd=0`，页面显示 `$0` 或“未定价”，无法说明项目真实花费 |
| E4 | API 计费语义不完整 | 未连接平台账单时只能显示 `not-connected/null`，不能说明是否为平台账单或用量估算 |
| E5 | 飞书 2.0 记录未闭环 | 当前读回文件仍是 W03E-R3 系列记录，不是本轮 2.0 的 01/02 |

## 必须完成

### 1. 修复项目真实路径

验收要求：

- `tokentracker-project-usage-summary` 对真实本地项目返回 `project_path`。
- 如果只能拿到远程仓库 URL，不能填入 `project_path`，只能填 `project_ref`。
- UI 中本地路径和远程仓库标识必须分开展示。
- 没有真实路径时显示“未检测到真实路径”。

复查命令：

```powershell
node --test test/project-path.test.js
```

运行时复查：

```powershell
node bin/tracker.js serve --port 17680 --no-open --no-sync
```

访问：

```text
http://127.0.0.1:17680/functions/tokentracker-project-usage-summary?limit=10
```

### 2. 修复请求日志完整分页

验收要求：

- UI 必须使用服务端分页，不允许只拉 100 条再前端分页。
- 页面总数、总页数、当前页必须和 API 返回一致。
- page 1 和 page 2 必须返回不同记录。
- 页码跳转、上一页、下一页、首页、末页必须可用。

复查命令：

```powershell
node --test test/request-usage-records-api.test.js
npm --prefix dashboard run test -- src/ui/dashboard/components/__tests__/RequestUsageLog.test.jsx
```

运行时复查：

```text
http://127.0.0.1:17680/functions/tokentracker-request-usage-records?page=1&pageSize=10&limit=5000
http://127.0.0.1:17680/functions/tokentracker-request-usage-records?page=2&pageSize=10&limit=5000
```

### 3. 修复成本与定价口径

验收要求：

- 能定价的模型必须计算成本。
- 不能定价的模型必须显示“未定价”或“需配置价格”。
- UI 不能把未定价成本误显示为真实 `$0`。
- 项目用量、请求日志、Provider 统计、模型统计的成本口径必须一致。

复查命令：

```powershell
node --test test/truthful-metrics-contract.test.js test/usage-caliber-consistency.test.js
npm --prefix dashboard run test -- src/pages/SpendPage.test.jsx
```

### 4. 修复 API 计费语义

验收要求：

- API 计费必须和订阅记录分离。
- 未连接真实平台账单时显示“未连接”。
- 如果采用用量估算，必须明确显示“基于用量估算”，不能冒充平台账单。
- `monthCostUsd` 和 `lifetimeCostUsd` 的 `null`、`0`、真实金额必须有不同语义。

复查命令：

```powershell
node --test test/api-billing-api.test.js
```

### 5. 修复飞书 2.0 进度同步

验收要求：

- 飞书表必须写入并读回本轮 2.0 记录。
- 至少包含：
  - `2.0 / 01 / 上线阻塞修复`
  - `2.0 / 02 / 独立验收审查`
- 不能把 W03E-R3 系列旧记录当成本轮证据。
- 读回输出不得泄露敏感凭证。

### 6. 修复本轮相关测试失败

验收要求：

- 与支出页、项目用量、请求日志、成本累积、API 计费、真实数据口径直接相关的测试必须通过。
- 对完整测试中的剩余失败，必须逐项分类：本轮相关、历史无关、环境依赖、发布阻塞。
- 发布阻塞类失败不能忽略。
