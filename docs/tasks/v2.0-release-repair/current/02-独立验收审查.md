# 02-独立验收审查

## 中文简述

本工单用于最终判断 01 是否真的修完。审查代理不能直接相信 01 的自评，必须重新读取代码、运行命令、检查 API、检查浏览器页面、核对飞书读回，再决定是否可以上线体验。

## 第一性原理执行规则

- 验收目标不是证明 01 做得好，而是找出仍会影响用户真实体验的问题。
- 任何“通过”结论必须有当前工作区的新鲜命令证据。
- 测试失败不能简单归类为“历史问题”，必须说明它为什么不影响本轮上线体验。
- API、UI、飞书三类证据必须能互相印证。
- 如果发现问题，先回写审查记录，再要求修复；修复后继续审查。

## 前置输入

- `docs/tasks/v2.0-release-repair/current/README.md`
- `docs/tasks/v2.0-release-repair/current/01-上线阻塞修复.md`
- 01 的完成报告
- 01 产出的截图、日志、飞书读回文件和测试输出

## 必须审查的问题

| 编号 | 审查项 | 不通过条件 |
---|---|---|
| A1 | 项目真实路径 | 项目用量仍只有 GitHub/Gitee URL，或 `project_path` 全为空 |
| A2 | 请求日志分页 | UI 总数/页数和 API 不一致，或仍只暴露 100 条 |
| A3 | 成本口径 | 未定价成本被显示为真实 `$0`，或项目成本无法解释 |
| A4 | API 计费 | 订阅费用和 API 账单混在一起，或未连接状态被显示成已同步 |
| A5 | 飞书记录 | 读回的仍是 W03E-R3，而不是本轮 2.0 的 01/02 |
| A6 | 发布门禁 | 构建、类型检查、lint、关键测试失败且无可接受解释 |
| A7 | 浏览器体验 | `/spend`、`/dashboard`、`/settings` 任一关键页面无法完成验收路径 |

## API 验收

启动本地服务：

```powershell
node bin/tracker.js serve --port 17680 --no-open --no-sync
```

检查以下接口：

```text
/functions/tokentracker-project-usage-summary?limit=10
/functions/tokentracker-request-usage-records?page=1&pageSize=10&limit=5000
/functions/tokentracker-request-usage-records?page=2&pageSize=10&limit=5000
/functions/tokentracker-api-billing-accounts
/functions/tokentracker-usage-summary
```

必须记录：

- 项目数量。
- `project_path` 非空数量。
- page 1 和 page 2 的前三条 ID。
- API 总数和总页数。
- API 计费账户状态。
- 成本字段是 `null`、`0` 还是真实金额。

## 浏览器验收

必须检查：

- `/spend` 使用统计：请求日志、Provider 统计、模型统计。
- `/spend` 成本累积：Token 套餐、API 计费、订阅记录。
- `/dashboard` 项目用量：真实路径或未检测到路径提示。
- `/settings` 数据目录：环境检测按钮和状态显示。

必须产出：

- 截图路径。
- DOM 摘要。
- 页面结论。
- 仍存在的问题。

## 飞书验收

必须读回以下记录：

- `2.0 / 01 / 上线阻塞修复`
- `2.0 / 02 / 独立验收审查`

不通过条件：

- 只读回 W03E-R3 系列旧记录。
- 读回数量为 0。
- 状态字段缺失。
- 进度说明没有写明修复或验收结果。
- 输出泄露敏感凭证。

## 放行标准

只有同时满足以下条件，才能写“通过”：

- 本轮关键命令全部通过。
- 完整测试失败已分类，且没有本轮相关或发布阻塞失败。
- 项目用量能展示真实本地路径，或明确说明未检测到路径。
- 请求日志 UI 和 API 分页一致。
- 成本显示不再混淆真实 0 与未定价。
- API 计费状态语义清楚。
- 飞书读回本轮 2.0 记录。
- 浏览器页面完成验收路径。

工单执行完成的最后增加一个审查环节，以对抗性审查的方式回写审查记录，如果出现问题就修复，修复执行完的环节依旧是对抗性审查，直到都完成了才能结束，并汇报给我工单的完成情况
