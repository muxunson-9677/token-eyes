# 03 - 独立验收与发布收口

## 中文简述

本工单不属于主线实现。它必须由一个全新、独立的 subagent 在 01、02 完成后执行，重新验证真实数据、浏览器交互、完整测试、桌面壳、飞书记录和发布基线。不能直接采信主线 subagent 的“已完成”结论。

## 第一性原理执行规则

- 验收对象是用户能看到和操作的真实产品，不是测试桩和 mock 页面。
- 任何放行结论都必须对应刚运行的命令或可重复的 E2E 证据。
- 一个阻断门槛失败，结论就是“不放行”，不能用其他通过项抵消。
- 发现问题后可以做最小修复，但必须记录失败、修复和重新审查全过程。
- 飞书写入后必须读回；本地文档不能冒充飞书同步。
- 不删除或回滚用户无关修改；发布范围必须能单独识别和复现。

## 前置门槛

- 01、02 均有完整审查记录，最终结论为“通过”。
- 主线 subagent 提供修改文件清单、测试命令、真实 E2E 脱敏证据。
- 如果缺任一项，03 直接记录“前置证据不足”，退回主线，不开始放行。

## 任务 1：独立读取与需求对照

1. 阅读 `CLAUDE.md`、本目录 README、01、02 和主线审查记录。
2. 直接读取实际修改文件，不用主线摘要替代代码审查。
3. 建立需求矩阵：真实分页、真实路径、请求数、成本 availability、API 计费、环境检测、趋势图、订阅命名、热力图移除。
4. 每项填写：代码位置、自动化证据、真实运行证据、结论。

## 任务 2：真实本地 API 与浏览器 E2E

启动真实本地服务，不加 `mock=1`，不得使用只包含前端假数组的测试证明以下结论：

1. 请求日志 API 的第 1、2 页返回不同记录，UI 显示与 API 相同的总数和总页数。
2. UI 页码、`...`、输入框、跳转按钮、上一页、下一页均可操作。
3. 当前仓库新会话经同步后，项目卡返回并展示当前仓库真实路径；证据只记录路径哈希和路径类型。
4. 请求数未知时显示 `—`；存在请求级数据时显示真实数量。
5. 未定价成本显示“未定价”，部分定价显示已知成本和缺口，不得显示成完整 `$0`。
6. 新增一条测试订阅记录后，订阅区块出现记录，API 计费区块不出现相同金额；测试后清理该记录。
7. 空目录不能通过环境检测；真实可执行 Agent 能返回环境和当前版本；WSL 未启动时不能显示 ready。
8. 1440px 下趋势图宽度比不低于 95%；900px 和移动宽度无横向溢出。
9. 浏览器 console 没有 React key、未处理异常、500 或新增 warning。

## 任务 3：运行发布门槛

```powershell
npm run ci:local
npm --prefix dashboard run lint
npm --prefix dashboard run typecheck
npm --prefix dashboard run test
npm --prefix dashboard run build
cargo check --manifest-path src-tauri/Cargo.toml
git diff --check
```

执行要求：

- 每条命令记录退出码和通过/失败数量。
- 缺少 `sqlite3`、符号链接权限等环境问题必须在受支持的 CI 环境复跑，不能把环境失败写成代码通过。
- 与本轮需求冲突的旧测试必须更新；不得 skip、删除断言或降低门槛来换绿。
- 完整 lint、copy、UI hardcode、guardrails 和构建必须退出 0。
- Tauri 至少 `cargo check` 退出 0；如要生成给用户安装的体验包，还必须执行项目正式 Windows 构建流程并记录产物哈希。
