# 2.0 最终上线阻断修复总调度

## 中文简述

本目录用于处理 2026-07-01 独立复验发现的最后一批上线阻断项。目标不是继续增加功能，而是把已经开发的功能真正接入用户界面、恢复可信发布链路、清零完整测试，并由独立上下文作最终放行判断。

## 文档目录

- `README.md`：总调度、上下文分配、串并行关系和派发口令。
- `01-功能闭环修复.md`：把真实项目路径、项目成本、路径状态接入实际页面，并清理本地浏览器错误。
- `02-发布与测试收口.md`：修复 macOS 与 Windows/Tauri 发布链路，清零后端和前端完整测试。
- `03-独立最终验收.md`：在全新上下文中复跑 API、UI、完整测试、发布 workflow 和飞书读回。
- `review-records.md`：统一记录每轮对抗性审查、问题、修复和复验结论。

## 推荐派发矩阵

建议使用 **1 个主线修复 subagent + 1 个独立验收 subagent**，不要为每个工单新开上下文。

| Subagent | 执行方式 | 发哪些文件 | 说明 |
|---|---|---|---|
| 主线修复 subagent | 串行、同一上下文 | `README.md` + `01-功能闭环修复.md` + `02-发布与测试收口.md` | `01` 会改变 `02` 的测试基线，必须先完成 `01` 再执行 `02` |
| 独立验收 subagent | 等主线完成后，使用全新上下文 | `README.md` + `03-独立最终验收.md` + 主线完成报告和证据路径 | 不参与主线自证，独立判断是否达到上线门槛 |

## 串并行规则

### 必须串行

```text
01 功能闭环修复
  -> 02 发布与测试收口
  -> 03 独立最终验收
```

- `01 -> 02` 必须串行：`02` 的完整测试和发布构建必须验证 `01` 的最终代码。
- `02 -> 03` 必须串行：独立验收只能读取已经完成的主线证据，不能边修边验。
- `02` 的合并、完整测试、干净检出验证、飞书状态更新必须串行执行。

### 可以并行但默认不建议

在 `01` 已完成并形成基线提交后，`02` 内以下两项可以在 **两个独立 worktree** 中并行：

- macOS workflow 修复。
- Windows/Tauri workflow 修复。

并行分支完成后必须回到主线串行合并，再执行完整测试和发布验证。考虑当前工作区约有 255 项改动，为降低冲突和 Token 成本，默认仍建议由同一个主线 subagent 串行完成。

## 主线派发口令

```text
请先阅读 docs/tasks/v2.0-release-final-fix/README.md，然后在同一个上下文中按顺序执行 01-功能闭环修复.md 和 02-发布与测试收口.md。必须先完成 01 并通过其验收，再开始 02，不得跳步。开始前先保护当前工作区，不得删除或回退不属于本工单的已有改动。每个工单都必须按第一性原理执行，先记录失败证据，再实施最小修复，运行规定命令和真实运行时验收，并把过程写入 review-records.md。不要执行 03，03 交给独立验收 subagent。
```

## 独立验收派发口令

```text
请阅读 docs/tasks/v2.0-release-final-fix/README.md、03-独立最终验收.md、review-records.md，以及主线 subagent 的 01/02 完成报告。你必须使用全新上下文，不得直接采信主线的通过结论。重新读取代码、复跑完整测试、真实 API、浏览器 E2E、发布 workflow 检查和飞书读回。任何硬门禁失败都必须判定不通过并回写审查记录；修复后从对应门禁重新开始，直到所有门禁通过后才能报告可上线。
```

## 共同规则

- 不得删除或回退用户已有的无关改动。
- 不得用局部测试通过替代完整测试通过。
- 不得把构建成功当作浏览器 E2E 成功。
- 不得把 workflow 关键词测试通过当作 workflow 命令可执行。
- 不得把旧 .NET Windows 包当作 Token Eyes Tauri 包。
- 不得在报告、日志、截图或飞书中输出 App Secret、tenant token、Cookie、API Key 或实际资源 Token。
- 飞书只能在工程证据通过后更新为“通过”；发现失真状态必须先改为“进行中”或“阻塞”。
- 所有通过结论必须附当前工作区的新鲜命令输出、API 摘要或浏览器证据。

工单执行完成的最后增加一个审查环节，以对抗性审查的方式回写审查记录，如果出现问题就修复，修复执行完的环节依旧是对抗性审查，直到都完成了才能结束，并汇报给我工单的完成情况
