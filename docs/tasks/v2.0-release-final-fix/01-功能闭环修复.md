# 01 - 功能闭环修复

## 中文简述

本工单解决“后端已经返回真实项目路径和成本，但用户页面仍看不到”的断链问题，同时补齐项目路径状态契约并消除本地页面的可复现控制台错误。只修复已确认的功能闭环，不新增热力图或其他功能。

## 目标

用户进入概览页的“项目用量”后，能够直接看到项目名、真实本地路径或未检测提示、远程仓库、Token、成本和定价状态；请求日志继续保持每页 10 条并可翻页。

## 第一性原理执行规则

1. 用户只能使用实际渲染到页面的功能，未接入组件即等于功能不存在。
2. 本地路径、远程仓库和展示名称是三种不同数据，任何一种都不能冒充另一种。
3. 未检测到路径、未定价和真实零成本必须是三个可区分状态。
4. 测试必须覆盖生产页面的真实组件树，不能只测试一个未被页面引用的孤立组件。
5. 先复现失败，再做最小改动；每个改动都必须能映射到本工单的验收条件。
6. 不删除或回退无关改动，不引入热力图，不进行无关重构。

## 已知失败证据

| 编号 | 失败 | 证据 |
|---|---|---|
| E1 | 实际项目页不显示路径和成本 | `DashboardView.jsx` 渲染 `DataDetails.jsx`；其项目分支只输出 `project_key` 和 Token |
| E2 | 完整项目组件未接入 | `ProjectUsagePanel.jsx` 支持路径和成本，但生产组件树未使用它 |
| E3 | API 契约缺少状态 | 项目摘要无 `path_status`；当前 `path_kind` 为 `win/unknown` |
| E4 | POSIX 与 WSL 语义混淆 | `project-path.js` 把普通 `/Users/...`、`/home/...` 绝对路径统一判为 WSL |
| E5 | 本地页面产生脚本语法错误 | `/dashboard`、`/spend`、`/settings` 请求 `/_vercel/*/script.js` 时收到 HTML，出现 `Unexpected token '<'` |
| E6 | 旧审查缺少浏览器证据 | 上一轮没有验证真实路径是否出现在 DOM 中 |

## 执行步骤

### 1. 保护工作区并记录失败基线

- [ ] 记录 `git status --short --branch`，不得清理、reset 或 checkout 用户改动。
- [ ] 记录当前项目 API 的字段、路径数量、成本数量和路径类型。
- [ ] 用 Playwright 打开 `/dashboard` 项目用量，记录路径和成本未出现在 DOM 的失败证据。
- [ ] 运行项目相关专项测试并保存原始结果。

验收要求：报告必须包含失败截图或 DOM 摘要，不能只写“已复现”。

### 2. 先补生产组件树失败测试

- [ ] 新增针对 `DataDetails` 或 `DashboardView` 真实组件树的测试，而不是继续只测孤立的 `ProjectUsagePanel`。
- [ ] 测试必须构造以下三类项目：有真实路径且已定价、无路径但有远程仓库、未定价项目。
- [ ] 断言真实路径、远程仓库、Token、成本、定价状态和“未检测到真实路径”都出现在真实页面节点中。
- [ ] 断言远程 `https://` URL 不会出现在本地路径位置。
- [ ] 先运行新增测试并确认其在修复前失败。

### 3. 接入唯一的项目展示实现

- [ ] 在 `DataDetails` 的项目页签中复用 `ProjectUsagePanel`，或把同等完整能力直接收敛到 `DataDetails`；两种实现只能保留一个真实来源，避免双份 UI 漂移。
- [ ] 移除由本次接线产生的未使用 import，但不得顺手重构其他区域。
- [ ] 有路径时展示完整可识别路径并提供复制能力；无路径时展示明确提示。
- [ ] 展示远程仓库信息，但远程 URL 不得作为本地路径。
- [ ] 展示项目 Token、`cost_usd` 和 `pricing_coverage`；未定价不得显示为真实 `$0`。
- [ ] 所有新增文案写入 `copy.csv`，不得硬编码中英文文案。

### 4. 收敛项目路径 API 契约

- [ ] 将 `path_kind` 固定为 `windows | wsl | posix | unknown`，前后端与测试使用同一枚举。
- [ ] 增加 `path_status: detected | not_detected`，由真实路径是否存在决定。
- [ ] Windows 盘符和 UNC/WSL 路径分别识别；普通 POSIX 路径必须为 `posix`，不能自动等同 WSL。
- [ ] 历史数据没有 `cwd/repo_root` 时保持空路径和 `not_detected`，禁止推测或伪造。
- [ ] 保持已通过的成本聚合：可定价项目成本大于 0，未定价项目保留覆盖率信息。

### 5. 消除本地 Vercel 脚本错误

- [ ] 为 `Analytics` 和 `SpeedInsights` 增加明确运行环境条件，只在支持对应脚本的部署环境加载。
- [ ] 本地 CLI、Tauri 和 localhost 页面不得请求会被 SPA fallback 返回为 HTML 的 `/_vercel/*/script.js`。
- [ ] 不得通过吞掉全局异常掩盖错误。

### 6. 运行时回归

- [ ] 构建最新 dashboard 后启动真实本地服务。
- [ ] `/dashboard` 项目用量必须在 DOM 中出现至少一个真实路径、项目成本和路径状态提示。
- [ ] `/spend` 请求日志必须显示 10 条记录、总记录数、总页数，并验证第 1 页和第 2 页记录不同。
- [ ] `/settings` 必须能看到每个 Agent 的环境检测按钮。
- [ ] 三个页面不得出现 `Unexpected token '<'`；记录其余控制台错误并逐项解释或修复。

## 验收标准

- 实际生产页面组件树显示项目名、路径或未检测提示、远程仓库、Token、成本和定价状态。
- `project_path` 不使用远程 URL 冒充；`path_status` 和 `path_kind` 契约完整。
- 可定价项目成本非零，未定价不显示成真实零成本。
- 请求日志每页严格 10 条，页码跳转有效。
- `/dashboard`、`/spend`、`/settings` 的本地 Playwright 验收路径可执行。
- 本地页面不再产生两个 Vercel 脚本语法错误。
- 规定专项测试、typecheck、lint、build 和校验命令全部通过。

## 对抗性审查循环

完成实现后，以“如何证明功能仍未真正接入”为审查目标，重新检查：孤立组件、伪造路径、未定价 `$0`、过期构建产物、控制台错误和只测不渲染。发现任何问题后先回写审查记录，再修复并重跑本工单全部验收；每轮均记录问题、修复和复验结果，只有所有标准通过才能结束。
