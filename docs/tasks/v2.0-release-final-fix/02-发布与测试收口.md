# 02 - 发布与测试收口

## 中文简述

本工单把“文件存在、关键词测试通过”升级为“发布命令和完整测试实际可执行”。它修复 macOS 与 Windows/Tauri workflow，处理后端 88 项和前端 16 项失败，并确保发布关键源码全部进入可复现的干净检出。

## 前置条件

- `01-功能闭环修复.md` 已完成并通过全部验收。
- `review-records.md` 已包含 01 的命令、API 和浏览器证据。
- 如果 01 未通过，禁止开始本工单。

## 第一性原理执行规则

1. 发布成功的定义是用户可获得由当前源码构建出的正确产物，不是 YAML 文件存在。
2. 测试门禁的定义是完整命令退出码为 0，不是大多数测试通过。
3. Token Eyes Windows 当前产品壳是 Tauri；构建旧 `TokenTrackerWin` .NET 包不能证明 Token Eyes Windows 可发布。
4. CI 只能使用仓库中已跟踪的文件；未跟踪源码在开发机可运行，但在 CI 中等同不存在。
5. 环境失败必须通过可维护的依赖检测、skip 条件或项目依赖解决，不能口头豁免。
6. workflow 测试必须验证路径、工作目录、产物和命令顺序，不能只搜索关键词。
7. 先建立失败测试，再修 workflow 或代码；禁止为了绿色删除有业务价值的测试。

## 执行步骤

### 1. 加固发布 workflow 失败测试

- [ ] 为 macOS workflow 增加工作目录、工具安装、签名、DMG 实际输出路径、标签和 display name 断言。
- [ ] 为 Windows workflow 增加 Tauri 构建断言，并明确禁止 `setup-dotnet`、`dotnet publish` 和旧 `TokenTrackerWin` 产物作为 Token Eyes 交付物。
- [ ] 验证 macOS 与 Windows 两个 job 都依赖同一个 draft release，二者完成后才 publish。
- [ ] 先运行 workflow 测试，确认新断言在修复前失败。

### 2. 修复 macOS 发布链路

- [ ] workflow display name 使用 `release (macOS + Windows)`。
- [ ] 输入 `X.Y.Z` 时统一创建、上传和发布 `vX.Y.Z` 标签。
- [ ] 安装 `xcodegen` 和 `create-dmg`。
- [ ] 在 `TokenTrackerBar` 目录执行 `xcodegen generate`、图标 patch 和 `xcodebuild`。
- [ ] 按仓库规范先签名内层 Node Mach-O，再带 entitlements 对外层 `.app` 做 ad-hoc 签名。
- [ ] 把实际 `.app` 路径传给 `scripts/create-dmg.sh`。
- [ ] 上传 `TokenTrackerBar/build/TokenTrackerBar.dmg` 或脚本真实输出路径，不得上传不存在的根目录文件。
- [ ] Homebrew 通知目标必须与仓库规范一致，并且只在 release 公开后执行。

### 3. 修复 Windows/Tauri 发布链路

- [ ] 使用 `windows-latest`、Node、Rust stable 和 Tauri CLI 所需依赖。
- [ ] 构建 dashboard 后执行 Token Eyes Tauri release build。
- [ ] 校验 `src-tauri/target/release/bundle` 下实际生成的安装包或归档产物。
- [ ] 将 Tauri 产物上传到同一个 draft release。
- [ ] 不要求用户或 CI 安装 .NET SDK，不用旧 WinForms 包替代 Tauri 包。
- [ ] 如果旧 `TokenTrackerWin` 仍需保留，只能作为明确命名的 legacy 产物，不能作为本工单 Token Eyes Windows 验收证据。

### 4. 清理后端完整测试

- [ ] 单独复跑所有失败文件，区分真实代码回归、过期测试、环境依赖和并发污染。
- [ ] 恢复 account source registry 的单一事实来源和 parity 测试。
- [ ] 删除或改写仍要求热力图、GitHub stars 的过期断言，替换为“热力图不存在”和当前项目字段的正向断言。
- [ ] 更新数据目录测试，使新增 Agent 字段与生产契约一致。
- [ ] 修复 Windows 下 TypeScript 子进程启动方式。
- [ ] 对 `sqlite3` 采用可维护方案：项目依赖、显式前置检测或有原因的 skip；不得让缺失命令产生大量假失败。
- [ ] 修复其余确定性失败，直到 `npm test` 退出码为 0。

### 5. 清理前端完整测试和 worker 异常

- [ ] 给 `useUsageData` 测试提供真实 `UsageFiltersProvider` 或集中测试 wrapper。
- [ ] 更新 `TokenPlanSection` mock，包含生产代码调用的 `getTokenPlanCatalog` 等导出。
- [ ] 修复导航 preload、Leaderboard、ResetPassword、UsageLimitsPanel、StatsPanel 等剩余失败。
- [ ] 移除已废弃热力图测试，或改写为“不出现热力图”的回归测试。
- [ ] 处理 worker OOM；允许调整 Vitest 并发或隔离重型测试，但不得隐藏失败测试。
- [ ] 直到 `npm --prefix dashboard run test` 退出码为 0 且无 unhandled error。

### 6. 干净检出与发布文件收口

- [ ] 生成本工单范围文件清单，区分用户已有改动和本轮改动。
- [ ] 确保所有发布关键源码、测试和 workflow 已被 Git 跟踪。
- [ ] 不提交临时日志、截图、实际 Feishu App Token、表格 ID、Cookie 或凭证。
- [ ] 在独立 worktree 或干净检出中安装依赖并运行完整门禁，证明不依赖本机未跟踪文件。
- [ ] 未经用户要求不得删除无关未跟踪文件；只需保证发布提交完整且可复现。

### 7. 飞书状态校正

- [ ] 在完整门禁通过前，将失真的 2.0-01/02/03 状态改为“进行中”或“阻塞”。
- [ ] 01 和 02 通过后，只更新对应记录；03 必须等待独立验收完成。
- [ ] 写入后读回任务 ID、状态、阶段和更新时间。
- [ ] 输出必须脱敏，不显示实际 App Token、Table ID、tenant token 或 Authorization。

## 验收标准

- 三个 workflow 文件被 Git 跟踪且测试通过。
- workflow 测试验证真实路径、命令、产物、标签和依赖，不只是关键词存在。
- macOS workflow 可从当前仓库结构生成并上传正确 DMG。
- Windows workflow 构建 Token Eyes Tauri 产物，不以旧 .NET 包替代。
- `npm test` 零失败。
- `npm --prefix dashboard run test` 零失败、零 unhandled error、零 worker 异常。
- typecheck、lint、build、cargo check 和所有校验命令通过。
- 干净检出能够复现全部结果。
- 飞书 01/02 状态与工程证据一致，03 未被提前标记通过。

## 对抗性审查循环

完成实现后，以“这些 workflow 是否只会通过文本测试但在 CI 失败”“完整测试是否被跳过或隐藏”“是否仍依赖未跟踪文件”为攻击面复审。发现问题后先回写审查记录，再修复并从相关专项测试开始，最终必须重新运行两套完整测试和干净检出验证。循环直到所有门禁通过。

工单执行完成的最后增加一个审查环节，以对抗性审查的方式回写审查记录，如果出现问题就修复，修复执行完的环节依旧是对抗性审查，直到都完成了才能结束，并汇报给我工单的完成情况
