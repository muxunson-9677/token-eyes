# 工单 09: MVP 联调测试与冷启动打包验证

## 任务编号与分支名

- 编号: `09`
- 分支: `feature/09-integration-test`

## 背景说明

Day1 后端能力和 Day2 三个前端组件已合并到 `main`。本任务只做 MVP 联调验收，验证三个数据源用量展示、手动订阅费录入、花销聚合数字和全新环境冷启动打包。发现问题只记录，不在本工单中修代码。

## 允许改动的目标文件清单

- `docs/test-reports/09.md`

## 已确定的输入规范

后端接口和前端数据契约以 `docs/dev-notes/interfaces.md` 为准。

需要验证的已合并能力:

- Win Codex / WSL Claude Code 用量统计: 复用 CC Switch 原生能力。
- Hermes 用量统计: 手动填写 Hermes 数据源路径后同步并展示。
- 手动订阅费: 使用 `subscription_fee_commands` 对应前端表单录入。
- 花销聚合: `cost_ledger` 简化口径，`本周期花销 = token 消耗成本 + 手动订阅费`，`累计花销 = 历史同口径求和`。

## 具体步骤

1. 从最新 `main` 切出 `feature/09-integration-test`。
2. 记录测试环境信息:
   - OS 与版本。
   - Node / pnpm / Rust / Cargo 版本。
   - 当前 commit hash。
3. 执行基础静态验证:
   - `pnpm install --frozen-lockfile`
   - `pnpm typecheck`
   - `pnpm test:unit -- SpendOverviewChart SubscriptionFeeForm UsageListPanel`
   - `cargo check --manifest-path src-tauri/Cargo.toml`
4. 验证 Win Codex 用量展示:
   - 使用当前机器已有 Codex 用量数据。
   - 打开 Dashboard 用量页。
   - 选择 Codex 筛选。
   - 记录是否能看到 Codex 用量列表、token、花销字段。
5. 验证 WSL Claude Code 用量展示:
   - 使用当前机器已有 Claude Code / WSL 用量数据。
   - 打开 Dashboard 用量页。
   - 选择 Claude 筛选。
   - 记录是否能看到 Claude 用量列表、token、花销字段。
6. 验证 Hermes 用量展示:
   - 在路径设置模块手动填写 Hermes 数据源路径。
   - 执行用量同步。
   - 打开 Dashboard 用量页。
   - 选择 Hermes 筛选。
   - 记录是否能看到 Hermes 用量列表、`appType = hermes`、`dataSource` 字段。
7. 验证手动订阅费:
   - 在订阅费表单新增一条记录。
   - 推荐测试值: `agentType = hermes`、`planLabel = Hermes Test Plan`、`monthlyFee = 20.00`、`currency = USD`、`billingDay = 1`、`effectiveFrom = 当前月月初`。
   - 刷新页面后确认记录仍存在。
   - 编辑一次备注或金额，确认保存成功。
   - 删除测试记录前，先完成第 8 步花销验证。
8. 验证花销聚合数字:
   - 记录当前统计周期内 token 成本合计。
   - 记录手动订阅费合计。
   - 计算期望值: `expectedPeriodTotal = tokenCostUsd + subscriptionCostUsd`。
   - 对比花销图表展示的本周期花销。
   - 对比累计花销是否不小于本周期花销，并与 `cost_ledger` 返回口径一致。
9. 执行全新环境冷启动打包测试:
   - 在仓库外新建临时目录。
   - 重新 clone GitHub 仓库。
   - checkout 最新 `main`。
   - 执行 `pnpm install --frozen-lockfile`。
   - 执行 `pnpm tauri build`。
   - 记录打包是否成功、产物路径或失败日志。
10. 将所有结果写入 `docs/test-reports/09.md`。
11. 提交 PR，不自行合并。

## `docs/test-reports/09.md` 必须包含

1. 测试环境。
2. 基础静态验证结果。
3. Win Codex 用量展示结果。
4. WSL Claude Code 用量展示结果。
5. Hermes 用量展示结果。
6. 手动订阅费 CRUD 验证结果。
7. 花销聚合计算表:
   - token 成本。
   - 订阅费。
   - 期望本周期花销。
   - 实际本周期花销。
   - 实际累计花销。
8. 全新环境冷启动打包结果。
9. 发现的问题清单；如无问题，明确写 `未发现阻断问题`。

## 验收标准

- `docs/test-reports/09.md` 存在且包含上述 9 个章节。
- 三个数据源至少完成可展示性验证；如本机缺少真实数据，必须说明缺失原因和替代验证方式。
- 新增订阅费后，刷新仍能看到记录。
- 花销图表本周期数字与手工计算结果一致。
- 全新环境 `pnpm tauri build` 成功，或报告中提供完整失败日志和复现步骤。
- PR 改动只涉及 `docs/test-reports/09.md`。

## 禁止事项

- 不修改任何 `src/` 或 `src-tauri/` 代码。
- 不修改 schema、接口签名或迁移脚本。
- 不新增依赖。
- 不做 UI 视觉打磨。
- 不实现 OpenClaw、燃烧速率预测、套餐自动识别或复杂摊销。
- 发现问题不要自行修复；在 `docs/test-reports/09.md` 写清楚复现步骤、实际结果、期望结果。
