# R1 - 自包含运行时与本地 API 返工

## 目标

关闭旧 05 发现的 P0：Tauri Release 仍依赖源码仓库和系统 Node。最终安装包必须内置固定版本 Node、CLI、Dashboard、生产依赖、runtime manifest 和许可证；在无 Node、无源码的环境中启动真实本地 API，并在失败时给用户可见、可复制、脱敏的诊断。

对应维度：B2、B3、B7。

## 第一性原理执行规则

1. 安装后的 Release 主路径只能依赖安装包内资源、Windows/WebView2 和用户数据目录。
2. Release 不能向上搜索源码仓库，不能调用 PATH 中的 `node`。
3. 写入 Tauri config 不等于进入安装包；必须解包验证。
4. 后端进程启动不等于可用；必须等 `/api/local-auth` 返回协议版本和 capabilities。
5. 用户数据只能写入用户数据目录，不能写入安装资源目录。
6. 故障必须用户可见且脱敏；不能静默回退默认端口。
7. 先写或运行能暴露旧行为的负向探针，再修最小路径。

## 执行步骤

### 1. 旧反例复现

- [ ] 记录当前 HEAD、branch、工具版本和 `git status --short --branch`。
- [ ] 用代码定位记录 `find_repo_root`、`Command::new("node")`、无 `EmbeddedServer` resources。
- [ ] 增加 Release 路径负向测试：PATH 无 Node、cwd 不在 repo、安装目录无源码时启动失败且不能回退源码。
- [ ] 记录旧 0.54.0 安装包或当前构建包解包缺 runtime 的证据；如果解包命令失败，也必须记为失败证据。

### 2. 建立 runtime bundler

- [ ] 新增 Tauri 专用 `src-tauri/scripts/bundle-runtime.ps1`。
- [ ] 固定 Node win-x64 版本；下载官方 SHASUMS 并校验 SHA256，不匹配立即失败。
- [ ] 构建 dashboard 后复制 CLI allowlist、`package.json`、`package-lock.json`、`dashboard/dist`。
- [ ] 用锁文件安装生产依赖；禁止无锁 `npm install`。
- [ ] 生成 `runtime-manifest.json`，至少包含 app version、Node version、官方 SHA256、当前 HEAD、构建时间、文件数量。
- [ ] 复制 Node license。
- [ ] 明确排除 `.env`、`.git`、测试、文档、截图、日志、缓存和 devDependencies。

### 3. 接入 Tauri resources

- [ ] `tauri.conf.json` 配置 `EmbeddedServer` resource。
- [ ] `npm run tauri:build` 自动执行 runtime prepare，不能要求人工隐藏步骤。
- [ ] runtime prepare 任一失败必须让 Tauri build 失败。
- [ ] 解包 MSI/NSIS，验证 `EmbeddedServer/node.exe`、`tokentracker/bin/tracker.js`、`dashboard/dist/index.html`、`runtime-manifest.json`、license、生产依赖存在。

### 4. Release 只从内置 runtime 启动

- [ ] Rust Release 用 Tauri resource API 定位 `EmbeddedServer`。
- [ ] Release 用内置 `node.exe` 和内置 `tokentracker/bin/tracker.js`。
- [ ] Debug 开发回退必须由编译模式或显式 env 隔离；Release 不允许静默回退。
- [ ] 子进程 cwd 指向内置 tokentracker 根目录。
- [ ] 保持 loopback、随机端口、protocol version、capabilities 校验。
- [ ] 退出应用时只回收自己启动的子进程。

### 5. 故障可见性

- [ ] runtime 缺文件、node 校验失败、端口耗尽、8 秒未就绪、后端崩溃分别有结构化错误码。
- [ ] 前端提供重试动作和简洁诊断，不永久缓存失败默认端口。
- [ ] 错误和日志不包含 API Key、Cookie、Authorization、完整用户名路径或环境变量值。
- [ ] 日志写用户数据目录，限制大小和保留数量。

## 产物验证命令

```powershell
$ManifestPath = "src-tauri\EmbeddedServer\runtime-manifest.json"
$Manifest = Get-Content $ManifestPath -Raw | ConvertFrom-Json
if ($Manifest.node.sha256 -ne $Manifest.node.official_sha256) { throw "Bundled Node checksum mismatch" }

$ReleaseRoot = (Resolve-Path "src-tauri\target\release").Path
$Msi = Get-ChildItem (Join-Path $ReleaseRoot "bundle\msi\*.msi") | Sort-Object LastWriteTime -Descending | Select-Object -First 1
$Nsis = Get-ChildItem (Join-Path $ReleaseRoot "bundle\nsis\*-setup.exe") | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Get-FileHash $Msi.FullName,$Nsis.FullName -Algorithm SHA256

$ExtractDir = Join-Path $env:TEMP ("token-eyes-r1-msi-audit-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $ExtractDir | Out-Null
$Process = Start-Process msiexec.exe -ArgumentList @('/a',('"' + $Msi.FullName + '"'),'/qn',('TARGETDIR="' + $ExtractDir + '"')) -Wait -PassThru
if ($Process.ExitCode -ne 0) { throw "MSI administrative extract failed: $($Process.ExitCode)" }
Get-ChildItem -Recurse -File $ExtractDir
```

## 对抗性审查要求

至少三轮：

1. 正常路径：build runtime、build Tauri、解包检查、启动真实 API。
2. 负向路径：删除/损坏 `node.exe`、`tracker.js`、manifest；PATH 清空 Node；cwd 移到 repo 外；占用 7680；后端启动后立刻崩溃。
3. 干净路径：从干净 checkout 运行 `npm ci`、`npm ci --prefix dashboard`、`npm run tauri:build`，不能复制旧 `dist`、`target`、`EmbeddedServer`。

发现问题必须追加 `review-records.md`，修复后重跑受影响轮次。最后一轮无新 P0/P1 才能结束。

## 验收标准

- Release 主路径没有 `find_repo_root` 或 PATH `node` 依赖。
- 解包后的 MSI/NSIS 包含完整 runtime。
- runtime manifest、Node 官方 SHA256 和 license 存在。
- `.env`、密钥、测试、日志、截图、devDependencies 不进入安装包。
- 真实 bundled Node 启动本地 API，`/api/local-auth` 和核心端点通过。
- 后端失败用户可见、可重试、日志脱敏。
- B2/B3/B7 计算阶段后验；最终阈值由 R5 判定。
