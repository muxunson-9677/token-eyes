# 工单 02: Hermes 数据源路径配置

## 任务编号与分支名

- 编号: `02`
- 分支: `feature/02-hermes-data-source-path`

## 背景说明

当前后端已有 Hermes 配置目录字段和路径解析函数，设置页也已有 Hermes 目录输入行。本任务补齐前端 schema、表单状态和保存链路，让用户手动填写的 Hermes 路径能持久化并被后端读取。

## 允许改动的目标文件清单

- `src/lib/schemas/settings.ts`
- `src/hooks/useSettingsForm.ts`
- `src/hooks/useSettings.ts`
- `tests/hooks/useSettingsForm.test.tsx`
- `tests/hooks/useSettings.test.tsx`
- `tests/hooks/useDirectorySettings.test.tsx`
- `docs/test-reports/02.md`

## 已确定的输入规范

- 字段名: `hermesConfigDir`。
- 值类型: `string | undefined | null`。
- 保存前 trim；空字符串按 `undefined` 保存。
- 后端读取链路: `settings.hermes_config_dir -> get_hermes_override_dir() -> hermes_config::get_hermes_dir()`。
- 本轮只保留手动输入和目录选择，不做候选路径扫描。

## 具体步骤

1. 在 `settingsSchema` 加入 `hermesConfigDir`，规则与其它配置目录字段一致。
2. 在 `useSettingsForm` 初始化与 reset 时 sanitize `hermesConfigDir`。
3. 在 `useSettings` 的自动保存和手动保存 payload 中加入 `hermesConfigDir`。
4. 确认 reset 目录状态时 Hermes resolved dir 不丢失。
5. 补充或更新现有 hook 测试，覆盖:
   - 读取服务器数据时 trim。
   - 空字符串保存为 `undefined`。
   - 手动保存 payload 包含 `hermesConfigDir`。
6. 自测并把结果写入 `docs/test-reports/02.md`。
