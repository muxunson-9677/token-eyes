# 03 - 成本设置与实时展示

## 中文简述

本工单在 01 的二级导航和 02 的后端契约之上完成前端闭环：在“设置 > 成本设置”管理 Token 套餐和供应商 API，在“支出 > 成本累积”展示账户花销、余额、同步状态和订阅记录。

## 前置条件

- 01 已完成并合入当前工作基线。
- 02 已完成并合入当前工作基线。
- 先阅读 01、02 的完成回写、最终接口字段和遗留问题。
- 若 02 的接口与总调度契约不一致，先补契约测试并统一，不能在前端静默兼容两套字段。

## 第一性原理执行规则

- 设置页只负责配置和验证连接，支出页只展示财务结果和成本记录。
- API Key 输入框是一次性秘密输入，不是可回填配置值。
- 用户看到的“余额/花销”必须带币种、状态和更新时间，不能只显示一个没有来源的数字。
- 实时刷新必须可控：进入页面刷新、手动刷新、定时刷新，不建立无边界高频轮询。
- 失败状态应保留上次成功值并明确标记过期，不能把网络错误显示成 0 元。

## 必做任务

### 1. 成本设置页面

- 在 `/settings/cost` 保留完整 `TokenPlanSection` 管理能力。
- 新增聚焦组件 `ProviderApiConfigSection`，不要把新表单继续堆进 `SettingsPage.jsx`。
- 列表展示供应商、账户标签、请求地址脱敏摘要、连接状态、上次同步时间和启用状态。
- 支持新增、编辑、删除、测试连接、手动刷新。
- 表单至少包含：供应商、账户标签、请求地址、GET/POST、鉴权方式、API Key、自定义 Header 名、非敏感 Header、余额字段路径、月花销路径、累计花销路径、币种路径、刷新间隔、启用状态。
- API Key 编辑时永不回填原值；未输入新值表示保留现有引用。
- 页面不得展示、复制或通过 DOM 属性携带完整 API Key。
- 测试连接必须显示成功、未授权、限流、超时、不支持和响应格式错误。

### 2. 前端 API client 与状态管理

- 在 `dashboard/src/lib/api.ts` 增加配置 CRUD、密钥保存/删除、测试连接、刷新和余额列表调用。
- 使用现有 Tauri/local API URL 与鉴权封装，不另写平行 fetch 基础设施。
- 组件卸载时停止轮询和未完成状态更新。
- 最短刷新间隔为 60 秒；默认 300 秒。
- 同一账户手动刷新期间禁用重复点击。
- 网络失败保留上次成功数据并标记 `stale/error`，首次失败显示 `—`，不得显示 0。

### 3. 成本累积展示

- `/spend/cost` 展示 Token 套餐状态、供应商 API 账户、订阅记录和成本汇总。
- 供应商账户卡片展示：供应商、账户标签、余额、当月花销、累计花销、币种、同步状态、上次同步时间。
- 显示的数据必须来自 02 的财务接口，不得用本地 Token 成本替代余额。
- 未连接显示“未连接”，不支持显示“不支持自动查询”，错误显示可操作原因。
- 页面进入时立即刷新一次，随后按配置间隔刷新；同时提供手动刷新。
- 供应商 API 配置入口跳转到 `/settings/cost`，但不在支出页编辑密钥。

### 4. 订阅记录功能闭环

- 把 `SpendPage.jsx` 中现有但未挂载的新增、编辑、删除逻辑接入 `/spend/cost`。
- 页面统一使用“订阅记录”，不得出现“新增订阅记录”作为模块名称。
- 可使用“添加记录”作为按钮动作文本。
- 新增、编辑、删除后刷新成本汇总和订阅列表。
- 订阅费用与供应商 API 花销分栏展示，避免重复计算。

### 5. 清理归属错误

- `/settings/basic` 不出现 Token 套餐或供应商 API 配置。
- `/settings/cost` 不出现外观、数据目录、环境检测和限制显示。
- `/spend/usage` 不请求供应商余额接口。
- `/spend/cost` 不包含 API Key 输入框。

## 明确禁止

- 不增加模型选择、聊天、提示词或“测试模型调用”按钮。
- 不在 localStorage、sessionStorage、React state 持久化 API Key；短暂表单 state 提交后立即清空。
- 不显示供应商原始响应。
- 不用 0 表示未知、失败或未连接。
- 不恢复独立“按来源拆分”模块。
- 不修改 02 的安全边界来迁就前端。

## 测试要求

先写失败测试，至少覆盖：

1. 成本设置同时出现 Token 套餐和供应商 API 配置。
2. 基础设置不出现这两项。
3. API Key 输入提交后清空，编辑时不回填。
4. DOM、错误文案和 mock 调用参数不会泄漏测试密钥。
5. 测试连接各状态显示正确。
6. 成本累积显示余额、月花销、累计花销、币种和时间。
7. 未连接、错误、不支持时显示 `—` 而不是 0。
8. 进入成本累积立即刷新，定时刷新不低于 60 秒，卸载后停止。
9. 手动刷新防重复。
10. 订阅记录可以新增、编辑、删除并刷新汇总。
11. `/spend/usage` 不调用余额接口。
12. 供应商 API 配置页面没有模型调用入口。

## E2E 验收路径

1. 从左侧进入“设置 > 成本设置”。
2. 新增一个指向受控 mock server 的供应商配置并输入测试 API Key。
3. 测试连接成功，确认页面和日志无密钥原文。
4. 从左侧进入“支出 > 成本累积”。
5. 确认显示 mock server 返回的余额、月花销、累计花销、币种和更新时间。
6. 让 mock server 返回 401、429、超时和错误 JSON，确认状态正确且不显示 0。
7. 新增、编辑、删除一条订阅记录。
8. 进入“支出 > 使用统计”，确认没有按来源拆分且未请求余额接口。
9. 进入“设置 > 基础设置”，确认没有 Token 套餐和 API 配置。

## 验收标准

- 配置入口、展示入口和订阅管理形成可点击闭环。
- 密钥只在安全保存请求中短暂出现，之后 UI 不可读回。
- 余额和花销状态真实，不以估算值或 0 掩盖失败。
- 成本汇总不重复累计订阅费用、估算 API 成本和账户花销。
- 四个二级路由均可直接刷新和返回。
- B2、B5、B6 有自动测试、E2E 和 API 证据。
