# 04 - 独立贝叶斯验收

## 中文简述

本工单由未参与 01-03 开发的独立 subagent 执行。它不接受“已完成”口头结论，而是从需求、代码、测试、真实页面和密钥安全五个方向重新取证，用总调度中的贝叶斯表计算是否能够验收。

## 第一性原理执行规则

- 验收的目标是证明用户任务可以完成，不是证明代码数量很多或测试文件存在。
- 缺少证据等于概率不更新，不得按通过处理。
- 自动测试、截图和执行者报告可能共同复制同一个错误，必须寻找独立反例。
- 安全问题优先于功能通过；发现密钥泄漏立即判定 P0。
- 没有真实供应商凭据时只能验收到“实现完成、待真实账户验证”，不能宣称正式上线。

必须读取：

- `AGENTS.md`

- `01-二级导航与页面重构.md` 的完成回写和审查记录

不得只读取执行者总结。

## 必做审查

### 1. 需求与代码映射

逐项定位 B1-B7 的生产代码、测试和用户入口。检查：

- Sidebar 是否真的有四个子项，而不是页面内 Tab。
- 四个子 URL 是否独立工作。
- Token 套餐和 API 配置是否只在成本设置管理。
- 使用统计是否删除独立“按来源拆分”，同时保留 Provider 统计。
- 成本累积是否展示真实财务结果和完整订阅 CRUD。
- 代码中是否仍有未挂载的死表单或重复入口。

### 2. 自动测试与构建

先运行工单针对性测试，再运行全量门禁。最低命令：

```powershell
node --test test/provider-api-configs-api.test.js test/provider-api-balance.test.js test/provider-api-security.test.js
npm --prefix dashboard run test
npm --prefix dashboard run typecheck
npm --prefix dashboard run build
npm test
npm run validate:copy
npm run validate:ui-hardcode
npm run validate:guardrails
cargo check --manifest-path src-tauri/Cargo.toml
git diff --check
```

任何命令失败都必须记录原始错误，不能用“与本任务无关”直接忽略；确属环境问题时必须给出可复现依据和隔离验证。

### 3. Playwright 用户路径

启动真实本地 API 和 Dashboard/Tauri 页面，至少验证：

1. 支出父项展开后显示“使用统计、成本累积”。
2. 设置父项展开后显示“基础设置、成本设置”。
3. 四个子项均可点击，URL、标题和内容一致。
4. 刷新、前进、后退和直接访问 URL 不跳错。
5. 移动端 Drawer 可完成同样导航。
6. 使用统计没有独立“按来源拆分”，但 Provider 统计仍可用。
7. 基础设置没有 Token 套餐和 API 配置。
8. 成本设置可以管理 Token 套餐和 API 配置。
9. 成本累积显示余额、花销、币种、状态和更新时间。
10. 订阅记录新增、编辑、删除可完成。
11. 页面无未处理异常、脚本错误和横向溢出。

保存桌面和移动端截图、页面控制台摘要及关键 DOM 断言。

### 4. 安全对抗

必须使用唯一测试密钥字符串，例如随机生成的 `TE_TEST_SECRET_<uuid>`，执行：

- 保存、更新、测试连接、刷新、失败、删除和应用重启。
- 扫描 Git diff、仓库文本文件、配置目录、localStorage/sessionStorage、API 响应、控制台、服务日志、截图元数据和测试报告。
- 诱导 401、429、超时、HTML、跨域重定向、模型 endpoint、恶意字段路径和超大响应。
- 验证前端无法通过 GET、DOM、React props 或错误详情读回密钥。
- 验证删除配置后凭据引用不可再用。

发现明文密钥、跨域携带 Authorization、普通文件持久化或模型调用入口，立即判定 B4 不通过并按 P0 修复。

### 5. 财务语义核对

- 供应商余额/花销来自供应商财务响应。
- 本地 Token 估算成本不冒充余额。
- 订阅费用不冒充 API 花销。
- 未连接、未知、错误显示 `—` 或明确状态，不显示 0。
- 不同币种不在没有汇率依据时直接相加。
- 若有真实供应商测试账户，执行一次脱敏真实接口验证，只保留供应商、币种、数值是否匹配、时间和状态，不保留密钥或完整响应。

## 缺陷处理规则

- P0：密钥泄漏、模型调用越界、数据破坏、应用无法启动。
- P1：核心路由不可达、余额/花销虚假、配置不可用、订阅 CRUD 失败、严重重复计费。
- P2：局部视觉、文案、非核心交互问题。
- 发现问题后直接修复或回到责任工单修复。
- 修复后必须重新运行受影响针对性测试、全量门禁和对应 E2E。
- 原失败证据不得删除；追加新一轮审查，形成可追踪链路。

## 最终验收标准

- B1-B7 达到总调度最低后验。
- 加权总后验不低于 0.95。
- B4 不低于 0.99。
- P0/P1 为 0。
- 全量测试、构建、Tauri 检查通过。
- 有真实供应商脱敏验证，才能给出“可正式上线”。
- 没有真实供应商凭据时，最高结论为“可进入用户真实账户验证，暂不可正式上线”。
