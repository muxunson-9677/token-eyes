## 最终方案

- 公开 Plan Market、Reset feed 和 285 个排行榜对象由现有 Cloudflare Workers Free + 单一 SQLite Durable Object 提供。

- Worker 的可选写入由同一 Durable Object 串行预算账本约束：每日 70,000 warning、90,000 stop；配置只能下调，账本不可用时 fail-closed。平台免费额度耗尽时请求失败，不自动升级或产生超额账单。

## 两轮独立真实云核对

`.tmp/run-live-cloud-rounds.mjs` 每轮都执行：

1. 真实密码登录隔离 InsForge staging；先清理远端状态并确认匿名榜单无记录、`leaderboard_public=false`、`me=null`。
2. 明确开启参赛并上传不超过 8 KiB 的紧凑聚合摘要。
3. 触发受控 dirty 刷新，在 60 秒内匿名读取签名 Top 50 并核对生成时间、缓存和 ETag。
4. 真实退出登录，确认公开读取仍保留；重新登录，确认本人名次和参赛状态仍保留。
5. 删除头像和排行榜数据，再次受控刷新，并在 60 秒内确认匿名 Top 50、参赛状态和 `me` 全部移除。

两轮不得共享上一轮参与记录；完整观测、耗时和生成时间写入 `.tmp/acceptance-05449/final-cloud-rounds.json`。

## 零费用与权限边界

- Cloudflare：Workers Free；唯一绑定为 SQLite Durable Object；R2 未启用；无 R2/KV/D1、无 checkout、无支付方式。本任务不依赖“预计用量低于免费额度”，而依赖 Free 计划超额失败语义和应用内 90,000 fail-closed 门。
- InsForge：组织 `plan=free`、订阅 `status=none`、Stripe customer/subscription 为 null、账单历史空、余额 `$0.00`、`exceeded_limits=[]`；staging 为 `nano`，`custom_compute_cost_micros=0`。
- 若任一免费资源额度耗尽，允许的结果是公开服务失败并由客户端读取磁盘 LKG；不允许自动开通付费、恢复旧 InsForge 或回退到 R2。
- 本轮仅修改当前 worktree、隔离 InsForge staging 与 staging Worker；未 push、未 merge、未生产发布、未覆盖安装、未购买服务。

## 剩余风险

- Free 额度耗尽、服务商故障或签名发布失败会导致 staging 服务不可用；设计目标是 fail-closed 和 LKG 降级，不是无限可用。
- 隔离验收使用 staging，不代表正式生产域名已经发布。
- NSIS 当前无 Authenticode 代码签名；这不影响隔离功能验收，但正式分发时仍可能触发 Windows 信誉提示。
