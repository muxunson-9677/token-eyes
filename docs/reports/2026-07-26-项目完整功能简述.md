# Token Eyes 项目完整功能简述

更新日期：2026-07-26  
说明：本文按“当前代码实际可达、实际编译、实际存在”整理。为了避免误导，已把当前正式功能、可选云功能、暂时隐藏页面和历史残留代码分开说明。

## 一、一句话理解这个项目

Token Eyes 是一个“AI 编程工具 Token 用量总账本”。

它会从电脑上已经存在的 AI Agent/IDE 日志、SQLite 数据库、官方用量接口或轻量 hook 中提取 Token 数字，把不同工具的数据统一成本地记录，再通过网页 Dashboard、桌面托盘/菜单栏和命令行展示：

- 用了多少 Token；
- Token 用在什么 Agent、模型、日期和项目；
- 输入、输出、缓存创建、缓存命中、推理 Token 各是多少；
- 按模型价格估算花了多少钱；
- 套餐/订阅额度用了多少、什么时候重置；
- API 余额、订阅固定成本和 Token 套餐成本合计是多少。

它不是模型切换器、账号切换器、代理网关或 MCP/Skill 管理器。仓库里虽然保留了一部分 CC Switch 历史代码，但当前 Token Eyes 的有效 Tauri 入口没有编译这些能力。

## 二、给完全不懂 Token 的用户解释

AI 模型处理文字时，不是直接按“一个汉字”或“一个单词”计费，而是先把内容切成 Token。一次请求常见会产生：

- **输入 Token**：发给模型的内容；
- **输出 Token**：模型生成的回答；
- **缓存创建 Token**：第一次建立可复用上下文缓存；
- **缓存命中 Token**：后续复用缓存的内容，通常更便宜；
- **推理 Token**：某些模型在内部思考阶段消耗的 Token。

Token Eyes 负责把这些数字从不同工具的不同格式中读出来，转换成同一套字段。这样用户不需要分别打开 Claude、Codex、Cursor 等多个地方查用量。

## 三、当前产品由哪些部分组成

### 1. Node.js CLI 和本地服务

目录：`bin/`、`src/`

这是数据采集和本地 API 的核心。它负责：

- 首次安装和接入检测；
- 扫描本地 Agent 日志；
- 增量解析 Token；
- 去重和写入本地 queue；
- 计算统计和成本；
- 查询官方额度；
- 启动 `127.0.0.1` 本地 Dashboard；
- 可选地把本地统计同步到用户账号。

要求 Node.js 20 或更高版本，支持 macOS、Linux、Windows。

### 2. React Dashboard

目录：`dashboard/`

这是用户看到的主要界面。当前桌面/本地 MVP 的正式导航只有：

- 概览；
- 支出 → 使用统计；
- 支出 → 成本累积；
- 设置 → 基础设置；
- 设置 → 成本设置。

### 3. Token Eyes Tauri 桌面壳

目录：`src-tauri/`

当前版本为 0.54.0，实际加载 `dashboard/dist`。它提供：

- 桌面窗口；
- 系统托盘；
- 单实例启动；
- 关闭时最小化到托盘；
- 开机启动；
- 静默启动；
- 本地 Node 服务自动启动和端口探测；
- 选择本地目录；
- 官方网页账号授权窗口。

当前 Rust 入口支持的官方控制台会话桥包括：

- Claude；

| Gemini CLI | SessionEnd hook 或被动会话日志 | 本地增量读取 |
| OpenCode | 插件/hook、SQLite 或 JSON fallback | 读取消息记录中的 Token |
| OpenClaw | session plugin/hook | 可由 OpenClaw 事件触发同步 |
| Kilo CLI | SQLite | 复用 OpenCode 风格数据库结构 |
| Kilo Code | VS Code 扩展的 `ui_messages.json` | 被动读取，不需要代理 |
| Roo Code | VS Code 扩展的 `ui_messages.json` | Cline 系结构 |

| Hermes Agent | SQLite sessions | 支持自定义 Hermes 数据路径 |
| Kimi | `wire.jsonl` | Kimi Agent 的被动日志读取 |
| Kimi Code | 另一套 `wire.jsonl` 路径 | 与 Kimi 分开识别 |
| CodeBuddy | `~/.codebuddy/projects` JSONL | 腾讯 CodeBuddy CLI |
| oh-my-pi | `~/.omp/agent/sessions` JSONL | 被动读取 |
| pi | `~/.pi/agent/sessions` JSONL | `@mariozechner/pi-coding-agent` |
| Craft Agents | session JSONL | 被动读取 |
| Grok Build | hook + updates/signals 会话扫描 | 当前部分数据只有累计 Token，成本可能是估算 |
| GitHub Copilot | OpenTelemetry JSONL | 需要 Copilot OTEL 文件导出 |
| Zed Agent | SQLite threads | 支持 Zed 内多个模型 Provider |
| Goose | SQLite sessions | 按累计值计算增量 |
| Droid | `~/.factory/sessions/*.settings.json` | Factory Droid 被动读取 |
| Antigravity | transcript JSONL | 扫描 Antigravity 多种本地目录 |

### 采集方式的区别

- **Hook**：Agent 一次会话结束后，通知 Token Eyes 进行同步。
- **被动日志读取**：Token Eyes 只读工具已经生成的 JSON/JSONL 文件。
- **SQLite**：只读工具自己的本地数据库。
- **OTEL**：读取工具主动导出的 OpenTelemetry 文件。
- **云/官方 API**：用现有登录态查询账号用量或余额。

## 五、Token 数据是怎样处理的

### 1. 增量扫描

Token Eyes 保存每个文件、会话或事件的游标。再次同步时只处理新增数据，避免每次从头扫描全部历史。

### 2. 统一字段

所有来源尽量统一为：

- `input_tokens`
- `output_tokens`
- `cached_input_tokens`
- `cache_creation_input_tokens`
- `reasoning_output_tokens`
- `total_tokens`
- `model`
- `source`
- `timestamp`
- 项目/会话等可用归属信息

### 3. 时间桶

数据按 UTC 半小时桶聚合，Dashboard 再按用户时区显示日、周、月和自定义区间。

### 4. 去重

不同 Agent 可能重复写累计值、事件或归档会话。项目使用来源专用游标和复合键避免重复计算。

### 5. 成本计算

成本引擎包括：

- 内置离线价格快照；
- LiteLLM 模型价格数据；
- 每日/缓存刷新；
- 输入、输出、缓存读、缓存写分别计价；
- 模型名称规范化；
- 小众 Agent 的人工覆盖价格；
- 用户自定义 Agent 计费规则；
- 无法定价时保留 Token，并标记未定价/部分定价，而不是假装准确。

## 十一、官方额度和余额能力

项目中存在四类容易混淆的“用量”：

1. **本地 Token 消耗**：从 26 个 Agent 日志中解析。
2. **订阅 Rate Limit**：例如 5 小时、7 天窗口的已用百分比和重置时间。
3. **Token 套餐额度**：用户购买的固定 Token/请求包。
4. **API 财务余额**：供应商账户还有多少钱或多少赠送额度。

后端当前有 Claude、Codex、Cursor、Kimi、Gemini、Kiro、Antigravity、Copilot、Grok 等官方/本地额度查询代码；UI 还支持 Hermes、OpenClaw、OpenCode 等自定义/套餐显示。由于能力注册表尚未完全统一，不能把“页面里能显示”直接理解成“该 Provider 一定有官方额度 API”。

## 十二、CLI 的全部命令

### `tokentracker`

默认初始化、同步、启动本地服务并打开 Dashboard。

### `tokentracker serve`

- 启动本地 Dashboard；
- 指定端口；
- 禁止自动打开浏览器；
- 禁止启动前同步；
- 默认端口不可用时尝试后续端口。

### `tokentracker init`

- 首次同意；
- 检测已安装工具；
- 安装 hook/plugin/本地运行文件；
- 支持 `--yes` 非交互；
- 支持 `--dry-run` 预览；
- 支持 link code 关联账号。

### `tokentracker sync`

- 扫描全部适配器；
- 增量解析；
- 写入本地 queue；
- 可选上传账号视图；
- `--auto` 自动模式；
- `--drain` 清空待同步队列；
- `--from-openclaw` 标记 OpenClaw 触发。

### `tokentracker status`

检查各 Agent：

- 是否安装；
- hook/plugin 是否配置；
- 数据目录是否存在；
- 最近同步情况；
- 可选 keychain 探测。

### `tokentracker diagnostics`

输出更完整的诊断 JSON，可保存到文件。

### `tokentracker doctor`

做健康检查：

- 本地环境；
- 数据目录；
- hook；
- 后端连接；
- 可输出机器可读 JSON。

### `tokentracker uninstall`

- 移除 TokenTracker 安装的 hook/plugin；
- `--purge` 可进一步清理本地数据。

### `tokentracker device-login`

用于 SSH/无界面机器：

- 在 CLI 产生配对流程；
- 浏览器完成账号登录；
- 配对码有效期 15 分钟；
- 支持 JSON 输出和自定义后端 URL。

### `tokentracker wrapped`

生成某一年度的 Token 使用总结，支持：

- 指定年份；
- JSON 输出。

## 十三、本地、联网和隐私边界

### 默认留在本机的数据

- 原始 Agent 日志仍在原工具目录；
- Token Eyes 的 queue、cursor、缓存和设置；
- Token 数量、时间、模型、来源和可用的项目归属；
- API Key secret 采用单独引用存储，不应进入普通响应和日志。

### 可能发起网络请求的功能

- Cursor/Claude/Codex/Gemini/Kimi/Kiro/Copilot/Grok 等额度查询；
- LiteLLM 价格更新；
- 汇率刷新；
- Provider API balance；
- 检查更新；
- 登录、设备配对和可选云同步；
- hosted 网站和公开分享。

因此准确描述应是“本地数据优先、云同步可选”，而不是“除排行榜外绝不联网”。

### 当前需要修复的隐私问题

本地 API 的只读接口目前使用宽松 CORS，可能被任意网页读取。详情和修复方案见《代码问题报告》P1-01。

## 十四、当前不是正式功能的代码

以下页面或模块虽然仍在仓库，但当前 `dashboard/src/App.jsx` 会把它们重定向到 `/dashboard`，不应写进当前 MVP 对外功能清单：

- Leaderboard；
- 用户公开 Profile；
- 独立 Limits 页面；
- Skills；
- Widgets Gallery；
- IP Check；
- 网页 Wrapped 页面。

其中 CLI `wrapped` 仍是有效命令；macOS 原生 Widget 也仍有独立实现。这里说的“隐藏”只指当前 React 路由。

以下 CC Switch 能力属于历史残留，不是当前 Token Eyes 有效 Tauri 功能：

- 模型/Provider 切换；
- 多账号切换；
- 本地代理接管；
- MCP 管理；
- Skill 管理；
- Provider 路由和故障转移；
- CC Switch 数据库和旧命令面。

## 十五、新用户的最短使用路径

1. 安装 Node.js 20+，或安装对应桌面版。
2. 运行 `npx tokentracker-cli`。
3. 第一次运行允许它检测本机已有 AI 工具。
4. 等待首次同步。
5. 浏览器打开本地 Dashboard。
6. 在“概览”看总体 Token。
7. 在“使用统计”按 Agent、模型和时间找消耗来源。
8. 在“成本设置”配置套餐、API 余额和固定订阅。
9. 在“成本累积”看真实总成本。
10. 遇到缺数据先运行 `tokentracker status`，再运行 `tokentracker doctor`。
