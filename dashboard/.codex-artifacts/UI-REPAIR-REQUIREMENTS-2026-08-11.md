# Token Eyes 0.54.40 UI 修复需求与验收清单

## 文档状态

- 当前状态：仅确认需求，尚未开始修复。
- 工作分支：`ui-release-05439-v2`
- 记录基线：`f9e41438e244bad99297059736edcf2f368f5e94`
- 执行约束：必须等待用户后续明确指令，才允许开始修改代码。
- 修复原则：十项问题逐项实现、逐项验证；不得用构建成功代替真实 EXE 和真实页面验收。

## 1. 修复 EXE 窗口控制按钮

### 需求

- 当前右上角缩小、最大化/还原、关闭按钮点击无效，必须修复。
- 可以直接删除项目自制的窗口控制按钮和自制标题栏控制区域，恢复并使用 PC/Tauri 桌面应用原生标题栏及系统自带窗口按钮。
- 如果保留自制按钮，则三个按钮必须分别真正调用缩小、最大化/还原、关闭能力；不允许继续保留无响应的假功能。
- 优先选择稳定、符合 Windows 桌面应用习惯、后续维护成本更低的原生方案。

### 验收标准

- 缩小按钮可将窗口缩到任务栏。
- 最大化按钮可在最大化与还原之间正确切换。
- 关闭按钮可正常关闭应用窗口和相关进程。
- 按钮视觉、悬停状态、点击区域和 Windows 桌面行为一致。
- 在正式打包安装的 EXE 中实测通过，不能只在浏览器开发环境验证。

## 2. 删除悬浮小组件外围灰色区域

### 需求

- 删除悬浮小组件外围可见的灰色矩形背景。
- 小组件窗口外围应透明，仅保留小组件本体、合理阴影和特效。
- 不能用裁切小组件或缩小可点击区域的方式掩盖灰色背景。

### 验收标准

- 在浅色、深色和不同桌面背景下，均看不到灰色矩形底板。
- 小组件圆角、阴影和边缘完整，不出现锯齿、白边或黑边。
- 小组件拖动、点击和悬浮交互不受影响。

## 3. 重做悬浮小组件流星雨/烟花特效

### 需求

- 删除当前弹出的、文字显示不完整的提醒卡片方案。
- 流星雨或烟花必须直接出现在悬浮小组件本体以及小组件周围区域。
- 特效不能被小组件窗口边界裁切，也不能只在卡片内部播放。
- 特效触发后必须持续显示，不能几秒后自动结束。
- 特效只能由用户主动点击特效本身后关闭；点击小组件普通功能区不应误关闭特效。
- 关闭操作要有明确的可点击反馈，同时不能额外弹出遮挡内容的文字卡片。

### 验收标准

- 用户没有点击特效时，特效持续可见。
- 用户点击流星、烟花粒子或明确的特效交互区域后，特效立即且平滑关闭。
- 特效覆盖小组件本体及周边空间，显示完整，不被裁边。
- 特效不阻塞小组件原有按钮，不造成窗口异常放大、灰底或焦点问题。
- 在不同缩放比例和桌面分辨率下实测通过。

## 4. 修复概览页统计卡片尺寸与溢出

### 需求

- 修复“总用量”等统计卡片标题、数字、单位、趋势文字和图标超出卡片的问题。
- 当前文字、数据和图标整体过大，需要明显缩小；以约缩小到当前视觉尺寸的一半为目标，再根据可读性和卡片实际空间做精确适配。
- 所有卡片必须保持一致的字号层级、内边距和对齐方式。

### 验收标准

- 所有内容完整位于卡片内部，不截断、不重叠、不显示省略号掩盖关键数据。
- 数字、单位、时间范围和趋势信息层级清晰。
- 在正常窗口和最小允许窗口尺寸下均完整显示。

## 5. 修复概览页 Agent/模型展示区域

### 需求

- Agent 与模型卡片必须根据可用窗口宽度自适应布局。
- 新增项目不能只在区域底部或右侧露出一部分。
- 根据空间采用合理的自动换行、列数调整、横向滚动或卡片尺寸调整，但不能隐藏有效内容。

### 验收标准

- 所有 Agent/模型卡片均可完整查看。
- 改变窗口宽度后布局稳定，不出现半张卡片、边缘裁切或容器溢出。
- 卡片顺序、标签、占比和状态信息保持清晰。

## 6. 恢复重置记录页已确认的热力图布局

### 需求

- 恢复此前已经确认并提交的热力图方案。
- 热力图应靠右放置，布局紧凑、整齐并准确对齐。
- 不得再次随意改变已验收区域的结构、间距或位置。
- 修复前需要从已提交历史中定位已确认版本，按该结果恢复，而不是凭印象重新设计。

### 验收标准

- 热力图位置、间距、日期、统计信息与已确认版本一致。
- 正常窗口和较窄窗口下均保持整齐，无错位、拉伸或不必要的大面积空白。

## 7. 为小组件页所有可点击控件增加按压动效

### 需求

- 小组件页内所有按钮、筛选器、下拉框和可点击控件都要有按下反馈。
- 范围包括但不限于：显示桌面小组件、选择项目文件夹、批量操作、恢复最近活跃项目、搜索、状态筛选、排序、日期筛选、刷新数据、分页和行操作按钮。
- 动效应简洁、快速、克制，不影响操作效率。

### 验收标准

- 鼠标按下时有明确的位移、缩放、明暗或阴影变化，松开后自然回弹。
- 禁用控件不播放可点击动效。
- 键盘操作保留清晰焦点状态，并兼容减少动态效果设置。

## 8. 全面修复使用明细页

### 需求

- 以此前已提交并推送、已经确认的正确版本为基准进行核对和恢复。
- 修复页面内容显示不全、容器裁切和底部内容被遮挡的问题。
- 修复“使用趋势”图表的高度、坐标、曲线、图例和可视区域问题。
- 修复 Token 服务列表卡片布局、空状态和尺寸问题。
- 提升卡片体积感，通过统一的边框、阴影、层级和背景处理增强可辨识度。
- 请求日志、Provider 统计和模型统计三个区域切换后都必须完整显示。

### 验收标准

- 页面主体、图表、服务列表和底部统计区均完整可见。
- 趋势图数据和坐标关系正确，无异常压缩、裁切或大面积无效空白。
- Token 服务列表在有数据和无数据状态下都布局正常。
- 卡片层级统一且有适度体积感，不出现浮夸或不一致的阴影。
- 正常窗口、最小窗口以及三个统计标签页分别验收。

## 9. 优化 Provider 统计和模型统计加载速度

### 需求

- 排查切换 Provider 统计和模型统计时长时间转圈或空白的真实原因。
- 检查并减少重复请求、重复扫描、重复聚合计算、串行等待和无效重新渲染。
- 在不改变真实数据口径的前提下优化加载速度。
- 加载过程中提供稳定、明确且不会撑坏布局的反馈。

### 验收标准

- 首次进入和标签切换都有可测量的速度改善。
- 重复切换时合理复用已有结果，不重复执行不必要的重型工作。
- 加载失败时给出可理解的错误状态，不能无限转圈。
- 优化前后数据结果一致。

## 10. 修复数据与诊断页卡片文字溢出

### 需求

- 修复“账户完整性”“Token Eyes 读取什么”、本地数据位置、隐私说明、清除本地导入数据以及底部说明区域的文字和图标溢出。
- 长文字需要合理换行，关键路径需要可读且不能挤压相邻内容。
- 底部隐私说明图标和竖排文字必须恢复为正常、清晰的横向或响应式布局。
- 页面所有卡片都要适配窗口宽度，不能依赖超宽窗口才能正常显示。

### 验收标准

- 文字、数字、图标和按钮全部位于各自卡片内部。
- 不出现竖向挤压文字、互相覆盖、越界或被窗口底部裁切。
- 正常窗口、最小窗口、浅色和深色模式均通过检查。

## 统一验证与交付要求

- 十项修复必须建立逐项验收记录，不能合并成一句“已优化”。
- 必须验证真实 Tauri/Windows EXE，不以浏览器开发页或构建成功代替桌面端验收。
- 至少覆盖正常窗口、最小允许窗口、浅色模式和深色模式。
- 检查页面横向溢出、纵向裁切、文字换行、按钮可点击性和响应式布局。
- 对已经确认并提交的页面，优先恢复已接受版本，避免重新设计造成回退。
- 完成代码修改后，先运行针对性测试、类型检查和生产构建，再进行真实页面截图与交互验证。
- 未经用户后续明确指令，不得开始上述修复，也不得提交、推送或重新打包安装。
